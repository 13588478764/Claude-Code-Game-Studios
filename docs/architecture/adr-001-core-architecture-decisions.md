# ADR-001: 核心架构决策

## 状态
已接受

## 上下文
武侠奇遇录项目需要建立清晰的技术架构基础，以支持MVP开发和后续的完整愿景实现。本ADR记录了项目的核心架构决策。

## 决策

### 1. 游戏引擎选择
**决策**：使用Godot 4.6作为主要游戏引擎

**理由**：
- 开源免费，无版税负担
- 优秀的2D/3D渲染能力，特别适合俯视角武侠游戏
- 内置GDScript语言，学习曲线平缓
- 强大的场景系统和节点架构
- 适合中小型团队的开发工作流
- 良好的跨平台支持（PC、移动、Web）

### 2. 编程语言
**决策**：GDScript作为主要编程语言，C#作为可选补充

**理由**：
- GDScript是Godot的原生脚本语言，专为游戏开发优化
- 语法简洁，类似Python，易于学习和维护
- 与Godot引擎深度集成，性能优秀
- C#可用于性能关键模块或团队有C#经验的情况

### 3. 架构模式
**决策**：采用Scene-Node架构模式 + 组件化设计

**理由**：
- Godot原生的Scene-Node架构适合游戏对象管理
- 组件化设计通过脚本和节点组合实现功能复用
- 避免过度工程化，保持开发效率
- 利用Godot的信号系统实现松耦合通信

### 4. 数据持久化
**决策**：JSON格式本地存储 + 可选云同步

**理由**：
- 人类可读，便于调试和修改
- Godot内置JSON支持，使用方便
- 跨平台兼容性好
- 支持版本迁移和向后兼容
- 云同步为可选功能，不影响核心体验

### 5. UI框架
**决策**：Godot Control节点系统 + Theme资源

**理由**：
- Godot原生UI系统，深度集成
- 声明式UI定义通过场景文件
- CSS-like样式系统通过Theme资源
- 支持复杂交互和动画
- 性能优秀，内存占用低

### 6. 网络架构
**决策**：单机游戏，无强制网络依赖

**理由**：
- MVP阶段专注于核心玩法
- 降低开发复杂度
- 云存档为可选功能（通过Steam Cloud）
- 未来可扩展多人模式

### 7. 资源管理
**决策**：Godot Resource系统 + PackedScene

**理由**：
- Godot原生资源管理系统
- 动态资源加载和卸载
- 内存优化通过引用计数
- 支持热更新和模块化开发

### 8. 版本控制
**决策**：Git + Git LFS

**理由**：
- 行业标准版本控制系统
- Git LFS处理大文件（纹理、音频、模型、场景）
- 良好的分支和合并策略支持
- 与CI/CD工具链集成

## 后果

### 积极后果
- 清晰的技术栈选择，减少技术债务
- 统一的架构模式，提高代码质量和可维护性
- 良好的性能基础，支持大型开放世界
- 跨平台发布能力，扩大用户群体
- 开源免费，无版税负担
- 模块化设计，便于团队协作

### 消极后果
- GDScript生态系统相对较小
- 团队需要学习Godot特定的工作流
- 3D功能相比Unity/Unreal仍在发展中
- 某些高级功能可能需要自定义实现
