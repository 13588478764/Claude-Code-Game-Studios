*Created: 2026-05-16*

## 1. Visual Identity Statement

### 一句话视觉规则

> **"一眼能看懂，两秒能笑出来。"**
> 所有视觉元素的存在只为两件事：让玩家瞬间理解发生了什么，然后觉得荒诞好笑。

### 支撑原则

**原则 1：表情即信息**
- 定义：角色和UI的情绪状态必须通过夸张到失真的表情传达，而非文字标注或复杂动画。
- 设计测试：当纠结"这个状态要怎么让玩家看懂"时，答案是——画一个夸张到不可能的表情。
- 服务支柱：**三秒上手** — 表情是人类最快的信息解码通道。

**原则 2：扁平但不无聊**
- 定义：画面保持扁平简洁（无阴影、无渐变、粗线条），但用比例失调和夸张造型制造视觉冲击。
- 设计测试：当纠结"要不要加更多细节"时，答案是——不加细节，而是把已有元素变得更夸张。
- 服务支柱：**随开随走** — 简洁画面=小包体+快渲染+低认知负担。

**原则 3：颜色讲故事**
- 定义：每种颜色有明确语义（活力绿=精力，焦虑橙=心情，钞票黄=钱），玩家无需读文字就能感知资源状态。
- 设计测试：当纠结"这个信息用什么方式呈现"时，如果能用颜色说清楚，就不要用文字。
- 服务支柱：**三秒上手** + **一局一笑**（颜色变化本身可以是喜剧节奏的一部分）。

## 2. Mood & Atmosphere

| 游戏状态 | 情绪目标 | 色温/对比 | 氛围关键词 | 能量级别 |
|----------|---------|-----------|-----------|---------|
| **选职业** | 期待+荒诞 | 暖色偏亮，低对比 | 轻松、好奇、"这次会怎么死" | 轻快 |
| **工作中（正常）** | 紧张+好笑 | 中性色温，中对比 | 忙碌、荒诞、节奏感 | 中等偏快 |
| **工作中（危机）** | 焦虑+喜剧紧张 | 暖色偏橙红，高对比 | 快要爆炸、滑稽的绝望 | 高能 |
| **下班后** | 短暂松弛 | 冷色偏暖黄，低对比 | 喘口气、小确幸 | 舒缓 |
| **通关（升职）** | 荒诞的胜利 | 金色+亮色爆发 | 夸张庆祝、讽刺性的辉煌 | 爆发 |
| **失败（燃尽/被炒）** | 黑色幽默的悲壮 | 灰蓝色调，低饱和 | 搞笑的凄惨、"果然如此" | 戏剧化下坠 |
| **主界面/图鉴** | 轻松收集 | 柔和暖色，极低对比 | 安全、浏览、无压力 | 平静 |

### 氛围规则

1. **没有真正的负面情绪** — 即使是"失败"状态也必须是搞笑的，不能让玩家真的难过。视觉上用夸张代替压抑。
2. **状态切换要有"弹性"** — 从危机到下班的视觉跳跃要像表情包一样突然（制造喜剧节奏），不需要过渡动画。
3. **移动端亮度优先** — 所有状态的基底都偏亮，因为手机屏幕户外可见性很重要。暗色调只用于对比强调，不做为底色。

## 3. Shape Language

### 角色剪影哲学

- **头大身小** — 所有角色头身比约 1:2（Q版比例），头部占据主要视觉面积，因为表情是核心信息载体
- **职业一秒可辨** — 每个职业通过一个标志性道具/服装元素区分（程序员=格子衫+黑眼圈，骑手=头盔+保温箱），缩略图大小也能认出
- **无性别/通用体型** — 角色为"打工人符号"而非具体人物，减少美术成本且提高普适性

### 环境/场景几何

- **极简矩形为主** — 场景是卡片，卡片是矩形。UI框架全部用圆角矩形统一，符合小程序设计规范
- **唯一的曲线给表情** — 直线/矩形构成世界框架，曲线只用于角色表情和情绪气泡，形成对比让表情更突出

### UI形状语法

- **卡片即世界** — 游戏世界不是一个"场景"，而是一张张卡片。卡片的圆角矩形就是游戏的边界
- **按钮大而明确** — 选择按钮至少占屏幕宽度40%，圆角半径大（16px+），带轻微阴影提示可点击
- **资源条用粗实心条** — 不用环形或复杂图表，三条粗实心进度条横排在顶部，颜色语义即可

### 视觉层级

| 层级 | 元素 | 视觉权重 |
|------|------|---------|
| 1（焦点） | 事件卡描述 + 角色表情 | 最大面积、最高对比 |
| 2（操作） | 选择按钮A/B | 大色块、明确可点击 |
| 3（状态） | 资源条（精力/心情/钱） | 始终可见但不抢焦点 |
| 4（背景） | 背景色/环境暗示 | 低饱和度、纯装饰 |

## 4. Color System

### 主色板

| 角色 | 颜色 | 色值 | 语义 |
|------|------|------|------|
| **活力绿** | 明亮草绿 | #4CD964 | 精力值 — "还活着" |
| **焦虑橙** | 暖橙 | #FF9500 | 心情值 — "情绪温度" |
| **钞票黄** | 金黄 | #FFCC00 | 钱包 — "到手的钱" |
| **危险红** | 亮红 | #FF3B30 | 资源告急 / 负面事件 |
| **安全蓝** | 天蓝 | #5AC8FA | 正面事件 / 恢复 |
| **底色白** | 纯白/微灰 | #F8F8F8 | 背景基底 — 保持轻盈 |
| **文字黑** | 深灰黑 | #1C1C1E | 正文 — 高可读性 |

### 语义规则

- **绿色下降 = 坏事**，绿色上升 = 好事（精力直觉映射）
- **橙色偏红 = 心情崩溃边缘**，橙色偏黄 = 心情尚可
- **金黄闪烁 = 赚钱了**，灰色 = 没钱了
- **红色只用于"快死了"** — 不滥用红色，保持红色的警报权威性
- **蓝色 = 好事降临** — 下班事件、恢复道具、正面选项

### 职业标识色

| 职业 | 标识色 | 色值 |
|------|--------|------|
| 程序员 | 极客紫 | #AF52DE |
| 外卖骑手 | 外卖蓝 | #007AFF |
| 公务员 | 政务红 | #FF2D55 |
| 老师 | 黑板绿 | #34C759 |
| 医生 | 医疗蓝绿 | #5AC8FA |

新增职业时分配新色相，保证色盲安全间距。

### 色盲安全规则

- 精力(绿) vs 钱包(黄): 明度差异足够大，且有图标辅助（⚡ vs 💰）
- 危险(红) vs 安全(蓝): 冷暖对比+明度差异+图标（❌ vs ✓）
- **所有语义色必须同时搭配图标或文字标签**，不能纯靠颜色传递关键信息

### UI配色

- 按钮: 深色文字 + 浅色填充（高对比），选项A和选项B用不同色相区分
- 卡片: 白色底 + 职业标识色边框
- 背景: 纯白或极浅灰 — 让卡片和按钮成为视觉焦点

## 5. Character Design Direction

### 角色体系

本游戏只有一种角色类型：**打工人** — 通过职业换装呈现多样性。

### 设计规则

| 规则 | 说明 |
|------|------|
| **头身比** | 1:2 Q版，头部60%是脸（为表情留空间） |
| **五官** | 极简：两个圆点眼+一条线嘴。情绪通过眼睛大小和嘴形变化表达 |
| **身体** | 圆润简笔，无手指细节（拳头或省略），最多4色填充 |
| **职业标识** | 每个职业通过1-2个标志性配件区分，不靠服装细节 |
| **表情优先** | 角色的核心价值是承载表情。10种基础表情需覆盖所有事件情绪 |

### 10种基础表情

| 表情 | 触发场景 | 视觉描述 |
|------|---------|---------|
| 😐 平静 | 默认状态 | 标准圆点眼+横线嘴 |
| 😱 震惊 | 荒诞事件出现 | 眼睛放大3倍+嘴巴O型 |
| 😤 愤怒 | 被压榨/不公 | 眉毛倒八字+嘴角下拉 |
| 😭 崩溃 | 精力/心情告急 | 瀑布眼泪+嘴巴波浪线 |
| 😏 得意 | 摸鱼成功 | 一只眼微闭+嘴角上扬 |
| 🤑 发财 | 赚钱事件 | 眼睛变成$符号 |
| 😵 猝死 | 精力归零 | 眼睛变成X+灵魂出窍 |
| 🥳 狂喜 | 升职通关 | 眼睛星星+嘴巴大笑 |
| 😰 焦虑 | 资源偏低 | 汗滴+眉毛紧锁 |
| 🤡 自嘲 | 选了离谱选项 | 红鼻子+苦笑 |

### 职业配件速查

| 职业 | 标识配件 | 标识色 |
|------|---------|--------|
| 程序员 | 格子衫 + 黑眼圈 + 咖啡杯 | 极客紫 |
| 外卖骑手 | 黄色头盔 + 保温箱 | 外卖蓝 |
| 公务员 | 茶杯 + 文件夹 | 政务红 |
| 老师 | 粉笔 + 教鞭 | 黑板绿 |
| 医生 | 口罩 + 听诊器 | 医疗蓝 |

## 6. Environment Design Language

### "环境"定义

本游戏没有传统"场景"——环境通过卡片背景色和少量装饰元素暗示。

### 环境层次

| 层次 | 元素 | 设计规则 |
|------|------|---------|
| **卡片背景** | 纯色或极简图案 | 用职业标识色的10%透明度作为卡片底色 |
| **氛围插图** | 小尺寸装饰图标 | 每个职业3-5个场景图标，线稿风格 |
| **事件配图** | 事件卡顶部小图 | 与事件相关的简笔画（64×64px），表意>美观 |
| **页面背景** | 全屏底色 | 跟随游戏状态变色（见Section 2氛围表） |

### 设计原则

1. **环境是配角** — 环境永远不该抢走事件文案和角色表情的注意力
2. **暗示而非描绘** — 用一个咖啡杯图标暗示办公室，而不是画一整间办公室
3. **职业通过色温区分** — 程序员偏冷（屏幕蓝光感），外卖偏暖（户外阳光感），公务员偏灰
4. **零资源的环境叙事** — 加班时卡片背景从白转深蓝（暗示夜晚），不需额外美术资源

## 7. UI/HUD Visual Direction

### UI哲学

**"UI就是游戏，游戏就是UI。"** 整个游戏体验就是UI本身。

### 排版方向

| 元素 | 规格 |
|------|------|
| **主字体** | 系统默认（PingFang/思源黑体） |
| **标题** | Bold, 20-22px, 深灰黑 |
| **事件描述** | Regular, 16-17px, 深灰 |
| **按钮文字** | Bold, 16-18px, 高对比 |
| **数值** | Bold Mono, 14px, 语义色 |

### 图标体系

- 风格: 线性图标，2px线宽，圆角端点
- 尺寸: 24×24px（资源条）、48×48px（职业选择）
- 颜色: 跟随语义色系统，单色

### UI动效

| 动效 | 场景 | 时长 | 方式 |
|------|------|------|------|
| 资源条变化 | 选择后 | 300ms | 宽度动画+数值跳动 |
| 卡片进入 | 新事件 | 200ms | 底部滑入+弹性 |
| 按钮点击 | 选择时 | 100ms | 缩小95%→回弹 |
| 结局弹出 | 失败/通关 | 400ms | 中心放大+背景模糊 |

**规则**: 总时长≤400ms，无加载动画，动效服务于信息反馈。

### 信息架构

```
┌─────────────────────────┐
│  ⚡ ████░░  😊 █████░  💰 ███░░░  │  ← 资源条（固定顶部）
├─────────────────────────┤
│                         │
│    [职业图标 + Day X]    │  ← 上下文
│                         │
│  ┌───────────────────┐  │
│  │                   │  │
│  │   事件描述文案      │  │  ← 核心阅读区
│  │   + 角色表情       │  │
│  │                   │  │
│  └───────────────────┘  │
│                         │
│  ┌──────┐  ┌──────┐   │  ← 选择按钮（拇指热区）
│  │ 选项A │  │ 选项B │   │
│  └──────┘  └──────┘   │
└─────────────────────────┘
```

## 8. Asset Standards

### 文件格式与命名

| 资产类型 | 格式 | 命名规则 | 示例 |
|----------|------|---------|------|
| 角色表情 | SVG / PNG @2x | `char-[表情名].svg` | `char-shocked.svg` |
| 职业配件 | SVG / PNG @2x | `job-[职业]-[配件].svg` | `job-programmer-shirt.svg` |
| 事件配图 | PNG @2x | `event-[职业]-[事件ID].png` | `event-programmer-overtime.png` |
| 图标 | SVG | `icon-[名称].svg` | `icon-energy.svg` |
| 背景 | CSS纯色/渐变 | 不需要图片文件 | — |

### 尺寸标准

| 资产类别 | 设计尺寸 | 输出尺寸 | 文件上限 |
|----------|---------|---------|---------|
| 角色表情 | 128×128px | @2x (256×256) | < 10KB |
| 事件配图 | 64×64px | @2x (128×128) | < 8KB |
| 职业大图 | 200×200px | @2x (400×400) | < 20KB |
| 图标 | 24×24px | SVG | < 2KB |

### 包体预算

| 类别 | 预算 |
|------|------|
| 主包总计 | < 2MB |
| 图片资源 | < 500KB |
| 单职业资源包 | < 50KB |
| JSON数据 | < 200KB |

### 生产规则

1. **优先SVG** — 能用SVG的不用PNG
2. **CSS优先于图片** — 能用CSS实现的视觉效果不做成图片
3. **懒加载** — 非当前职业的资源按需加载
4. **色值统一管理** — 通过CSS变量定义，不硬编码
5. **单色图标** — 图标为单色（currentColor），运行时CSS着色

## 9. Style Prohibitions

### 绝对不做

| 禁止项 | 为什么 | 替代方案 |
|--------|--------|---------|
| 写实人物 | 破坏荒诞Q版调性+成本高 | Q版夸张表情 |
| 渐变/阴影/3D效果 | 增加包体+破坏扁平统一性 | 纯色块+线条 |
| 暗色主题/深色背景 | 违反亮度优先+压抑氛围 | 浅底+深色文字 |
| 复杂动画/骨骼动画 | 性能不支持+不符合碎片时间 | CSS过渡+帧切换 |
| 手绘质感/纹理 | 风格不统一+资产复杂度高 | 均匀线条+纯色 |
| 暴力/血腥视觉 | 审核不过+不符合幽默调性 | 符号化表达 |
| 真人照片 | 风格割裂+版权风险 | 极简插画重绘 |
| 超过3种字体 | 视觉混乱+包体浪费 | 系统字体+大小粗细区分 |

### 灰色地带决策规则

> 回到核心规则：**"一眼能看懂，两秒能笑出来。"**
> 如果这个视觉元素不服务于"看懂"或"笑出来"，删掉它。

## Reference Direction

| 参考来源 | 取什么 | 不取什么 |
|----------|--------|---------|
| **微信表情包** | 极简线条表情的识别效率和共鸣感 | 不取过度网络化的低质量画风 |
