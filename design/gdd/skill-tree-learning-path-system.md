# 技能树/学习路径系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-25
> **实现支柱**: 支柱1：深度武学系统

## 概述

技能树/学习路径系统采用"模块化武学图谱 + 熟练度解锁"的机制，通过为每个武学流派或角色境界设计独立的微型图谱，摒弃复杂的传统RPG天赋树，转而强调"武学招式"的收集与精进。系统利用2D俯视角的优势，实现线性主干、分支专精和网状关联的混合结构。

玩家通过前置武学熟练度、境界门槛、物品/秘籍消耗和奇遇事件等多种方式解锁新武学，在水墨卷轴风格的UI中直观地看到自己从"初窥门径"到"登峰造极"的成长过程。这种设计既为武学系统提供了深度和多样性，又避免了过度复杂的数值平衡问题，让玩家能够真正体验到武侠世界的武学魅力。

如果没有这个系统，游戏将失去成长深度与构建多样性，武学同质化导致所有玩家使用完全相同的招式，成长感薄弱仅体现为数字变化，策略单一缺乏根据敌人类型调整武学配置的能力，大量武学残页和悟性丹变成无用垃圾。该系统是实现"深度武学系统"游戏支柱的重要支撑，利用Steam平台的PC硬件优势提供高精度视觉表现、即时反馈与缓存、复杂数据计算和音频沉浸感。

## 玩家幻想

玩家应该能够体验到"习得绝世武功"、"自创流派"、"招式千变万化"的武侠核心幻想，通过在水墨卷轴风格的技能树中解锁和精进武学招式，直接体验到从"初窥门径"到"登峰造极"的成长过程。

直接层面：玩家积极且频繁地与技能树/学习路径系统交互。这包括在武学图谱中浏览可解锁的招式、消耗武学残页和悟性丹解锁新技能、根据属性条件选择不同分支路线、预览未解锁招式的效果。这是显性的成长决策和资源管理过程，直接决定了玩家的战斗风格和武学特色。玩家应该能够清晰地看到每个招式的前置条件、属性要求、伤害系数和特殊效果，从而做出明智的选择。

间接层面：技能树的底层逻辑（如图谱数据结构、解锁条件验证、熟练度计算）由系统自动处理。玩家在解锁招式时体验的是"墨水晕染"的视觉反馈和"领悟成功"的成就感，而非直接操作底层的数据验证或图谱构建。这种无缝的体验让玩家专注于武侠成长和武学探索，而不是技术细节。

参考游戏实现：
- 《如龙8》的多样化技能组合系统，允许玩家自由搭配不同技能形成独特战斗风格
- 《最终幻想7重制版-重生》的挑战性战斗系统，通过精确的招式判定和连击系统提供深度战斗体验
- 《暗黑破坏神4》的技能树系统，通过分支选择和条件解锁提供角色构建深度

## 详细设计

### 核心规则

1. **学习路径类型**（模块化武学图谱）：
   - **线性主干**（Main Path）：
     - 描述：代表武学的基础招式进阶，必须按顺序解锁
     - 示例：《华山剑法》：刺 → 撩 → 劈 → 崩
     - 目的：确保玩家掌握基础连招逻辑，形成流派特色
   - **分支专精**（Branches）：
     - 描述：在主干关键节点分叉，提供不同风格的强化或变招
     - 示例：劈之后可选重劈（高伤害、破防）或快劈（低伤害、高连击、加身法）
     - 条件：基于玩家属性（如STR>10选择重劈，AGI>10选择快劈）
   - **网状关联**（Cross-Links）：
     - 描述：不同武学之间的少量关联，鼓励多修武学
     - 示例：学习《太极拳》的"借力"后，可解锁《擒拿手》中的"反关节技"
     - 目的：增加武学组合深度，避免单一武学路线

2. **解锁机制**（多维条件验证）：
   - **前置武学熟练度**（Proficiency Gate）：
     - 规则：解锁下一层招式需要当前武学熟练度达到特定等级
     - 示例：华山剑法Lv.5才能解锁崩字诀
     - 目的：鼓励玩家反复使用同一套武学，形成肌肉记忆
   - **境界门槛**（Realm Requirement）：
     - 规则：高阶武学需要角色达到特定境界
     - 示例：筑基期才能学习《御剑术》
     - 目的：将武学成长与角色整体成长绑定
   - **物品/秘籍消耗**（Item/Material Cost）：
     - 规则：解锁新武学需要消耗特定物品
     - 示例：武学残页、名师指点令、悟性丹
     - 来源：探索宝箱、任务奖励、黑市购买
     - 目的：作为经济系统回收站，增加探索动力
   - **奇遇/事件解锁**（Event Unlock）：
     - 规则：隐藏武学只能通过特定奇遇解锁
     - 示例：《独孤九剑》残篇通过山洞石壁参悟获得
     - 目的：奖励深度探索玩家，提供独特性

3. **武学品阶体系**（统一命名规范）：
   - **品阶分类**：普通(White)、稀有(Blue)、史诗(Purple)、传说(Gold)
   - **对应关系**：
     - 普通 = 黄阶武学（基础招式）
     - 稀有 = 玄阶武学（进阶技巧）
     - 史诗 = 地阶武学（高级绝学）
     - 传说 = 天阶武学（顶级神功）
   - **视觉表现**：武学图标和技能树节点使用对应颜色标识（普通-白色、稀有-蓝色、史诗-紫色、传说-金色）

3. **可视化呈现**（水墨卷轴风格）：
   - **视觉风格**：
     - 背景：展开的古旧卷轴或宣纸纹理
     - 节点：毛笔书写的汉字或简化的兵器图标
     - 连线：水墨笔触风格，已解锁为浓墨，未解锁为淡墨或虚线
   - **布局逻辑**：
     - 垂直流：从上到下代表从入门到精通
     - 左右分支：向左代表"刚猛/外功"路线，向右代表"灵动/内功"路线
   - **交互反馈**：
     - 悬停：显示招式详细信息、伤害系数、消耗内力、前置条件
     - 点击：满足条件时播放墨水晕染动画，节点变为金色/亮色
     - 预览：未解锁节点显示灰色剪影，可预览效果但不可学习

4. **Steam平台优化实现**：
   - **高精度视觉表现**：使用GPUParticles3D渲染墨水晕染特效，动态光照照亮卷轴纹理
   - **即时反馈与缓存**：启动时预加载所有技能树数据到内存，UI零延迟响应
   - **复杂数据计算**：多线程后台验证解锁条件，使用二进制格式(.tres)存储图谱数据
   - **音频沉浸感**：每个解锁操作播放独特的传统乐器音效（古琴、笛子）

### 状态和转换

- **锁定状态**：武学节点未满足解锁条件，显示为灰色剪影
- **可解锁状态**：武学节点满足部分条件，显示为淡墨色，可预览但不可学习
- **已解锁状态**：武学节点完全解锁，显示为浓墨色或金色，可在战斗中使用
- **激活状态**：武学节点已装备到技能槽，在配招界面高亮显示

状态转换流程：
- 锁定 → 可解锁：当玩家满足部分解锁条件（如达到所需境界但缺少物品）
- 可解锁 → 已解锁：当玩家满足所有解锁条件并消耗所需物品
- 已解锁 → 激活：当玩家在配招界面将武学拖拽到技能槽
- 激活 → 已解锁：当玩家在配招界面移除武学装备

### 与其他系统的交互

- **武学数据库**：
  - 数据输入：接收武学数据中的unlock_requirements、branch_options等字段
  - 功能输出：提供已解锁武学列表，支持武学系统查询可用技能
- **武学系统**：
  - 数据输入：接收玩家当前装备的武学配置
  - 功能输出：提供武学解锁状态和分支选择，影响武学组合和连招
- **角色成长系统**：
  - 数据输入：接收玩家属性（STR、AGI等）、境界等级、熟练度数据
  - 功能输出：根据玩家属性和境界验证解锁条件，提供成长反馈
- **物品数据库**：
  - 数据输入：接收武学残页、悟性丹等消耗物品的数据
  - 功能输出：消耗指定物品完成武学解锁，更新玩家物品库存
- **奇遇系统**：
  - 数据输入：接收奇遇事件触发的特殊武学解锁条件
  - 功能输出：处理奇遇相关的隐藏武学解锁，扩展武学图谱
- **UI系统**：
  - 数据输入：接收技能树数据结构和玩家当前状态
  - 功能输出：渲染水墨卷轴风格的技能树界面，处理用户交互

## 公式

### 武学解锁条件验证公式

`可解锁 = (前置武学熟练度 ≥ 要求熟练度) AND (角色境界 ≥ 要求境界) AND (拥有物品数量 ≥ 需要物品数量)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 前置武学熟练度 | current_proficiency | int | 0-15 | 当前前置武学的熟练度等级 |
| 要求熟练度 | required_proficiency | int | 1-15 | 解锁所需前置武学熟练度 |
| 角色境界 | current_realm | int | 1-10 | 玩家当前境界等级 |
| 要求境界 | required_realm | int | 1-10 | 解锁所需境界等级 |
| 拥有物品数量 | owned_items | int | 0-999 | 玩家拥有的指定物品数量 |
| 需要物品数量 | required_items | int | 1-10 | 解锁所需物品数量 |
| 可解锁 | can_unlock | boolean | true/false | 是否满足所有解锁条件 |

**输出范围:** true或false
**示例:** 当前置武学熟练度为5，要求熟练度为5，角色境界为3，要求境界为3，拥有物品数量为2，需要物品数量为2时，可解锁 = (5 ≥ 5) AND (3 ≥ 3) AND (2 ≥ 2) = true AND true AND true = true

### 分支选择条件公式

`可选择分支 = 玩家属性 ≥ 分支要求属性`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 玩家属性 | player_stat | int | 0-100 | 玩家的属性值（STR、AGI等） |
| 分支要求属性 | branch_requirement | int | 1-50 | 分支选择所需的属性值 |
| 可选择分支 | can_choose_branch | boolean | true/false | 是否满足分支选择条件 |

**输出范围:** true或false
**示例:** 当玩家STR属性为12，分支要求STR为10时，可选择分支 = 12 ≥ 10 = true

### 技能树数据加载公式

`加载时间 = (技能树节点数 × 单节点数据大小) / 加载速度`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 技能树节点数 | node_count | int | 10-1000 | 技能树中的总节点数量 |
| 单节点数据大小 | node_size | float | 0.1-1.0 | 每个节点的数据大小（KB） |
| 加载速度 | load_speed | float | 10-100 | 数据加载速度（MB/s） |
| 加载时间 | load_time | float | 0.001-0.1 | 技能树数据加载时间（秒） |

**输出范围:** 0.001到0.1秒
**示例:** 当技能树节点数为100，单节点数据大小为0.5KB，加载速度为50MB/s时，加载时间 = (100 × 0.5) / (50 × 1024) = 50 / 51200 ≈ 0.001秒

## 边缘情况

- **如果Steam平台内存不足无法加载所有技能树数据**：系统将优先加载玩家当前武学流派的技能树，其他流派按需加载，确保核心功能正常运行。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前技能树状态，等待网络恢复后同步数据。
- **如果武学解锁条件验证失败**：系统将显示具体的缺失条件（如"需要华山剑法Lv.5"、"缺少2个武学残页"），帮助玩家明确下一步目标。
- **如果分支选择条件不满足**：系统将灰色显示不可用的分支选项，并在悬停时提示所需属性值（如"需要STR≥10"）。
- **如果技能树数据文件损坏**：系统将使用默认的通用技能树模板，确保玩家仍能进行基本武学解锁，同时记录错误日志。
- **如果玩家同时满足多个分支选择条件**：系统将允许玩家选择任意一个分支，但一旦选择后无法更改，鼓励玩家慎重决策。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **武学数据库**：需要武学数据库提供武学数据中的unlock_requirements、branch_options等字段
  - **武学系统**：需要武学系统提供玩家当前装备的武学配置和熟练度数据
  - **角色成长系统**：需要角色成长系统提供玩家属性（STR、AGI等）、境界等级、熟练度数据
  - **物品数据库**：需要物品数据库提供武学残页、悟性丹等消耗物品的数据
  - **奇遇系统**：需要奇遇系统提供奇遇事件触发的特殊武学解锁条件

- **下游依赖**（依赖此系统的系统）：
  - **UI系统**：依赖技能树系统提供技能树数据结构和玩家当前状态，用于渲染水墨卷轴风格的界面
  - **武学系统**：依赖技能树系统提供已解锁武学列表和分支选择，影响武学组合和连招

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的Resource系统、动画系统和粒子系统
  - **Steam平台API**：使用Steam的成就系统和云存档功能保存技能树进度

## 调整参数

- **要求熟练度范围**：1-15（可调整范围：1-20）
- **要求境界范围**：1-10（可调整范围：1-15）
- **需要物品数量范围**：1-10（可调整范围：1-20）
- **分支要求属性范围**：1-50（可调整范围：1-100）
- **技能树节点数范围**：10-1000（可调整范围：5-2000）
- **单节点数据大小范围**：0.1-1.0KB（可调整范围：0.05-2.0KB）
- **加载速度范围**：10-100MB/s（可调整范围：5-200MB/s）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于平衡技能树系统和适应不同难度级别。

## 视觉/音频要求

- **视觉风格一致性**：所有技能树界面必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **水墨卷轴背景**：技能树背景使用展开的古旧卷轴或宣纸纹理，营造传统武侠氛围。
- **节点设计**：武学节点使用毛笔书写的汉字（如"刺"、"撩"）或简化的兵器图标，品阶通过颜色区分（黄阶-黄色、玄阶-蓝色、地阶-紫色、天阶-金色）。
- **连线风格**：水墨笔触风格的连接线，已解锁部分为浓墨，未解锁部分为淡墨或虚线。
- **解锁特效**：满足条件时播放墨水晕染动画，节点变为金色/亮色，显示"领悟成功"提示。
- **音频要求**：
  - 解锁音效：每个解锁操作播放独特的传统乐器音效（古琴、笛子）
  - 悬停音效：鼠标悬停在节点上时播放轻微的纸张翻动声
  - 分支选择音效：选择分支路线时播放清脆的玉石碰撞声
  - 背景音乐：根据当前浏览的武学流派动态调整（少林-庄严钟声、武当-悠扬笛声、唐门-诡异琵琶）

## UI要求

- **技能树主界面**：
  - 触发：武学菜单点击"技能树"选项
  - 布局：中央显示水墨卷轴风格的技能树，左侧显示武学流派选择，右侧显示当前选中节点的详细信息
  - 功能：支持鼠标滚轮缩放、拖拽平移、点击节点查看详情和解锁操作
  - 交互：悬停显示详细信息，点击满足条件的节点进行解锁

- **武学流派选择面板**：
  - 位置：界面左侧
  - 内容：显示所有已获得和可获得的武学流派图标
  - 状态：已解锁流派显示完整图标，未解锁流派显示灰色剪影
  - 交互：点击切换当前浏览的武学流派技能树

- **节点详情面板**：
  - 位置：界面右侧
  - 内容：显示当前选中节点的名称、描述、伤害系数、消耗内力、前置条件、分支选项
  - 状态：满足解锁条件时显示"领悟"按钮，不满足时显示具体缺失条件
  - 交互：点击"领悟"按钮消耗所需物品完成解锁

- **分支选择对话框**：
  - 触发：当玩家在分支节点满足多个选择条件时
  - 布局：居中弹出对话框，显示所有可选分支的详细信息和预览效果
  - 功能：提供2-3个分支选项，每个选项显示属性要求、效果差异和不可逆提示
  - 交互：点击确认选择，一旦选择无法更改

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 武学品阶通过颜色区分（黄阶-黄色、玄阶-蓝色、地阶-紫色、天阶-金色）
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的成长路径和解锁条件，帮助玩家规划武学发展方向
  - 支持快捷键操作（WASD移动视图，鼠标滚轮缩放，空格居中当前流派）

## 验收标准

- **GIVEN** 玩家拥有华山剑法Lv.5熟练度、筑基期境界和2个武学残页，**WHEN** 在技能树界面点击崩字诀节点，**THEN** 系统验证所有解锁条件满足，播放墨水晕染动画，节点变为金色，显示"领悟成功"提示。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 玩家打开技能树界面，**THEN** 系统预加载当前武学流派数据，UI切换零延迟，其他流派按需异步加载。
- **GIVEN** 玩家STR属性为12，AGI属性为8，**WHEN** 在劈字诀分支节点选择，**THEN** 系统显示重劈（需要STR≥10）和快劈（需要AGI≥10）选项，但快劈选项为灰色不可用状态。
- **GIVEN** 玩家同时满足重劈和快劈的属性条件，**WHEN** 选择分支路线，**THEN** 系统弹出分支选择对话框，显示两个选项的详细信息和不可逆提示，玩家确认后无法更改选择。
- **GIVEN** 武学解锁条件验证失败，**WHEN** 玩家悬停在锁定节点上，**THEN** 系统显示具体的缺失条件（如"需要华山剑法Lv.5"、"缺少2个武学残页"），帮助玩家明确下一步目标。
- **GIVEN** 技能树数据文件损坏，**WHEN** 游戏启动，**THEN** 系统使用默认通用技能树模板确保基本功能，并记录错误日志。
- **GIVEN** 游戏运行在不同分辨率的设备上（1920x1080到3440x1440），**WHEN** 玩家查看技能树UI，**THEN** UI元素正确适配屏幕尺寸，支持鼠标滚轮缩放和拖拽平移。
- **GIVEN** 玩家学习《太极拳》的"借力"后，**WHEN** 查看《擒拿手》技能树，**THEN** 系统显示"反关节技"节点已解锁，体现网状关联效果。

## 开放问题

- **技能树平衡性**：如何建立有效的技能树平衡测试框架，确保不同武学流派之间的公平性？
- **动态难度调整**：如何根据玩家表现动态调整武学解锁难度和分支选择条件？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的技能树系统设计是否足够灵活？
- **本地化支持**：如何设计技能树系统以支持多语言本地化，特别是武学名称、描述和UI文本？
- **多人模式扩展**：虽然当前是单人游戏，但技能树系统是否为未来的多人合作或对战模式预留了扩展接口？
