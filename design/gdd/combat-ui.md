# 战斗UI系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-25
> **实现支柱**: 支柱1：深度武学系统

## 概述

战斗UI系统采用"沉浸式HUD + 模块化面板"的设计，通过常驻HUD（角色状态栏、行动队列、连携/连击指示器、状态效果图标栏、伤害/状态飘字）和交互面板（武学指令菜单、目标选择光标、战斗日志、暂停/战术菜单）为玩家提供清晰的信息反馈和流畅的操作体验。系统利用2D俯视角的优势，实现信息层次分明的界面布局和直观的视觉反馈，既保证了策略深度，又避免了界面混乱。

玩家通过"查看状态->选择技能->确认目标->观察结果"的操作循环体验武侠对决的核心乐趣。系统支持键盘为主、鼠标为辅的混合交互方式，确保操作效率与精准度。所有UI元素采用水墨武侠风格，普通攻击使用固定侧视角，强力技能触发特写镜头，特殊战术动作呈现特殊特效。

如果没有这个系统，游戏将失去信息反馈与操作流畅性，战斗变成猜谜游戏，节奏严重拖慢，策略失效，沉浸感破坏。该系统是实现"深度武学系统"游戏支柱的重要支撑，利用Steam平台的PC硬件优势提供高效的UI渲染、动态信息展示和实时战斗反馈。

## 玩家幻想

玩家应该能够体验到"一目了然"、"操作流畅"、"沉浸武侠"的武侠核心幻想，通过直观的UI界面和流畅的操作体验直接感受到作为武林高手的快感与成就感。

直接层面：玩家在战斗中通过清晰的UI界面获取所有必要信息（角色状态、行动顺序、技能效果、战斗结果），并通过高效的交互方式（键盘快捷键、鼠标悬停）快速做出战术决策。这是显性的操作体验过程，直接决定了战斗的流畅度和效率。玩家应该能够清晰地看到每个角色的状态条、行动队列、技能预览和战斗反馈，从而做出明智的战术选择。

间接层面：战斗UI的底层逻辑（如信号监听、数据绑定、动画播放）由系统自动处理。玩家在后台不可见这些技术实现过程，只体验到最终的结果（信息清晰显示、操作即时响应、视觉效果流畅）。这种无缝的体验让玩家专注于策略思考和武侠对决，而不是界面操作的复杂性。

参考游戏实现：
- 《最终幻想7重制版》的战斗UI，通过清晰的状态显示和技能预览提供深度战斗体验
- 《女神异闻录5》的战斗UI，通过强烈的视觉反馈和节奏变化提供爽快感
- 《暗黑破坏神4》的战斗UI，通过简洁的信息布局和流畅的操作提供直观的战斗体验

## 详细设计

### 核心规则

1. **UI界面类型**（常驻HUD + 交互面板）：
   - **常驻HUD**（始终显示）：
     - 角色状态栏(Character Status Bars)：位于屏幕左下角/右下角，显示头像、HP条（红）、Qi条（蓝）、Poise条（黄/白）
     - 行动队列(Turn Order Queue)：位于屏幕顶部中央，以图标形式显示当前回合及后续3-5个单位的行动顺序
     - 连携/连击指示器(Combo/Link Gauge)：位于屏幕侧边或角色头顶，显示当前连击数、连携槽充能进度
     - 状态效果图标栏(Status Icon Bar)：紧邻血条，显示当前激活的Buff/Debuff图标，悬停显示详情
     - 伤害/状态飘字(Floating Text)：直接在角色模型上方显示伤害数值、Miss、Crit、状态施加提示
   - **交互面板**（触发时显示）：
     - 武学指令菜单(Martial Arts Menu)：当轮到玩家行动时弹出，列出可用技能、消耗、冷却、命中率预览
     - 目标选择光标(Target Selector)：高亮可选敌人或队友，显示其弱点、剩余血量百分比
     - 战斗日志(Combat Log)：位于屏幕一侧（可折叠），以文本形式记录关键事件
     - 暂停/战术菜单(Pause/Tactical Menu)：暂停时间，允许使用道具、查看敌人详细属性、调整阵型或退出战斗

2. **UI交互方式**（键盘为主，鼠标为辅）：
   - **键盘快捷键**（Keyboard Shortcuts）：
     - 核心操作：WASD或方向键移动光标；Enter/Space确认；Esc取消/返回；Q/E切换目标；1-4快速使用常用技能或道具
     - 优势：在回合制中，键盘操作比鼠标点击更快，减少手部移动疲劳
   - **鼠标辅助**（Mouse Assistance）：
     - 悬停预览：鼠标悬停在技能图标上显示详细描述；悬停在敌人身上显示其属性和弱点
     - 点击选择：用于复杂的目标选择（如：范围攻击时点击地面确定中心点）
   - **手柄支持**（Controller Support - 可选）：
     - 若计划支持手柄，需设计径向菜单或列表导航逻辑，初期可仅做基础映射，后期优化

3. **视觉风格要求**（水墨武侠风格）：
   - **色彩体系**：
     - 主色调：黑、白、灰（水墨底色）
     - 强调色：朱砂红（HP/危险/敌人）、靛青蓝（Qi/内力/玩家）、鎏金黄（暴击/稀有/连携）
   - **元素设计**：
     - 边框：使用毛笔笔触风格的边框，而非硬朗的几何直线
     - 图标：技能图标采用简化的兵器或招式剪影，背景为宣纸纹理
     - 字体：使用楷体或行书风格的字体，增强古风韵味
   - **动效**：
     - 展开/收起：菜单出现时带有水墨晕染或卷轴展开动画
     - 反馈：按钮点击时有墨滴溅射效果；伤害数字带有轻微的抖动和消散特效
   - **透明度与层级**：
     - HUD保持半透明，避免遮挡战场关键信息
     - 重要提示（如破防、终结技）使用全屏短暂遮罩或高亮特效，确保玩家不会错过关键时刻

4. **Steam平台优化实现**：
   - **高效UI渲染**：使用UI批处理渲染，合并渲染批次，避免Draw Call飙升
   - **动态信息展示**：实时更新角色状态、行动队列、战斗日志等信息
   - **实时战斗反馈**：当发生关键战斗事件时，播放对应的粒子特效和音效
   - **音频沉浸感**：不同UI操作播放不同的音效（点击-墨滴声、确认-古琴声、取消-竹笛声）

### 状态和转换

- **无战斗状态**（No Combat）：游戏处于探索或其他非战斗模式，战斗UI完全隐藏
- **战斗准备状态**（Combat Ready）：进入战斗场景，常驻HUD显示，但交互面板隐藏
- **玩家回合状态**（Player Turn）：武学指令菜单弹出，目标选择光标激活，等待玩家输入
- **技能选择状态**（Skill Selected）：玩家选择技能后，目标选择光标高亮可选目标
- **目标确认状态**（Target Confirmed）：玩家确认目标后，执行技能动画和效果
- **敌方回合状态**（Enemy Turn）：交互面板隐藏，常驻HUD继续显示，观察敌人AI行动
- **战斗结束状态**（Combat End）：显示胜利/失败结算面板，提供战利品、经验、升级等信息

状态转换流程：
- 无战斗 → 战斗准备：遭遇敌人，摄像机切入战斗视角，显示常驻HUD
- 战斗准备 → 玩家回合：轮到玩家行动，弹出武学指令菜单
- 玩家回合 → 技能选择：玩家选择技能，进入技能选择状态
- 技能选择 → 目标确认：玩家选择目标，进入目标确认状态
- 目标确认 → 战斗准备：技能执行完成，回到战斗准备状态
- 战斗准备 → 敌方回合：轮到敌人行动，隐藏交互面板
- 敌方回合 → 战斗准备：敌人行动完成，回到战斗准备状态
- 战斗准备 → 战斗结束：战斗胜利或失败，显示结算面板
- 战斗结束 → 无战斗：玩家确认结算，返回探索模式

### 与其他系统的交互

- **战斗系统**（CombatSystem）：
  - 数据输入：监听turn_started, action_executed, damage_dealt, status_applied等信号
  - 功能输出：提供UI操作结果（技能选择、目标确认、菜单导航）
- **状态效果系统**（StatusEffectSystem）：
  - 数据输入：查询状态ID对应的图标、描述、持续时间等信息
  - 功能输出：渲染状态效果图标栏，提供悬停预览信息
- **命中检测系统**（HitDetectionSystem）：
  - 数据输入：查询技能命中率预测数据，用于武学菜单中的命中率预览
  - 功能输出：显示命中/闪避/Miss的视觉反馈
- **伤害计算系统**（DamageCalculationSystem）：
  - 数据输入：查询技能预计伤害数据，用于武学菜单中的伤害预览
  - 功能输出：显示不同类型的伤害数字（外功-白色、内功-蓝色、暴击-金色、真实-红色）
- **武学系统**（MartialArtsSystem）：
  - 数据输入：查询武学技能数据（图标、描述、消耗、冷却、属性类型）
  - 功能输出：渲染武学指令菜单，提供技能详细信息

## 公式

### UI元素位置公式

`UI元素X坐标 = 锚点X + 偏移X × 屏幕宽度`
`UI元素Y坐标 = 锚点Y + 偏移Y × 屏幕高度`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 锚点X | anchor_x | float | 0.0-1.0 | X轴锚点位置（0=左，0.5=中，1=右） |
| 锚点Y | anchor_y | float | 0.0-1.0 | Y轴锚点位置（0=上，0.5=中，1=下） |
| 偏移X | offset_x | float | -0.5-0.5 | X轴相对偏移量 |
| 偏移Y | offset_y | float | -0.5-0.5 | Y轴相对偏移量 |
| 屏幕宽度 | screen_width | int | 1280-3440 | 当前屏幕分辨率宽度 |
| 屏幕高度 | screen_height | int | 720-1440 | 当前屏幕分辨率高度 |
| UI元素X坐标 | ui_x | int | 0-3440 | UI元素在屏幕上的X坐标 |
| UI元素Y坐标 | ui_y | int | 0-1440 | UI元素在屏幕上的Y坐标 |

**输出范围:** X: 0-3440, Y: 0-1440
**示例:** 当锚点X为0.0（左），偏移X为0.1，屏幕宽度为1920时，UI元素X坐标 = 0.0 + 0.1 × 1920 = 192

### 伤害数字颜色公式

`伤害颜色 = 根据伤害类型和暴击状态选择对应颜色`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 伤害类型 | damage_type | string | 外功/内功/真实 | 伤害的属性类型 |
| 暴击状态 | is_crit | boolean | true/false | 是否为暴击伤害 |
| 伤害颜色 | damage_color | string | white/blue/purple/red | 伤害数字的显示颜色 |

**输出范围:** white, blue, purple, red
**示例:** 
- 外功普通伤害：white（白色）
- 内功普通伤害：blue（蓝色）
- 外功暴击伤害：purple（紫色）
- 真实伤害：purple（紫色）

### 状态图标透明度公式

`图标透明度 = 基础透明度 + (剩余回合数 / 最大回合数) × 透明度增量`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础透明度 | base_alpha | float | 0.5-0.8 | 图标的基础透明度 |
| 剩余回合数 | remaining_turns | int | 1-8 | 状态效果的剩余回合数 |
| 最大回合数 | max_turns | int | 1-8 | 状态效果的最大回合数 |
| 透明度增量 | alpha_increment | float | 0.1-0.3 | 透明度的增量系数 |
| 图标透明度 | icon_alpha | float | 0.6-1.0 | 最终的图标透明度 |

**输出范围:** 0.6到1.0
**示例:** 当基础透明度为0.6，剩余回合数为3，最大回合数为5，透明度增量为0.2时，图标透明度 = 0.6 + (3/5) × 0.2 = 0.6 + 0.12 = 0.72

## 边缘情况

- **如果Steam平台内存不足无法加载战斗UI系统数据**：系统将使用默认的简化UI配置，确保核心战斗功能正常运行。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前战斗状态，等待网络恢复后同步数据。
- **如果UI元素位置计算结果溢出**：系统将自动限制UI元素坐标在屏幕范围内，防止UI元素显示在屏幕外。
- **如果伤害数字颜色映射失败**：系统将使用默认白色显示所有伤害数字，确保玩家仍能看到伤害反馈。
- **如果状态图标透明度计算异常**：系统将使用默认透明度0.8，确保状态图标清晰可见。
- **如果交互面板响应超时**：系统将自动关闭交互面板并返回战斗准备状态，防止战斗卡死。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **战斗系统**：需要战斗系统提供turn_started, action_executed, damage_dealt, status_applied等信号数据
  - **状态效果系统**：需要状态效果系统提供状态ID对应的图标、描述、持续时间等信息
  - **命中检测系统**：需要命中检测系统提供技能命中率预测数据用于武学菜单中的命中率预览
  - **伤害计算系统**：需要伤害计算系统提供技能预计伤害数据用于武学菜单中的伤害预览
  - **武学系统**：需要武学系统提供武学技能数据（图标、描述、消耗、冷却、属性类型）

- **下游依赖**（依赖此系统的系统）：
  - **战斗系统**：依赖战斗UI系统提供UI操作结果（技能选择、目标确认、菜单导航）
  - **存档系统**：依赖战斗UI系统提供战斗状态和进度数据用于存档持久化

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的UI系统、动画系统、粒子系统和输入处理功能
  - **Steam平台API**：使用Steam的性能监控功能优化UI渲染效率

## 调整参数

- **UI元素锚点范围**：X: 0.0-1.0, Y: 0.0-1.0（可调整范围：X: -0.5-1.5, Y: -0.5-1.5）
- **UI元素偏移范围**：X: -0.5-0.5, Y: -0.5-0.5（可调整范围：X: -1.0-1.0, Y: -1.0-1.0）
- **状态图标基础透明度范围**：0.5-0.8（可调整范围：0.3-1.0）
- **状态图标透明度增量范围**：0.1-0.3（可调整范围：0.05-0.5）
- **伤害数字颜色映射**：外功=white, 内功=blue, 暴击=gold, 真实=red（可调整为其他颜色方案）
- **HUD透明度范围**：0.6-0.9（可调整范围：0.3-1.0）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于平衡战斗UI系统和适应不同玩家偏好。

## 视觉/音频要求

- **视觉风格一致性**：所有战斗UI元素必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **色彩体系应用**：
  - 主色调：黑、白、灰（水墨底色）用于背景和基础元素
  - 强调色：朱砂红（HP/危险/敌人）、靛青蓝（Qi/内力/玩家）、鎏金黄（暴击/稀有/连携）用于关键信息和高亮效果
- **特效表现**：
  - 菜单展开：水墨晕染或卷轴展开动画，持续0.3秒
  - 按钮点击：墨滴溅射效果，伴随轻微的屏幕震动
  - 伤害数字：带有轻微的抖动和消散特效，不同颜色代表不同类型（白色=外功、蓝色=内功、金色=暴击、红色=真实）
  - 重要提示：破防、终结技等关键时刻使用全屏短暂遮罩或高亮特效
- **UI动效**：
  - 状态图标：旋转入场，持续时间倒计时，透明度随剩余回合数变化
  - 行动队列：当前行动单位高亮显示，下一行动单位淡入提示
  - 战斗日志：新事件滚动进入，旧事件淡出消失
  - 目标选择：高亮光圈围绕可选目标，显示弱点图标和血量百分比
- **音频要求**：
  - UI操作音效：点击-墨滴声、确认-古琴声、取消-竹笛声
  - 战斗反馈音效：伤害-金属碰撞声、Miss-风声、暴击-特殊音效
  - 背景音乐：战斗BGM根据战斗紧张度动态调整（普通战斗-紧张节奏，Boss战-史诗交响）

## UI要求

- **角色状态栏**：
  - 位置：屏幕左下角/右下角
  - 布局：垂直堆叠头像、HP条（红）、Qi条（蓝）、Poise条（黄/白）
  - 样式：水墨风格边框，毛笔字体显示数值，半透明背景
  - 功能：实时显示角色当前状态，血条跳动显示伤害/回复效果

- **行动队列**：
  - 位置：屏幕顶部中央
  - 布局：水平排列当前回合及后续3-5个单位的行动图标
  - 样式：当前行动单位高亮显示，下一行动单位淡入提示
  - 功能：直观展示速度优势和行动顺序，帮助玩家制定策略

- **武学指令菜单**：
  - 位置：屏幕中央偏下，轮到玩家行动时弹出
  - 布局：网格布局显示可用技能，按类型（外功/内功/轻功）分页
  - 样式：技能图标采用简化的兵器或招式剪影，背景为宣纸纹理
  - 功能：显示技能消耗、冷却、命中率预览，支持键盘快捷键和鼠标点击

- **目标选择光标**：
  - 位置：鼠标悬停在可选目标上时显示
  - 样式：高亮光圈围绕目标，显示弱点图标和血量百分比
  - 动画：光圈脉动效果，弱点图标旋转入场
  - 交互：支持点击确认目标，WASD切换目标

- **战斗信息界面**：
  - 位置：角色模型上方
  - 样式：浮动伤害数字带有描边，不同颜色代表不同类型（白色=外功、蓝色=内功、金色=暴击、红色=真实）
  - 动画：伤害数字轻微抖动后消散，Miss显示灰色斜体文字
  - 交互：点击可查看详细伤害分解

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 状态条通过颜色区分（血条-红色、内力-蓝色、架势-黄色、连携-紫色）
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的技能预览和战斗反馈，帮助玩家做出明智的战术选择

## 验收标准

- **GIVEN** 玩家使用克制属性攻击敌人弱点，**WHEN** 攻击命中，**THEN** 敌人进入Down状态，屏幕震动，弱点图标爆炸式展开，伤害数字显示为白色（外功）或蓝色（内功）。
- **GIVEN** 玩家角色连击数达到3，**WHEN** 释放武学技能，**THEN** 伤害增加30%，伤害数字放大并闪烁金色，显示连击加成特效。
- **GIVEN** 全场所有敌人均处于Down状态，**WHEN** 战斗界面，**THEN** 显示"总攻击"按钮，点击后发动终结技，造成巨额固定伤害并结束战斗，播放全屏黑白特效。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 进入战斗场景，**THEN** 系统使用简化版UI配置，确保核心战斗功能正常运行，但视觉效果可能降级。
- **GIVEN** 游戏运行在不同分辨率的设备上（1920x1080到3440x1440），**WHEN** 查看战斗主界面，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读，不遮挡关键战场信息。
- **GIVEN** 玩家与队友连携槽均满，**WHEN** 选择合体技选项，**THEN** 发动特殊合体技能，触发全屏粒子特效和特殊音效，连携槽清空。
- **GIVEN** 战斗中所有角色死亡，**WHEN** 战斗结束，**THEN** 弹出"重伤"界面，提供消耗银两或特殊道具的复活选项，背景音乐切换为悲伤曲调。
- **GIVEN** 敌人架势条归零，**WHEN** 受到攻击，**THEN** 进入Break状态，敌人模型显示破碎效果，架势条清空动画，伤害数字显示为红色（真实伤害）。

## 开放问题

- **UI平衡性**：如何建立有效的UI平衡测试框架，确保不同分辨率和设备上的显示效果一致性和操作流畅性？
- **动态UI调整**：如何根据玩家表现和战斗节奏动态调整UI信息密度和显示方式？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的UI系统设计是否足够灵活？
- **本地化支持**：如何设计UI系统以支持多语言本地化，特别是UI文本、字体和布局适配？
- **多人模式扩展**：虽然当前是单人游戏，但UI系统是否为未来的多人合作或对战模式预留了扩展接口？
