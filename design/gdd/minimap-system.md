# 地图/小地图系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-25
> **实现支柱**: 支柱1：深度武学系统

## 概述

地图/小地图系统采用"2D手绘风格 + 动态层级"的设计，通过双层结构（局部小地图和世界大地图）为玩家提供清晰的导航和位置信息。小地图位于屏幕右上角，采用半透明背景显示当前区域的简化地形轮廓、玩家朝向箭头、周围敌人红点和任务目标标记；大地图全屏展开时采用水墨/手绘风格的区域地图，每个区域是一张独立的精美插画式地图。

系统核心包括三个功能维度：实时定位（玩家位置、朝向、周围威胁）、探索追踪（迷雾系统、兴趣点标记、探索进度）和快速导航（罗盘指引、快速旅行、路径规划）。这种设计既保证了战斗中的快速识别，又提供了宏观的世界认知，让玩家能够真正感受到"江湖之大，尽在掌握"的武侠世界观。

如果没有这个系统，游戏将失去方向感与探索驱动力，玩家在复杂的山水地形中极易迷路，任务效率低下，收集要素遗漏，世界感知弱化。该系统是实现"深度武学系统"游戏支柱的重要支撑，利用Steam平台的PC硬件优势提供程序化小地图生成、GPU加速迷雾渲染、UI动效交互和多线程路径预计算等高质量体验。

## 玩家幻想

玩家应该能够体验到"运筹帷幄"、"决胜千里"的武侠核心幻想，通过地图系统掌握江湖全局，精准定位目标，规划最优路线，直接体验到作为武林高手的战略智慧与方向感。

直接层面：玩家积极且频繁地与地图系统交互。这包括查看小地图确认当前位置和朝向、在大地图上规划快速旅行路线、标记重要地点、追踪任务目标。这是显性的导航决策和路径规划过程，直接决定了玩家的游戏效率和探索体验。玩家应该能够清晰地看到每个区域的地形轮廓、兴趣点位置、探索进度和快速旅行点，从而做出明智的导航选择。

间接层面：地图的底层逻辑（如程序化生成、迷雾渲染、路径计算）由系统自动处理。玩家在使用地图时体验的是"清晰指引"和"便捷导航"的结果，而非直接操作底层的渲染管线或数据结构。这种无缝的体验让玩家专注于江湖冒险和战略规划，而不是技术细节。

参考游戏实现：
- 《原神》的小地图系统，通过清晰的图标和标记提供高效的导航体验
- 《塞尔达传说：旷野之息》的手绘风格大地图，通过精美的插画式地图增强世界沉浸感
- 《刺客信条》系列的鹰眼视角，通过俯视图提供战术优势和方向感

## 详细设计

### 核心规则

1. **地图类型和层级**（2D手绘风格 + 动态层级）：
   - **小地图**（Minimap）：
     - 位置：屏幕右上角的圆形或方形区域
     - 视觉：半透明背景，显示当前区域的简化地形轮廓、道路、玩家朝向箭头
     - 标记：周围敌人红点、任务目标标记、兴趣点图标
     - 动态缩放：根据玩家移动速度自动调整缩放比例（跑步时缩小视野，走路时放大细节）
   - **大地图**（World Map）：
     - 触发：按下Tab或M键全屏展开
     - 视觉：水墨/手绘风格的区域地图，每个区域是独立的精美插画式地图
     - 内容：标注主要地点、传送点、未探索迷雾、区域连接关系
     - 时间控制：展开时暂停游戏时间（可选）

2. **地图功能**（实时定位 + 探索追踪 + 快速导航）：
   - **实时定位**：
     - 玩家定位：小地图始终居中，箭头指示朝向
     - 威胁显示：周围敌人以红色圆点显示，距离越近点越大
     - 队友位置：队友以蓝色三角形显示，支持点击快速切换视角
   - **探索追踪**：
     - 迷雾系统：未探索区域显示为灰色迷雾，探索后永久点亮
     - 兴趣点标记：
       - 黄色感叹号：可接取任务
       - 蓝色问号：进行中任务目标
       - 红色骷髅：高难度敌人/危险区域
       - 宝箱图标：已发现但未开启的宝箱
       - 传送点图标：已解锁的快速旅行点
     - 探索进度：显示当前区域的探索百分比（如：青云山 85%）
   - **快速导航**：
     - 罗盘环：小地图边缘显示北向南等方向指示
     - 快速旅行：在大地图上点击已解锁的传送点，确认后执行快速旅行
     - 图鉴链接：点击特定地点可查看该地点的简要介绍或相关任务线索

3. **技术实现**（Steam平台优化）：
   - **程序化小地图生成**：
     - 技术：根据当前加载的TileMap或GridMap数据，实时绘制小地图线条和图标
     - 优势：内存极低，动态更新，无限分辨率
   - **GPU加速迷雾渲染**：
     - 技术：使用ShaderMaterial覆盖迷雾纹理，GPU计算可见区域
     - 表现：迷雾消散效果流畅自然，无锯齿
   - **UI动效与交互**：
     - 技术：使用Godot的AnimationPlayer和Tween
     - 表现：地图展开水墨晕染特效，任务标记脉冲动画，快速旅行风声特效
   - **多线程路径预计算**：
     - 技术：后台线程预计算快速旅行路径点和预计时间
     - 优势：避免主线程卡顿，确保UI响应即时

4. **移除机制**：
   - 移除详细室内地图：室内场景不单独制作地图，仅依靠小地图指引出口和关键物品
   - 简化标记系统：只保留核心功能标记，避免界面过于复杂

### 状态和转换

- **未探索状态**：区域未被玩家访问，大地图显示为灰色迷雾
- **部分探索状态**：区域部分被玩家访问，大地图部分点亮，显示已发现的兴趣点
- **完全探索状态**：区域完全被玩家访问，大地图完全点亮，显示所有兴趣点和探索进度100%
- **小地图激活状态**：小地图常驻屏幕一角，显示当前区域信息
- **大地图展开状态**：大地图全屏显示，暂停游戏时间，提供宏观导航功能

状态转换流程：
- 未探索 → 部分探索：玩家首次进入区域
- 部分探索 → 完全探索：玩家探索完区域所有角落
- 小地图激活 → 大地图展开：玩家按下Tab或M键
- 大地图展开 → 小地图激活：玩家关闭大地图或执行快速旅行

### 与其他系统的交互

- **开放世界探索系统**：
  - 数据输入：接收区域地形数据、兴趣点位置、探索状态
  - 功能输出：提供导航标记、探索进度显示、快速旅行界面
- **任务系统**：
  - 任务标记：接收任务目标坐标，在小地图和大地图上显示任务标记
  - 任务状态：根据任务状态更新标记颜色（可接取-黄色、进行中-蓝色、完成-绿色）
- **奇遇系统**：
  - 奇遇标记：接收奇遇触发位置，在地图上显示特殊标记
  - 探索奖励：在地图上标记奇遇奖励位置
- **快速旅行系统**：
  - 传送点管理：显示已解锁的传送点位置和状态
  - 路径规划：提供快速旅行的路径预览和时间估算
- **战斗系统**：
  - 威胁显示：在小地图上显示周围敌人位置和威胁等级
  - 战术支援：提供战斗中的位置信息和撤退路线建议

## 公式

### 小地图缩放比例公式

`小地图缩放比例 = 基础缩放 × (1 + 移动速度修正)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础缩放 | base_zoom | float | 0.5-2.0 | 小地图的基础缩放比例 |
| 移动速度修正 | speed_modifier | float | -0.5-0.5 | 根据玩家移动速度的修正值（跑步-0.5，走路+0.5） |
| 小地图缩放比例 | minimap_zoom | float | 0.25-3.0 | 最终的小地图缩放比例 |

**输出范围:** 0.25到3.0
**示例:** 当基础缩放为1.0，玩家跑步时移动速度修正为-0.5，小地图缩放比例 = 1.0 × (1 - 0.5) = 0.5（缩小视野）

### 探索进度计算公式

`区域探索进度 = 已探索区块数 / 总区块数 × 100%`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 已探索区块数 | explored_chunks | int | 0-∞ | 玩家已探索的区块数量 |
| 总区块数 | total_chunks | int | 1-∞ | 区域总区块数量 |
| 区域探索进度 | exploration_progress | float | 0.0-100.0 | 区域探索进度百分比 |

**输出范围:** 0.0到100.0%
**示例:** 当已探索区块数为85，总区块数为100，区域探索进度 = 85 / 100 × 100% = 85%

### 敌人威胁距离公式

`敌人威胁等级 = max(0, 基础威胁 - 距离衰减 × 敌人距离)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础威胁 | base_threat | int | 1-10 | 敌人的基础威胁等级 |
| 距离衰减 | distance_decay | float | 0.01-0.1 | 距离对威胁的衰减系数 |
| 敌人距离 | enemy_distance | float | 0-∞ | 玩家与敌人的距离（像素） |
| 敌人威胁等级 | threat_level | int | 0-10 | 最终的敌人威胁等级（0表示无威胁） |

**输出范围:** 0到10
**示例:** 当基础威胁为8，距离衰减为0.05，敌人距离为100像素，敌人威胁等级 = max(0, 8 - 0.05 × 100) = max(0, 3) = 3

## 边缘情况

- **如果Steam平台内存不足无法加载地图数据**：系统将使用简化的程序化生成算法，确保核心导航功能正常运行，但视觉效果可能降级。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前地图状态和探索进度，等待网络恢复后同步数据。
- **如果玩家快速切换小地图和大地图**：系统将实施防抖机制，避免频繁切换导致UI闪烁，设置最小切换间隔（200毫秒）。
- **如果地图数据加载失败**：系统将记录错误并尝试重新加载最多3次，如果仍然失败则使用默认的简化地图模板并继续游戏流程。
- **如果快速旅行路径计算超时**：系统将使用预计算的简化路径或直接执行瞬时传送，确保玩家体验不被阻塞。
- **如果迷雾渲染出现性能问题**：系统将自动降低迷雾分辨率或切换到简单的alpha混合模式，维持60FPS目标帧率。

  - **快速旅行系统**：需要快速旅行系统提供传送点位置和解锁状态

- **下游依赖**（依赖此系统的系统）：
  - **UI系统**：依赖地图/小地图系统提供地图界面、标记图标和交互元素
  - **战斗系统**：依赖地图/小地图系统提供敌人位置和威胁等级信息
  - **导航系统**：依赖地图/小地图系统提供路径规划和方向指引

  - **Godot 4.6引擎**：利用Godot的2D渲染、ShaderMaterial和AnimationPlayer功能

- **UI切换防抖时间**：200毫秒（可调整范围：100-500毫秒）

## 视觉/音频要求

- **视觉风格一致性**：所有地图界面必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **小地图视觉表现**：半透明背景，简化地形轮廓使用水墨线条勾勒，玩家朝向箭头使用金色传统纹样，敌人红点使用渐变红色圆点。
- **大地图视觉表现**：全屏展开时采用手绘风格插画，每个区域地图包含山水、建筑、道路等元素，使用传统国画技法渲染。
- **迷雾系统特效**：未探索区域的迷雾使用水墨晕染效果，探索时迷雾消散呈现水墨流动动画。
- **标记图标设计**：所有兴趣点标记使用传统纹样图标，任务标记用黄色感叹号，危险区域用红色骷髅，宝箱用金色宝箱图标。
- **音频要求**：
  - 地图展开音效：播放古琴音效配合水墨晕染动画
  - 任务标记音效：发现新任务时播放清脆的提示音
  - 快速旅行音效：执行快速旅行时播放风声和环境音效过渡
  - 背景音乐：大地图界面播放轻松的江湖背景音乐，营造战略规划氛围

## UI要求

- **小地图界面**：
  - 位置：屏幕右上角，可配置为圆形或方形
  - 大小：可调整大小（默认150x150像素）
  - 透明度：可调整透明度（默认70%）
  - 内容：显示玩家位置（居中）、朝向箭头、周围敌人（红点）、队友（蓝三角）、任务目标（黄感叹号）、兴趣点（各种图标）
  - 交互：支持鼠标悬停查看详细信息，右键标记自定义地点

- **大地图界面**：
  - 触发：按下Tab或M键全屏展开
  - 布局：中央显示当前区域手绘地图，左侧显示区域列表，右侧显示探索进度和快速旅行点
  - 功能：点击区域切换地图，点击传送点执行快速旅行，右键标记重要地点
  - 时间控制：可选择是否暂停游戏时间（默认暂停）

- **罗盘环界面**：
  - 位置：环绕小地图边缘
  - 内容：显示东南西北方向标记，主要地标方向指示
  - 交互：点击罗盘可快速旋转视角对准指定方向

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 地图层级通过颜色区分（未探索-灰色、部分探索-黄色、完全探索-绿色）
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的标记系统和导航指引，帮助玩家规划探索路线
  - 支持快捷键操作（M-开关小地图，Tab-展开大地图，Ctrl+M-标记地点）

## 验收标准

- **GIVEN** 玩家在开放世界中移动，**WHEN** 接近区域边界，**THEN** 小地图自动更新显示相邻区域的简化地形轮廓，且不会导致帧率下降超过10%。
- **GIVEN** 玩家按下Tab键，**WHEN** 大地图展开，**THEN** 显示当前区域的手绘风格地图，暂停游戏时间，并在UI上播放水墨晕染特效。
- **GIVEN** 玩家首次进入新区域，**WHEN** 区域加载完成，**THEN** 大地图上该区域从灰色迷雾状态变为部分点亮，显示已探索的地形和兴趣点。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 玩家快速切换小地图和大地图，**THEN** 系统实施防抖机制，避免UI闪烁，确保流畅的用户体验。
- **GIVEN** 游戏运行在不同分辨率的设备上（800x600到3440x1440），**WHEN** 玩家查看地图界面，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
- **GIVEN** 玩家在大地图上点击已解锁的传送点，**WHEN** 确认快速旅行，**THEN** 播放风声和环境音效过渡，瞬时传送到目标位置。
- **GIVEN** 玩家周围有多个敌人，**WHEN** 查看小地图，**THEN** 敌人以红色圆点显示，距离越近点越大，威胁等级根据距离公式计算。
- **GIVEN** 玩家完成区域100%探索，**WHEN** 最后一个区块被探索，**THEN** 大地图完全点亮，显示"青云山 100%"探索进度，并播放特殊成就音效。

## 开放问题

- **地图数据优化**：如何进一步优化程序化小地图生成算法，减少CPU和内存占用？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的地图系统设计是否足够灵活？
- **多人模式扩展**：虽然当前是单人游戏，但地图系统是否为未来的多人合作或对战模式预留了扩展接口？
- **动态地图更新**：如何处理游戏世界中的动态变化（如建筑破坏、地形改变）在地图上的实时反映？
- **本地化支持**：如何设计地图系统以支持多语言本地化，特别是区域名称、地点描述和UI文本？
