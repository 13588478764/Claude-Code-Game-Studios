# 物品数据库

> **状态**: Approved
> **作者**: 用户 + 代理
> **最后更新**: 2026-05-15
> **实现支柱**: 支柱3：奇遇驱动的成长

## 概述

物品数据库作为游戏经济与成长系统的核心数据中枢，结构化地存储所有可交互实体（装备、消耗品、任务道具）的属性、图标及行为逻辑，支撑起玩家的收集欲、构建深度（Build）以及世界探索的奖励反馈循环。玩家在背包中主动整理、装备、使用或丢弃物品，在商店/交易中买卖，通过拾取动作获取物品，同时系统根据数据库定义的规则自动应用属性加成、触发特效或判定任务进度。如果没有这个系统，游戏将失去成长的具象化载体与经济循环的基础，玩家无法通过收集和管理资源来获得成就感或策略深度，世界探索变得空洞无物，且开发者无法在不修改核心代码的情况下灵活新增内容，导致游戏缺乏重玩价值和长期留存动力。该系统是实现"奇遇驱动的成长"游戏支柱的技术基础，使玩家能够通过奇遇获得独特的物品和装备，体验丰富的武侠世界。

## 玩家幻想

玩家应该能够感受到物品系统的丰富性和策略深度，通过收集、管理和使用不同的物品来构建独特的角色成长路径。系统应该让玩家在UI界面中直观地了解每个物品的属性、效果和稀有度，同时在游戏过程中体验到物品带来的实质性收益和成就感。

直接层面：玩家频繁且主动地与物品系统交互，包括拾取、在背包中整理/丢弃、装备/卸下、使用消耗品、在商店买卖等。这是游戏核心循环的重要组成部分。玩家应该能够清晰地看到每个物品的属性、描述、图标和特效，从而做出明智的选择。

间接层面：物品数据库作为底层基础设施，存储了物品的数值、图标、描述、特效引用等数据。玩家在战斗中获得属性加成、触发被动效果或完成任务时，是在间接体验这些数据规则带来的结果，而非直接操作数据库本身。这种无缝的体验让玩家专注于探索和成长，而不是技术细节。

参考游戏实现：
- 《暗黑破坏神》系列的物品系统，通过丰富的属性组合和稀有度系统提供深度的装备构建体验
- 《塞尔达传说：旷野之息》的物品系统，通过多样化的道具和材料支持玩家的创造性解谜和战斗策略

## 详细设计

### 核心规则

1. **数据结构**：
   - **开发期**：使用Godot Resource (.tres)系统
   - **运行期（PC优化）**：通过导出插件将.tres序列化为优化的二进制格式，在PC端异步加载并解析为内存字典
   - 实现数据分片与懒加载，按类型或来源区域拆分数据文件

2. **物品核心属性**（基于ItemData基类）：
   - **通用基础信息**：
     - `id`: String (唯一标识符)
     - `name`: String (显示名称)
     - `description`: String (详细描述)
     - `icon`: Texture2D (UI图标，使用AtlasTexture)
     - `rarity`: Enum (COMMON, RARE, EPIC, LEGENDARY)
     - `max_stack`: int (最大堆叠数)
     - `vendor_price`: int (商店售价)
     - `tags`: Array[String] (标签，用于快速筛选)
   - **装备特有属性**（EquipmentData）：
     - `slot`: Enum (WEAPON_MAIN, ARMOR_CHEST, ACCESSORY_RING等)
     - `base_stats`: Dictionary (基础属性加成)
     - `affixes`: Array[Dict] (随机词条或固定特效)
     - `level_requirement`: int (装备所需等级)
     - `model_scene`: PackedScene (3D/2D模型引用)
   - **消耗品特有属性**（ConsumableData）：
     - `effect_type`: Enum (HEAL_HP, RESTORE_MANA, BUFF_TEMP)
     - `effect_value`: float (效果数值)
     - `duration`: float (持续时间)
     - `vfx_prefab`: PackedScene (使用时的特效)
   - **任务/关键道具特有属性**（QuestItemData）：
     - `quest_id`: String (关联的任务ID)
     - `is_consumable_on_use`: bool (使用后是否消失)

3. **物品分类**（层级 + 标签混合分类）：
   - **一级分类**：EQUIPMENT, CONSUMABLE, MATERIAL, QUEST, CURRENCY
   - **二级分类**：
     - 装备：WEAPON, ARMOR, ACCESSORY
     - 武器：SWORD, BLADE, FIST (与武学系统对应)
   - **动态标签**：跨类别筛选标签（如"fire_damage", "crafting_component"）

4. **PC平台优化**：
   - **数据分片与懒加载**：按类型拆分数据文件，启动时只加载基础物品，利用PC硬件优势支持更多同时加载的物品
   - **图标图集**：所有物品图标合并到少数几个大的AtlasTexture中，支持更高分辨率
   - **模型延迟加载**：物品模型通过ID动态加载，仅在装备或预览时实例化
   - **数据压缩**：使用高效的二进制序列化格式
   - **静态数据常驻**：物品定义常驻内存，玩家持有物品实例单独存储
   - **内存预算**：物品数据库总内存占用控制在<1GB范围内

5. **与武学数据库的协同**：
   - **属性加成叠加**：物品提供全局或特定类型的属性加成
   - **武器类型匹配**：武学与装备武器类型匹配，不匹配时有惩罚或禁止使用
   - **特效触发**：物品定义"攻击时有X%概率触发Y效果"，战斗系统检查并触发
   - **专属武学解锁**：传奇武器可携带专属武学，拾取后自动解锁

### 状态和转换

- **未加载状态**：物品数据未加载到内存中
- **已加载状态**：物品数据已加载到内存字典中
- **持有状态**：玩家拥有该物品（数量>0）
- **装备状态**：玩家当前装备的物品
- **锁定状态**：未满足获取条件的物品

状态转换流程：
- 未加载 → 已加载：当玩家进入相关区域或打开背包/商店
- 已加载 → 持有：当玩家拾取、购买或通过奇遇获得物品
- 持有 → 装备：当玩家选择装备该物品
- 装备 → 持有：当玩家卸下装备
- 持有 → 已加载：当玩家丢弃或使用消耗品
- 未加载 → 锁定：当物品存在但玩家未满足获取条件

### 与其他系统的交互

- **装备系统**：提供物品数据，支持装备、卸下和属性计算
- **奖励分配系统**：提供奇遇奖励的物品数据
- **奇遇系统**：提供奇遇中可获得的物品数据
- **装备属性计算**：提供物品属性加成数据用于角色属性计算
- **UI系统**：提供物品图标、名称、描述和稀有度用于显示
- **武学系统**：提供装备对武学效果的影响数据（武器类型匹配、属性加成、特效触发）

## 公式

### 物品属性加成公式

`最终属性 = 基础属性 + Σ(装备属性加成) + Σ(消耗品临时加成)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础属性 | base_stat | float | 1-1000 | 角色的基础属性值 |
| 装备属性加成 | equipment_bonus | float | -100-500 | 装备提供的属性加成 |
| 消耗品临时加成 | consumable_bonus | float | -50-200 | 消耗品提供的临时属性加成 |
| 最终属性 | final_stat | float | 1-2000 | 最终的属性值 |

**输出范围:** 1到2000
**示例:** 当基础属性为100，装备属性加成为50，消耗品临时加成为20时，最终属性 = 100 + 50 + 20 = 170

### 武器类型匹配伤害公式

`最终伤害 = 武学基础伤害 × 武器类型匹配系数 × (1 + 装备总加成)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 武学基础伤害 | base_damage | float | 10-1000 | 武学的基础伤害值 |
| 武器类型匹配系数 | weapon_match_multiplier | float | 0.7-1.2 | 武器类型匹配系数（完美适配=1.2，不完美适配=0.7，完全不匹配=无法使用） |
| 装备总加成 | total_equipment_bonus | float | 0.0-3.0 | 装备提供的总伤害加成 |
| 最终伤害 | final_damage | float | 5-4000 | 最终造成的伤害值 |

**输出范围:** 5到4000
**示例:** 当武学基础伤害为200，武器类型匹配系数为1.2（完美适配），装备总加成为0.5时，最终伤害 = 200 × 1.2 × (1 + 0.5) = 360

### 物品稀有度颜色公式

`稀有度颜色 = 根据稀有度等级选择对应的颜色`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 稀有度等级 | rarity | Enum | COMMON, RARE, EPIC, LEGENDARY | 物品的稀有度等级 |
| 稀有度颜色 | rarity_color | String | #FFFFFF, #0000FF, #800080, #FFD700 | 对应的显示颜色 |

**输出范围:** 
- COMMON: #FFFFFF (白色)
- RARE: #0000FF (蓝色)  
- EPIC: #800080 (紫色)
- LEGENDARY: #FFD700 (金色)

**示例:** 当稀有度为LEGENDARY时，稀有度颜色 = #FFD700 (金色)

## 边缘情况

- **如果物品数据加载失败**：系统将使用默认的通用物品数据，确保玩家仍能进行基本游戏，同时记录错误日志。
- **如果物品属性值超出合理范围**：系统将自动将值限制在预定义的安全范围内，并记录警告日志。
- **如果Web平台内存不足无法加载所有物品数据**：系统将优先加载玩家已持有和常用物品，其他物品按需加载。
- **如果物品图标资源缺失**：系统将使用通用的水墨风格图标替代，确保视觉一致性。
- **如果装备与武学类型不匹配**：系统将应用50%的伤害惩罚，或在UI中明确提示该武学无法使用。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - 无（作为基础层系统，物品数据库不依赖其他游戏系统）

- **下游依赖**（依赖此系统的系统）：
  - **装备系统**：需要物品数据库提供完整的物品数据
  - **奖励分配系统**：需要物品数据库提供奇遇奖励的物品数据
  - **奇遇系统**：需要物品数据库提供奇遇中可获得的物品数据
  - **装备属性计算**：需要物品数据库提供物品属性加成数据
  - **UI系统**：需要物品数据库提供物品图标、名称、描述和稀有度用于显示
  - **武学系统**：需要物品数据库提供装备对武学效果的影响数据

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的Resource系统和数据序列化功能
  - **Steam平台API**：使用Steam的云存档功能和成就系统

## 调整参数

- **基础属性范围**：1-1000（可调整范围：0.1-2000）
- **装备属性加成范围**：-100-500（可调整范围：-200-1000）
- **消耗品临时加成范围**：-50-200（可调整范围：-100-500）
- **武器类型匹配系数范围**：0.5-1.0（可调整范围：0.1-1.5）
- **装备总加成范围**：0.0-3.0（可调整范围：0.0-5.0）
- **稀有度颜色**：COMMON-白色、RARE-蓝色、EPIC-紫色、LEGENDARY-金色（可调整为其他配色方案）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于平衡物品系统和适应不同难度级别。

## 视觉/音频要求

- **视觉风格一致性**：所有物品图标和描述必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **物品图标设计**：每个物品应有独特的水墨风格图标，稀有度通过颜色区分（COMMON-白色、RARE-蓝色、EPIC-紫色、LEGENDARY-金色）。
- **特效风格**：物品使用特效应体现武侠特色，使用水墨晕染、粒子效果和传统纹样。
- **动画要求**：物品拾取和使用动画应体现武侠的飘逸感和力量感，符合角色门派特色。
- **音频要求**：每个物品应有独特的拾取音效和使用音效，使用传统乐器音效（如古琴、笛子）营造武侠氛围。

## UI要求

- **物品列表界面**：显示所有已获得物品，按类型、稀有度、装备部位分类筛选
- **物品详情界面**：显示物品的完整属性、描述、图标和特效预览
- **背包界面**：允许玩家整理、装备、使用或丢弃物品
- **商店界面**：显示可购买和出售的物品，支持价格查看和交易
- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 物品稀有度通过颜色区分（COMMON-白色、RARE-蓝色、EPIC-紫色、LEGENDARY-金色）
  - 确保UI在Web平台上清晰可读，适配不同屏幕尺寸
  - 提供直观的物品比较和装备建议功能

## 验收标准

- **GIVEN** 玩家打开背包界面，**WHEN** 浏览已获得物品，**THEN** 所有物品按类型、稀有度、装备部位正确分类显示，且图标和描述符合水墨武侠风格。
- **GIVEN** 玩家选择一个物品查看详情，**WHEN** 查看物品属性，**THEN** 显示完整的属性、描述、稀有度和特效预览。
- **GIVEN** 玩家装备一个物品，**WHEN** 在战斗中使用相关武学，**THEN** 物品属性加成正确应用，武器类型匹配逻辑正常工作。
- **GIVEN** PC平台内存充足（>2GB可用），**WHEN** 玩家加载物品数据，**THEN** 系统可以加载更多物品数据，保持总内存占用低于1GB。
- **GIVEN** 物品数据文件损坏或缺失，**WHEN** 游戏启动，**THEN** 系统使用默认通用物品数据确保基本游戏功能，并记录错误日志。
- **GIVEN** 游戏运行在不同分辨率的设备上（800x600到1920x1080），**WHEN** 玩家查看物品UI，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
- **GIVEN** 玩家在商店界面，**WHEN** 浏览可购买物品，**THEN** 显示正确的物品价格和描述，支持购买和出售操作。

## 开放问题

- **数据结构优化**：如何进一步优化Godot Resource系统在Web平台上的加载性能？
- **物品平衡性**：如何建立有效的物品平衡测试框架，确保不同物品之间的公平性？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的数据结构是否足够灵活？
- **本地化支持**：如何设计物品数据库以支持多语言本地化，特别是物品名称和描述？
- **经济系统扩展**：虽然游戏不包含复杂经济系统，但如何设计物品价值体系以支持简单的交易和制作功能？
