# 生命值/防御系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-28
> **实现支柱**: 支柱1：深度武学系统

## 概述

生命值/防御系统采用"传统血条 + 架势破防"的双层生存机制，通过生命值(HP)和架势值(Poise)两个核心数值为玩家提供深度策略体验。系统利用2D俯视角的优势，实现减法防御和概率规避的混合模型，既保留武侠战斗中"见招拆招"的博弈感，又避免过于复杂的操作门槛。

玩家通过管理生命值和架势值，在"进攻-防御-破防"的策略循环中体验武侠高手过招的核心乐趣。系统支持护甲减伤、抗性减免、闪避规避和格挡减伤四种防御类型，确保战斗既有策略深度又不会过于复杂。所有防御效果通过动态UI展示，普通攻击使用固定侧视角，强力技能触发特写镜头，破防状态呈现全屏特效。

如果没有这个系统，游戏将失去生存策略与战斗节奏，战斗变成无脑换血，坦克职业失去存在意义，紧张感缺失，Boss战变得乏味。该系统是实现"深度武学系统"游戏支柱的重要支撑，利用Steam平台的PC硬件优势提供高效的数值计算、动态UI展示和实时战斗反馈。

## 玩家幻想

玩家应该能够体验到"见招拆招"、"以守为攻"、"一击必杀"的武侠核心幻想，通过精准的防御管理和破防时机把握直接体验到作为武林高手的快感与成就感。

直接层面：玩家在战斗中积极管理生命值和架势值，选择防御、闪避、格挡等策略应对不同攻击，并寻找破防机会发动致命一击。这是显性的生存管理过程，直接决定了战斗的胜负和效率。玩家应该能够清晰地看到自己的HP条、Poise条、防御状态和破防提示，从而做出明智的战术选择。

间接层面：生命值/防御的底层逻辑（如减法防御计算、概率规避判定、破防状态触发）由系统自动处理。玩家在后台不可见这些计算过程，只体验到最终的结果（是否成功防御、是否触发破防、造成了多少伤害）。这种无缝的体验让玩家专注于策略思考和武侠对决，而不是复杂的数学计算。

参考游戏实现：
- 《只狼》的架势破防系统，通过精准的时机判断和反击提供紧张刺激的战斗节奏
- 《女神异闻录5》的弱点打击系统，通过强烈的视觉反馈和数值变化提供爽快感
- 《最终幻想7重制版》的ATB系统和防御机制，结合实时动作和策略指令提供深度战斗体验

## 详细设计

### 核心规则

1. **生命值机制**（双层生存结构）：
   - **生命值**（HP - Health Points）：
     - 定义：角色的根本生存指标，归零即死亡/战败
     - 表现：传统的红色长条
     - 特性：一旦扣除，不会在单场战斗中自动恢复（除非使用特定技能或道具）
   - **架势值**（Poise/Stance）：
     - 定义：角色的防御姿态稳定性，代表抵抗攻击、维持平衡的能力
     - 表现：位于HP条下方的黄色/白色短条，或环绕角色的光环
     - 关联属性：架势条上限受定力(WILL)属性影响，每点定力增加架势条上限+10
     - 机制：
       - 受损：受到任何攻击都会削减架势值（重攻击/克制属性削减更多）
       - 恢复：每回合结束或选择"防御/蓄力"指令时快速恢复
       - 破防(Break)：当架势值归零，角色进入"破防状态"：
         - 本回合无法行动（跳过回合）
         - 受到的下一次伤害大幅增加（+50%或+100%）
         - 暴露所有弱点，必定被击中

2. **防御类型**（减法防御 + 概率规避）：
   - **护甲/根骨**（Armor/CON - Damage Reduction）：
     - 机制：固定减伤，公式：Final_Damage = Raw_Damage - Armor_Value
     - 适用：主要对抗外功伤害
     - 来源：装备防具、角色根骨(CON)属性
     - 特点：对低伤害攻击有显著效果（甚至完全免疫），对高伤害攻击效果递减
   - **内力抗性**（Qi Resist/WIS - Percentage Reduction）：
     - 机制：百分比减伤，公式：Final_Damage = Raw_Damage × (1 - Resist_Percentage)
     - 适用：主要对抗内功/元素伤害
     - 来源：角色悟性(WIS)属性、特定饰品或心法
     - 特点：无论伤害多高，都能稳定按比例减免
   - **闪避**（Dodge/Evasion - Avoidance）：
     - 机制：完全免伤，基于身法(AGI)与敌人命中率的对比判定
     - 表现：若判定成功，伤害为0，并显示"Miss"或"闪避"特效
     - 代价：闪避通常不消耗资源，但失败则承受全额伤害
   - **格挡**（Block/Parry - Mitigation）：
     - 机制：主动减伤，玩家在回合中选择"防御"指令
     - 效果：本回合受到的所有伤害减少50%-70%，并大幅恢复架势值
     - 完美格挡：若预判准确（针对特定强力攻击），可完全抵消伤害并反弹少量架势伤害给敌人

3. **恢复机制**（战斗内外分离）：
   - **战斗内恢复**（In-Combat）：
     - HP恢复：极度受限，默认情况下不自动恢复，仅能通过消耗品（金创药）、特定治疗武学或吸血类特效恢复
     - 架势值(Poise)恢复：每回合结束时恢复Max_Poise×20%，选择"防御"或"蓄力"指令恢复Max_Poise×50%
   - **战斗外恢复**（Out-of-Combat）：
     - 自动满额：脱离战斗状态3-5秒后，HP和Poise开始快速自动恢复至最大值
     - 休息点：在土地庙、客栈休息可完全恢复所有状态并保存游戏
     - 环境加成：在灵气浓郁区域，非战斗状态下HP恢复速度加倍

4. **Steam平台优化实现**：
   - **高效数值计算**：使用预计算缓存避免重复计算，多线程后台处理复杂公式
   - **动态UI展示**：实时显示HP条和Poise条，不同颜色代表不同状态（红色=HP，黄色=Poise，破防时变红闪烁）
   - **实时战斗反馈**：当敌人破防时，播放碎裂音效，Poise条变红并闪烁，头顶显示"BREAK!"字样
   - **音频沉浸感**：不同防御类型播放不同的音效（格挡-金属碰撞声、闪避-风声、破防-碎裂声）

### 状态和转换

- **正常状态**（Normal）：HP和Poise均正常，可以正常行动
- **防御状态**（Defending）：选择"防御"指令，本回合受到伤害减少，Poise恢复增加
- **破防状态**（Break）：Poise归零，本回合无法行动，下一次伤害大幅增加
- **濒死状态**（Critical）：HP低于10%，UI显示红色警告，行动可能受限
- **死亡状态**（Dead）：HP归零，战斗失败，弹出"重伤"界面

状态转换流程：
- 正常 → 防御：玩家选择"防御"指令
- 正常 → 破防：受到攻击导致Poise归零
- 防御 → 正常：回合结束，恢复正常状态
- 防御 → 破防：即使在防御状态，如果受到足够强力的攻击仍可能导致Poise归零
- 破防 → 正常：破防效果结束后，Poise重置为0但可以正常行动
- 正常 → 濒死：HP降至10%以下
- 濒死 → 死亡：HP归零
- 死亡 → 重伤界面：弹出复活选项

### 与其他系统的交互

- **战斗系统**（CombatSystem）：
  - 数据输入：接收战斗实体的HP、Poise、防御属性等数据
  - 功能输出：提供防御判定结果、破防状态触发、恢复机制执行
- **伤害计算系统**（DamageCalculationSystem）：
  - 数据输入：查询护甲值、内力抗性、闪避率等防御属性
  - 功能输出：提供最终伤害值，用于扣减HP和Poise
- **装备系统**（EquipmentSystem）：
  - 数据输入：查询装备提供的护甲、抗性、HP加成等属性
  - 功能输出：提供装备属性对防御能力的影响计算
- **角色成长系统**（CharacterProgressionSystem）：
  - 数据输入：查询角色属性（CON、WIS、AGI）对防御能力的影响
  - 功能输出：提供属性成长对HP上限、Poise上限、防御效果的提升
- **UI系统**（UISystem）：
  - 数据输入：接收HP、Poise当前值和最大值、防御状态、破防状态等信息
  - 功能输出：渲染双条显示、破防特效、防御提示、濒死警告等UI元素

## 公式

### 生命值计算公式

`最大生命值 = 基础生命值 + 根骨属性 × 生命值系数 + 装备加成`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础生命值 | base_hp | int | 50-200 | 角色的基础生命值 |
| 根骨属性 | con_stat | int | 10-200 | 角色的根骨(CON)属性值 |
| 生命值系数 | hp_coefficient | float | 1.0-3.0 | 每点根骨提供的生命值加成 |
| 装备加成 | equipment_bonus | int | 0-500 | 装备提供的生命值加成 |
| 最大生命值 | max_hp | int | 100-2000 | 角色的最大生命值 |

**输出范围:** 100到2000
**示例:** 当基础生命值为100，根骨属性为80，生命值系数为2.0，装备加成为50时，最大生命值 = 100 + 80 × 2.0 + 50 = 310

### 架势值计算公式

`最大架势值 = 基础架势值 + 定力属性 × 架势系数 + 装备加成`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础架势值 | base_poise | int | 20-100 | 角色的基础架势值 |
| 定力属性 | wil_stat | int | 10-200 | 角色的定力(WIL)属性值 |
| 架势系数 | poise_coefficient | float | 0.5-2.0 | 每点定力提供的架势值加成 |
| 装备加成 | equipment_bonus | int | 0-200 | 装备提供的架势值加成 |
| 最大架势值 | max_poise | int | 50-800 | 角色的最大架势值 |

**输出范围:** 50到800
**示例:** 当基础架势值为50，悟性属性为60，架势系数为1.5，装备加成为30时，最大架势值 = 50 + 60 × 1.5 + 30 = 170

### 护甲减伤公式

`最终伤害 = 原始伤害 - 护甲值`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 原始伤害 | raw_damage | int | 1-3000 | 伤害计算系统提供的原始伤害值 |
| 护甲值 | armor_value | int | 0-500 | 角色的护甲值（装备+根骨） |
| 最终伤害 | final_damage | int | 1-3000 | 应用护甲减伤后的最终伤害值 |

**输出范围:** 1到3000
**示例:** 当原始伤害为200，护甲值为80时，最终伤害 = 200 - 80 = 120

### 内力抗性公式

`最终伤害 = 原始伤害 × (1 - 内力抗性)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 原始伤害 | raw_damage | int | 1-3000 | 伤害计算系统提供的原始伤害值 |
| 内力抗性 | qi_resist | float | 0.0-0.8 | 角色的内力抗性（0.0=0%，0.8=80%） |
| 最终伤害 | final_damage | int | 1-3000 | 应用内力抗性后的最终伤害值 |

**输出范围:** 1到3000
**示例:** 当原始伤害为200，内力抗性为0.3时，最终伤害 = 200 × (1 - 0.3) = 200 × 0.7 = 140

### 闪避判定公式

`闪避成功 = 随机数 < 闪避率`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 随机数 | random_value | float | 0.0-1.0 | 0到1之间的随机数 |
| 闪避率 | evasion_rate | float | 0.0-0.5 | 角色的闪避率（0.0=0%，0.5=50%） |
| 闪避成功 | dodge_success | boolean | true/false | 闪避是否成功 |

**输出范围:** true或false
**示例:** 当随机数为0.25，闪避率为0.3时，闪避成功 = 0.25 < 0.3 = true

### 破防伤害加成公式

`破防伤害 = 基础伤害 × 破防系数`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础伤害 | base_damage | int | 1-3000 | 伤害计算系统提供的基础伤害值 |
| 破防系数 | break_multiplier | float | 1.5-2.0 | 破防状态下的伤害加成系数 |
| 破防伤害 | break_damage | int | 1-6000 | 破防状态下的最终伤害值 |

**输出范围:** 1到6000
**示例:** 当基础伤害为200，破防系数为1.5时，破防伤害 = 200 × 1.5 = 300

## 边缘情况

- **如果Steam平台内存不足无法加载生命值/防御系统数据**：系统将使用默认的通用生命值/防御配置，确保核心战斗功能正常运行。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前战斗状态，等待网络恢复后同步数据。
- **如果生命值计算结果溢出**：系统将自动限制最大生命值在100-2000范围内，防止数值溢出导致游戏崩溃。
- **如果架势值计算结果溢出**：系统将自动限制最大架势值在50-800范围内，防止数值溢出导致游戏崩溃。
- **如果护甲值超过原始伤害**：系统将确保最终伤害至少为1，避免完全免疫所有伤害导致战斗僵局。
- **如果内力抗性超过80%**：系统将自动限制内力抗性在0.0-0.8范围内，防止过度减伤破坏平衡。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **战斗系统**：需要战斗系统提供战斗实体数据、回合状态、行动指令等信息
  - **伤害计算系统**：需要伤害计算系统提供原始伤害值、伤害类型、暴击状态等数据
  - **装备系统**：需要装备系统提供护甲、抗性、HP加成、Poise加成等属性数据
  - **角色成长系统**：需要角色成长系统提供CON、WIS、AGI等基础属性数据

- **下游依赖**（依赖此系统的系统）：
  - **战斗系统**：依赖生命值/防御系统提供防御判定结果、破防状态触发、恢复机制执行
  - **UI系统**：依赖生命值/防御系统提供HP、Poise当前值和最大值、防御状态、破防状态等信息

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的状态机、数值计算和UI系统功能
  - **Steam平台API**：使用Steam的性能监控功能优化数值计算效率

## 视觉/音频要求

- **视觉风格一致性**：所有生命值/防御UI元素必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **双条显示**：角色头像旁显示红色HP条和黄色Poise条，破防时Poise条变红并闪烁
- **特效表现**：
  - 破防效果：播放碎裂音效，Poise条变红并闪烁，头顶显示"BREAK!"字样
  - 濒死警告：HP低于10%时，HP条闪烁红色，UI显示红色警告边框
  - 防御提示：当玩家HP低下时，UI高亮"防御"按钮，提示玩家采取守势
- **UI动效**：
  - 血条跳动：受到伤害时血条闪烁红色，回复时闪烁绿色
  - 架势恢复：选择"防御"指令时，Poise条快速填充动画
  - 状态转换：从正常状态到破防状态时，播放破碎粒子效果
- **音频要求**：
  - 格挡音效：清脆的金属碰撞声
  - 闪避音效：轻柔的风声
  - 破防音效：玻璃碎裂般的音效
  - 濒死音效：低沉的警报声
  - 背景音乐：战斗BGM根据HP百分比动态调整（HP>50%-正常节奏，HP<50%-紧张节奏，HP<10%-急促节奏）

  - 动画：受到伤害时闪烁红色，回复时闪烁绿色
  - 数值：显示"当前HP/最大HP"格式（如：850/1000）
  - 交互：鼠标悬停显示详细属性（基础HP、根骨加成、装备加成）

  - 颜色：黄色，破防时变红并闪烁
  - 动画：受到攻击时减少，选择"防御"指令时快速填充
  - 数值：显示"当前Poise/最大Poise"格式（如：40/50）
  - 交互：鼠标悬停显示详细属性（基础Poise、悟性加成、装备加成）

  - 破防提示：头顶显示"BREAK!"字样，播放破碎粒子效果
  - 濒死警告：HP低于10%时，UI显示红色警告，高亮"防御"按钮
  - 防御提示：当玩家HP低下时，自动高亮"防御"按钮，提示采取守势
  - 完美格挡：成功完美格挡时，显示"Perfect Block!"提示和特殊音效

  - 位置：按F1打开开发者控制台，输入show_defense_stats命令
  - 样式：表格形式显示完整的防御属性计算过程
  - 内容：显示护甲值、内力抗性、闪避率、HP/Poise详细构成
  - 交互：支持复制防御属性日志，便于平衡测试和调试

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 状态条通过颜色和动画直观传达状态变化
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的防御提示和状态反馈，帮助玩家做出明智的战术选择

## 验收标准

- **GIVEN** 玩家角色受到外功攻击，**WHEN** 生命值/防御系统执行护甲减伤计算，**THEN** 系统正确使用护甲值进行固定减伤，最终伤害 = 原始伤害 - 护甲值。
- **GIVEN** 玩家角色受到内功攻击，**WHEN** 生命值/防御系统执行内力抗性计算，**THEN** 系统正确使用内力抗性进行百分比减伤，最终伤害 = 原始伤害 × (1 - 内力抗性)。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 进入战斗场景，**THEN** 系统使用默认的通用生命值/防御配置，确保核心战斗功能正常运行。
- **GIVEN** 游戏运行在不同分辨率的设备上（1920x1080到3440x1440），**WHEN** 查看生命值/防御界面，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
- **GIVEN** 玩家HP低于10%，**WHEN** 战斗界面，**THEN** HP条闪烁红色，UI显示红色警告边框，高亮"防御"按钮。
- **GIVEN** 敌人架势值归零，**WHEN** 受到攻击，**THEN** 进入破防状态，Poise条变红并闪烁，头顶显示"BREAK!"字样，下一次伤害增加50%-100%。
- **GIVEN** 护甲值超过原始伤害，**WHEN** 系统处理最终伤害，**THEN** 确保最终伤害至少为1，避免完全免疫所有伤害导致战斗僵局。
- **GIVEN** 玩家选择"防御"指令，**WHEN** 回合结束，**THEN** Poise条快速填充动画，本回合受到的所有伤害减少50%-70%。

## 开放问题

- **生命值平衡性**：如何建立有效的生命值平衡测试框架，确保不同角色构建和敌人配置之间的公平性？
- **动态难度调整**：如何根据玩家表现动态调整敌人强度和战斗节奏？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的生命值/防御系统设计是否足够灵活？
- **本地化支持**：如何设计生命值/防御系统以支持多语言本地化，特别是UI文本和音频提示？
- **多人模式扩展**：虽然当前是单人游戏，但生命值/防御系统是否为未来的多人合作或对战模式预留了扩展接口？
