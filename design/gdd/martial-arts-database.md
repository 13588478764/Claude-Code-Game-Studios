# 武学数据库

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-24
> **实现支柱**: 支柱1：深度武学系统

## 概述

武学数据库作为游戏战斗系统的核心数据中枢，结构化地存储招式属性、前摇后摇、判定框及连招逻辑，确保战斗体验的平衡性、一致性与可扩展性。玩家通过菜单主动浏览、学习、装备或升级武学，并在战斗中主动输入指令触发具体招式，同时系统根据数据库定义的规则自动计算伤害、硬直和状态效果。如果没有这个系统，游戏将失去战斗的深度与多样性，角色行动会变得单一且不可定制，开发者也无法在不修改核心代码的情况下快速迭代或新增战斗内容，导致玩法枯燥且维护成本极高。该系统是实现"深度武学系统"游戏支柱的技术基础，使玩家能够构建个性化的武学组合，体验丰富的武侠战斗。

## 玩家幻想

玩家应该能够感受到武学系统的深度和多样性，通过浏览、选择和组合不同的武学技能，构建独特的战斗风格。系统应该让玩家在UI界面中直观地了解每个武学的特点和效果，同时在战斗中体验到流畅、有力的招式连击和丰富的战斗反馈。

直接层面：玩家在UI界面中主动浏览、选择、装备和升级武学（招式/技能），这是显性的交互。玩家应该能够清晰地看到每个武学的属性、前摇后摇时间、伤害类型和特殊效果，从而做出明智的选择。

间接层面：在战斗过程中，数据库作为底层基础设施，无声地提供判定数据、数值平衡和逻辑规则，玩家体验的是战斗结果（伤害、特效、硬直），而非直接操作数据库本身。这种无缝的体验让玩家专注于战斗策略和技巧，而不是技术细节。

参考游戏实现：
- 《如龙8》的多样化技能组合系统，允许玩家自由搭配不同技能形成独特战斗风格
- 《最终幻想7重制版-重生》的挑战性战斗系统，通过精确的招式判定和连击系统提供深度战斗体验

## 详细设计

### 核心规则

1. **数据结构**：
   - 使用Godot Resource (.tres)系统作为主要数据格式
   - 在Web平台导出时，通过导出脚本将所有武学资源合并为JSON或二进制包
   - 实现异步加载机制，避免频繁的磁盘I/O

2. **武学核心属性**（基于MartialArtData基类）：
   - **基础信息**：
     - `id`: String (唯一标识符)
     - `name`: String (显示名称)
     - `description`: String (描述)
     - `icon`: Texture2D (UI图标)
   - **消耗与限制**：
     - `cost_stamina`: float (体力消耗)
     - `cost_mana`: float (内力/能量消耗)
     - `cooldown`: float (冷却时间，秒)
     - `unlock_level`: int (解锁所需角色等级)
   - **战斗参数**：
     - `damage_base`: float (基础伤害)
     - `damage_scale`: float (攻击力加成系数)
     - `hit_count`: int (攻击段数)
     - `element_type`: Enum (金木水火土/无)
   - **时序控制**：
     - `startup_frames`: float (前摇/发动时间，秒)
     - `active_frames`: float (有效判定持续时间，秒)
     - `recovery_frames`: float (后摇/硬直时间，秒)
     - `total_duration`: float (总时长)
   - **视觉与听觉**：
     - `vfx_prefab`: PackedScene (特效场景引用)
     - `sfx_hit`: AudioStream (命中音效)
     - `sfx_cast`: AudioStream (释放音效)
     - `camera_shake`: Vector2 (相机震动强度)

3. **武学分类**（多维标签系统）：
   - **主要类型**：ATTACK, DEFENSE, MOVEMENT, BUFF, DEBUFF
   - **武器类型**：SWORD, BLADE, FIST, STAFF, NONE
   - **门派/流派**：字符串标签（如"Shaolin", "Wudang", "Generic"）
   - **品阶**：COMMON, RARE, EPIC, LEGENDARY

4. **连招系统**：
   - 创建独立的ComboChain资源定义连招关系
   - 结构：`previous_art_id -> input_window -> next_art_id`
   - 武学内部添加`can_cancel_from_frame`属性定义取消窗口
   - 实现"状态机 + 输入缓冲"混合模式

5. **Web平台优化**：
   - **资源分片**：按门派或品阶打包，初始只加载基础武学
   - **纹理图集**：所有武学图标合并到AtlasTexture
   - **延迟加载特效**：只在武学释放时加载特效场景
   - **数据压缩**：使用GZIP压缩JSON数据
   - **对象池**：武学产生的特效、投射物使用对象池管理

### 状态和转换

- **未加载状态**：武学数据未加载到内存中
- **已加载状态**：武学数据已加载到内存字典中
- **激活状态**：玩家当前装备的武学
- **锁定状态**：未满足解锁条件的武学

状态转换流程：
- 未加载 → 已加载：当玩家进入相关区域或打开武学菜单
- 已加载 → 激活：当玩家选择装备该武学
- 激活 → 已加载：当玩家更换装备的武学
- 未加载 → 锁定：当武学存在但玩家等级不足

### 与其他系统的交互

- **武学系统**：提供武学数据，支持学习、装备和使用
- **技能树/学习路径系统**：提供武学解锁条件和依赖关系
- **武学组合/连招系统**：提供连招定义和取消窗口数据
- **战斗系统**：提供战斗参数、时序控制和视觉听觉资源
- **装备属性计算**：提供武学对角色属性的影响数据
- **UI系统**：提供武学图标、名称和描述用于显示

## 公式

### 武学伤害计算公式

`最终伤害 = 基础伤害 × 暴击系数 × 连击系数 × 弱点系数 × 破防系数 × 状态系数 × 随机浮动 × 元素克制倍率`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础伤害 | base_damage | int | 10-1000 | 武学的基础伤害值 |
| 暴击系数 | crit_multiplier | float | 1.0-2.5 | 暴击时的伤害倍数（通常为1.5-2.0） |
| 连击系数 | combo_multiplier | float | 1.0-1.3 | 连击数对应的伤害加成（最高30%） |
| 弱点系数 | weakness_multiplier | float | 1.0-1.5 | 弱点克制修正（克制=1.5，无关系=1.0） |
| 破防系数 | break_multiplier | float | 1.0-1.5 | 破防状态修正（破防=1.5，正常=1.0） |
| 状态系数 | status_multiplier | float | 0.5-2.0 | 状态效果修正（易伤=1.5，虚弱=0.8，破防=1.5） |
| 随机浮动 | random_variance | float | 0.95-1.05 | 随机浮动因子，增加战斗变数 |
| 元素克制倍率 | element_multiplier | float | 1.0-1.5 | 元素相克产生的伤害倍率（克制=1.5，无关系=1.0） |
| 最终伤害 | final_damage | int | 5-3000 | 最终造成的伤害值 |

**输出范围:** 5到3000
**示例:** 当基础伤害为100，暴击系数为1.5，连击系数为1.2，弱点系数为1.5，破防系数为1.5，状态系数为1.0，随机浮动为1.0，元素克制倍率为1.5时，最终伤害 = 100 × 1.5 × 1.2 × 1.5 × 1.5 × 1.0 × 1.0 × 1.5 = 607.5

### 武学冷却时间公式

`实际冷却时间 = 基础冷却时间 × (1 - 冷却缩减系数)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础冷却时间 | cooldown | float | 1.0-30.0 | 武学的基础冷却时间（秒） |
| 冷却缩减系数 | cooldown_reduction | float | 0.0-0.8 | 装备或技能提供的冷却缩减 |
| 实际冷却时间 | actual_cooldown | float | 0.2-30.0 | 实际的冷却时间（秒） |

**输出范围:** 0.2到30.0秒
**示例:** 当基础冷却时间为10秒，冷却缩减系数为0.3时，实际冷却时间 = 10 × (1 - 0.3) = 10 × 0.7 = 7秒

### 武学消耗资源公式

`实际消耗 = 基础消耗 × (1 + 消耗增加系数)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础消耗 | base_cost | float | 10-200 | 武学的基础资源消耗 |
| 消耗增加系数 | cost_increase | float | -0.5-1.0 | 装备或状态提供的消耗增减 |
| 实际消耗 | actual_cost | float | 5-400 | 实际的资源消耗 |

**输出范围:** 5到400
**示例:** 当基础消耗为50，消耗增加系数为-0.2时，实际消耗 = 50 × (1 - 0.2) = 50 × 0.8 = 40

## 边缘情况

- **如果武学数据加载失败**：系统将使用默认的通用武学数据，确保玩家仍能进行基本战斗，同时记录错误日志。
- **如果连招定义存在循环引用**：系统将在加载时检测并断开循环，选择第一个定义的连招路径，避免无限循环。
- **如果武学属性值超出合理范围**：系统将自动将值限制在预定义的安全范围内，并记录警告日志。
- **如果Web平台内存不足无法加载所有武学数据**：系统将优先加载玩家已解锁和常用武学，其他武学按需加载。
- **如果武学特效资源缺失**：系统将使用通用的水墨风格特效替代，确保视觉一致性。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - 无（作为基础层系统，武学数据库不依赖其他游戏系统）

- **下游依赖**（依赖此系统的系统）：
  - **武学系统**：需要武学数据库提供完整的武学数据
  - **技能树/学习路径系统**：需要武学数据库提供解锁条件和依赖关系
  - **武学组合/连招系统**：需要武学数据库提供连招定义和取消窗口数据
  - **战斗系统**：需要武学数据库提供战斗参数、时序控制和资源引用
  - **装备属性计算**：需要武学数据库提供武学对角色属性的影响数据
  - **UI系统**：需要武学数据库提供武学图标、名称和描述用于显示

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的Resource系统和数据序列化功能
  - **Web平台API**：使用浏览器的内存管理和网络API进行资源加载优化

## 视觉/音频要求

- **视觉风格一致性**：所有武学图标和特效必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **武学图标设计**：每个武学应有独特的水墨风格图标，品阶通过颜色区分（COMMON-白色、RARE-蓝色、EPIC-紫色、LEGENDARY-金色）。
- **特效风格**：武学特效应体现内力与招式的视觉冲击，使用水墨晕染、粒子效果和传统纹样。
- **动画要求**：武学释放动画应体现武侠的飘逸感和力量感，符合角色门派特色。
- **音频要求**：每个武学应有独特的释放音效和命中音效，使用传统乐器音效（如古琴、笛子）营造武侠氛围。

## UI要求

- **武学列表界面**：显示所有已解锁武学，按门派、类型、品阶分类筛选
- **武学详情界面**：显示武学的完整属性、描述、图标和特效预览
- **装备界面**：允许玩家选择和装备武学到快捷栏或技能槽
- **学习界面**：显示武学解锁条件和学习进度
- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 武学品阶通过颜色区分（COMMON-白色、RARE-蓝色、EPIC-紫色、LEGENDARY-金色）
  - 确保UI在Web平台上清晰可读，适配不同屏幕尺寸
  - 提供直观的武学组合和连招提示

## 验收标准

- **GIVEN** 玩家打开武学菜单，**WHEN** 浏览已解锁武学，**THEN** 所有武学按门派、类型、品阶正确分类显示，且图标和描述符合水墨武侠风格。
- **GIVEN** 玩家选择一个武学查看详情，**WHEN** 查看武学属性，**THEN** 显示完整的战斗参数、消耗资源、冷却时间和时序控制信息。
- **GIVEN** 玩家装备一个武学到快捷栏，**WHEN** 在战斗中使用该武学，**THEN** 武学按照数据库定义的参数正确执行，包括伤害计算、资源消耗和特效播放。
- **GIVEN** 玩家尝试使用连招，**WHEN** 在取消窗口内输入下一个武学指令，**THEN** 系统正确识别连招关系并执行连招，中断前一个武学的后摇。
- **GIVEN** Web平台内存有限（<100MB），**WHEN** 玩家加载武学数据，**THEN** 系统按需加载相关武学数据，保持总内存占用低于80MB。
- **GIVEN** 武学数据文件损坏或缺失，**WHEN** 游戏启动，**THEN** 系统使用默认通用武学数据确保基本战斗功能，并记录错误日志。
- **GIVEN** 游戏运行在不同分辨率的设备上（800x600到1920x1080），**WHEN** 玩家查看武学UI，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
