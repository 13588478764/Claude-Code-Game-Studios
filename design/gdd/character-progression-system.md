## 概述

角色成长系统采用"基础等级 + 境界突破 + 天赋网格"的三维立体成长体系，模拟修真者从外到内的修炼过程。基础等级通过经验值获得属性点和天赋点，提供前期快速成长引导；境界突破分为十大境界（炼气、筑基、金丹、元婴、化神、返虚、合道、大乘、渡劫、真仙），每个境界间有瓶颈，需完成特定条件才能突破并获得质变；天赋系统包括4x4网格天赋树，无前置依赖，可免费重置，玩家可自定义被动技能和特殊能力。

玩家通过战斗历练、任务与剧情、闭关修炼、奇遇与顿悟等多种方式获得成长资源，并通过六维核心属性（力道、身法、根骨、悟性、定力、福缘）构建独特的角色Build。这种深度成长系统让玩家能够体验到"从无名小卒到一代宗师"的武侠核心幻想。

如果没有这个系统，游戏将失去角色代入感与长期目标，玩家无法体验"变强"的快感，Build策略深度大幅降低，叙事与数值脱节，经济系统崩溃。该系统是实现"深度武学系统"游戏支柱的重要基础，利用Steam平台的PC硬件优势提供可视化天赋网格、复杂数值模拟与预测、动态数据持久化和粒子音效反馈等高质量体验。

## 玩家幻想

玩家应该能够体验到"修炼内功"、"突破境界"、"点亮天赋"的武侠核心成长幻想，通过分配属性点、点亮天赋节点、经历境界突破，直接体验到角色实力的质变和身份的提升。

直接层面：玩家积极且频繁地参与角色成长系统的核心循环。这包括在升级时手动分配属性点、在4x4天赋网格中选择天赋节点、在天赋树中规划流派构建（Build），以及收集资源进行境界突破。这些是显性的策略决策和资源管理交互，直接决定了角色的发展方向。玩家应该能够清晰地看到每个属性、天赋的效果和成长路径，从而做出明智的选择。

间接层面：成长的底层逻辑（如属性对战斗公式的具体影响系数、经验值获取的后台计算、存档数据的序列化与持久化、突破时的数值校验）由系统自动处理。玩家在战斗中体验的是成长带来的结果（如更高的伤害、更厚的血量、更快的先手），而非直接操作底层的数学模型或数据库。这种无缝的体验让玩家专注于角色构建和武侠幻想，而不是技术细节。

参考游戏实现：
- 《暗黑破坏神4》的天赋树系统，通过复杂的节点连接提供深度的Build构建
- 《最终幻想14》的境界突破系统，通过完成特定条件解锁新能力和外观
- 《原神》的角色培养系统，通过属性点分配和天赋升级提供长期的游戏目标

## 详细设计


### 核心规则

1. **成长机制**（简化核心 + 奇遇补充）：
   - **基础等级**：线性升级系统，共99级，每升一级获得5点属性点和1点天赋点
   - **境界突破**：10个大境界里程碑（炼气->筑基->金丹->元婴->化神->返虚->合道->大乘->渡劫->真仙），每个里程碑解锁新功能并提供全属性+10%加成（与 src/scripts/character/character_system.gd 的 REALMS 常量对齐, 美术亦已按 10 张图标出图）
     - 炼气 (Lv 1-10)
     - 筑基 (Lv 11-20)
     - 金丹 (Lv 21-30)
     - 元婴 (Lv 31-40)
     - 化神 (Lv 41-50)
     - 返虚 (Lv 51-60)
     - 合道 (Lv 61-70)
     - 大乘 (Lv 71-80)
     - 渡劫 (Lv 81-90)
     - 真仙 (Lv 91-99)
   - **天赋网格**：4x4网格天赋系统，无前置依赖，可免费重置，某些奇遇可赠送天赋重置符或额外天赋点

2. **属性系统**（六维核心属性）：
   - **力道**（Strength, STR）：影响物理攻击力、负重上限、破防能力
     - 每点力道增加：物理攻击力+2，负重上限+5kg，破防值+1
   - **身法**（Agility, AGI）：影响闪避率、行动速度、移动速度、暴击率
     - 每点身法增加：闪避率+0.5%，行动速度+1%，移动速度+0.5%，暴击率+0.3%
   - **根骨**（Constitution, CON）：影响最大生命值、物理防御力、异常状态抗性、生命回复
     - 每点根骨增加：最大生命值+20，物理防御力+1，异常状态抗性+0.5%，生命回复+0.5/秒
   - **悟性**（Wisdom, WIS）：影响最大内力值、内力回复速度、武学熟练度获取速度、暴击伤害
     - 每点悟性增加：最大内力值+15，内力回复速度+0.3/秒，武学熟练度获取速度+1%，暴击伤害+1%
   - **定力**（Willpower, WILL）：影响架势条上限、格挡成功率、免受控制概率、精神防御
     - 每点定力增加：架势条上限+10，格挡成功率+0.5%，免受控制概率+0.5%，精神防御+1
   - **福缘**（Luck, LUK）：影响奇遇触发概率、稀有掉落率、合成成功率、暴击率
     - 每点福缘增加（100点前）：奇遇触发概率+0.3%，稀有掉落率+0.5%，合成成功率+0.5%，暴击率+0.2%
     - 每点福缘增加（100点后）：奇遇触发概率+0.1%，稀有掉落率+0.2%，合成成功率+0.2%，暴击率+0.1%
     - **软上限说明**：福缘在100点后边际收益递减，鼓励平衡Build而非极端投资

3. **寿命系统**（叙事元素）：
   - **设计定位**：寿命系统主要作为叙事元素存在，用于支持修真世界观的真实感和某些NPC的剧情设定
   - **境界与寿命对应**（仅用于叙事和NPC设定）：
     - 炼气期：120-150岁
     - 筑基期：200-300岁
     - 金丹期：500-800岁
     - 元婴期：1000-1500岁
     - 化神期：3000岁以上
   - **玩家角色**：玩家角色不受寿命限制（游戏时间不会导致角色死亡）
   - **NPC应用**：
     - 某些NPC有"寿命将尽"的状态标记（如玄机真人）
     - 在对话和剧情中体现NPC的年龄和寿命
     - 用于解释NPC的外貌年龄与实际年龄的差异
   - **UI显示**：
     - 玩家角色面板不显示寿命
     - NPC信息面板可显示"年龄"和"境界"（不显示具体寿命上限）
   - **实施优先级**：
     - MVP阶段：仅在对话文本中体现，不需要系统实现
     - 完整版本：可考虑在NPC数据中添加age字段，用于某些剧情判定

4. **成长路径**（战斗为主，奇遇为辅）：
   - **战斗历练**：击败敌人获得EXP（唯一成长货币），主线任务赠送突破丹确保境界突破无障碍
   - **奇遇系统**：随机正向反馈系统，通过地图探索、战斗后、休息/移动等时机触发
     - 高人指点：直接增加2-5点自由属性点、1-2点天赋点、武学熟练度50-100
     - 秘境发现：进入小型单次战斗副本，胜利后获得大量EXP或稀有装备
     - 天材地宝：获得突破丹或洗点丹
     - 失传秘籍：直接学会稀有武学或获得武学残页
     - 江湖传闻：获得大量银两或材料
   - **移除机制**：移除经脉系统，仅保留简单的"休息"功能（恢复生命/内力，消耗金钱）

5. **Steam平台优化**（奇遇的表现力）：
   - **动态事件卡片**：奇遇触发时弹出精美UI卡片，背景根据奇遇类型动态变化，使用AnimationPlayer制作入场动画
   - **福缘可视化**：高福缘角色在UI上显示"吉星高照"图标，暗示高概率触发好事件
   - **异步加载**：利用PC性能预加载奇遇相关资源，确保无缝切换

### 状态和转换

- **未升级状态**：角色处于当前等级，未分配属性点和天赋点
- **已升级状态**：角色已分配属性点和天赋点，属性面板更新
- **境界突破状态**：角色已完成境界突破，解锁新功能和属性加成
- **奇遇触发状态**：角色触发奇遇事件，等待玩家选择或自动执行
- **奇遇完成状态**：奇遇事件已完成，奖励已发放，状态标记已记录

状态转换流程：
- 未升级 → 已升级：获得足够EXP后升级，分配属性点和天赋点
- 已升级 → 境界突破：达到境界要求后使用突破丹进行突破
- 任意状态 → 奇遇触发：满足触发条件（地图探索、战斗后、休息/移动）且福缘判定成功
- 奇遇触发 → 奇遇完成：玩家做出选择或事件自动执行完毕，发放奖励

### 与其他系统的交互

- **战斗系统**：
  - 属性检查：战斗开始前，BattleManager读取角色属性计算最终面板数据
  - 秘境战斗：奇遇中的"秘境发现"启动独立战斗实例，胜利后直接发放奖励
- **武学系统**：
  - 属性依赖：武学伤害公式引用角色的力道、身法、悟性等属性
  - 解锁条件：角色等级达到一定级别才能装备特定品阶武学
- **装备系统**：
  - 等级限制：装备有min_level要求，角色等级不足时装备图标变灰且不可穿戴
  - 属性加成：装备属性与角色基础属性叠加，影响最终战斗表现
- **奇遇系统**：
  - 属性检查：某些奇遇选项需要特定属性达标（如力道>50才能举起巨石）
  - 福缘判定：EncounterManager读取角色LUK属性，决定触发概率和奖励档次
- **存档系统**：
  - 种子记录：记录奇遇触发的随机种子，确保可复现性
  - 状态标记：记录已触发的一次性奇遇，避免重复
- **UI系统**：提供角色面板、天赋网格、奇遇事件卡片等UI元素

## 公式

### 奇遇触发概率公式（修订版 - DT-02平衡调整）

`奇遇触发概率 = 基础概率 × (1 + 福缘加成系数)`

**福缘加成系数计算**（软上限机制）：
```
if 福缘 <= 100:
    福缘加成系数 = 福缘 / 100
else:
    福缘加成系数 = 1.0 + (福缘 - 100) / 300
```

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础概率 | base_probability | float | 0.01-0.05 | 不同奇遇类型的基础触发概率（1%-5%） |
| 福缘属性 | luck_stat | int | 0-495 | 玩家的福缘属性值 |
| 福缘加成系数 | luck_bonus_coefficient | float | 0.0-2.32 | 计算得出的福缘加成系数（100点后递减） |
| 奇遇触发概率 | encounter_probability | float | 0.01-0.20 | 最终的奇遇触发概率（上限20%, 与 encounter-system.md 对齐） |

**输出范围:** 0.01到0.20

**示例计算:**
- 福缘50点：加成系数 = 50/100 = 0.5，触发概率 = 0.03 × (1 + 0.5) = 0.045 (4.5%)
- 福缘100点：加成系数 = 100/100 = 1.0，触发概率 = 0.03 × (1 + 1.0) = 0.06 (6%)
- 福缘200点：加成系数 = 1.0 + 100/300 = 1.33，触发概率 = 0.03 × (1 + 1.33) = 0.07 (7%)
- 福缘495点：加成系数 = 1.0 + 395/300 = 2.32，触发概率 = 0.03 × (1 + 2.32) = 0.10 (10%)

**设计说明**：
- 100点前：每点福缘提供0.3%触发概率加成（线性增长）
- 100点后：每点福缘提供0.1%触发概率加成（边际收益递减）
- 这种软上限机制鼓励玩家平衡Build，避免极端投资福缘

### 属性点分配公式

`最终属性 = 基础属性 + 分配属性点 × 属性系数`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础属性 | base_attribute | int | 10-20 | 角色创建时的基础属性值 |
| 分配属性点 | allocated_points | int | 0-495 | 玩家分配到该属性的点数（99级×5点） |
| 属性系数 | attribute_coefficient | float | 1.0-2.0 | 每点属性的实际效果系数 |
| 最终属性 | final_attribute | int | 10-1010 | 角色的最终属性值 |

**输出范围:** 10到1010
**示例:** 当基础属性为15，分配属性点为100，属性系数为1.5时，最终属性 = 15 + 100 × 1.5 = 165

### 境界突破属性加成公式

`突破后属性 = 突破前属性 × (1 + 境界加成系数)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 突破前属性 | pre_breakthrough_attribute | float | 10-1010 | 突破前的角色属性值 |
| 境界加成系数 | realm_bonus_coefficient | float | 0.1-0.4 | 每个境界突破的属性加成系数（10%-40%） |
| 突破后属性 | post_breakthrough_attribute | float | 11-1414 | 突破后的角色属性值 |

**输出范围:** 11到1414
**示例:** 当突破前属性为100，境界加成系数为0.1（10%）时，突破后属性 = 100 × (1 + 0.1) = 110

## 边缘情况

- **如果奇遇触发失败**：系统将记录失败次数但不消耗任何资源，玩家可继续探索以触发新的奇遇事件。
- **如果Steam平台内存不足无法加载奇遇资源**：系统将使用默认的奇遇卡片模板，确保核心功能正常运行，但视觉效果降级。
- **如果属性点分配超出限制**：系统将阻止玩家分配超过可用点数的属性，并在UI上显示当前可用点数。
- **如果境界突破条件未满足**：系统将禁用突破按钮，并提示玩家缺少的条件（如突破丹数量不足）。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前角色状态和成长进度，等待网络恢复后同步数据。
- **如果奇遇种子重复**：系统将自动重新生成随机种子，确保每次奇遇都是独特的体验。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **奇遇系统**：需要奇遇系统提供奇遇事件数据、触发条件和奖励机制
  - **战斗系统**：需要战斗系统提供经验值获取机制和战斗结果反馈
  - **任务系统**：需要任务系统提供主线和支线任务的奖励数据

- **下游依赖**（依赖此系统的系统）：
  - **战斗系统**：依赖角色成长系统提供STR、AGI、CON、WIS、WILL、LUK等基础属性数据，用于战斗面板计算和伤害公式
  - **武学系统**：依赖角色成长系统提供角色等级和属性数据，用于武学解锁和伤害计算
  - **装备系统**：依赖角色成长系统提供角色等级数据，用于装备解锁和属性加成
  - **经验值系统**：依赖角色成长系统提供等级、境界、属性点等数据用于EXP计算和升级逻辑
  - **等级提升机制**：依赖角色成长系统提供境界状态、属性点分配等数据用于升级和突破逻辑
  - **生命值/防御系统**：依赖角色成长系统提供CON、WILL等属性数据，用于HP和Poise计算
  - **UI系统**：依赖角色成长系统提供角色面板、天赋网格、奇遇事件卡片等UI数据
  - **存档系统**：依赖角色成长系统提供角色状态和成长进度数据

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的数据序列化、动画系统和UI系统
  - **Steam平台API**：使用Steam的成就系统和云存档功能保存角色进度

## 调整参数

- **基础等级属性点**：每级5点（可调整范围：3-10点）
- **基础等级天赋点**：每级1点（可调整范围：0-2点）
- **境界突破加成系数**：10%（可调整范围：5%-20%）
- **奇遇基础触发概率**：1%-5%（可调整范围：0.5%-10%）
- **福缘概率加成**：0.1%-0.5%（可调整范围：0.05%-1.0%）
- **属性系数**：1.0-2.0（可调整范围：0.5-3.0）
- **天赋网格大小**：4x4（可调整范围：3x3-6x6）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于平衡角色成长系统和适应不同难度级别。

## 视觉/音频要求

- **视觉风格一致性**：所有角色成长界面必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **角色面板预览**：在角色面板中，使用Godot的UI系统实时显示角色属性、等级、境界状态，支持动态数字滚动效果增强成就感。
- **天赋网格可视化**：4x4天赋网格使用传统纹样边框，已点亮节点显示金色光效，未点亮节点显示灰色轮廓，鼠标悬停显示详细效果描述。
- **奇遇事件卡片**：奇遇触发时弹出精美UI卡片，背景根据奇遇类型动态变化（山洞、竹林、集市），使用AnimationPlayer制作缩放淡入动画。
- **音频要求**：
  - 升级音效：每次升级播放激昂的传统乐器音效（如古琴、笛子）
  - 境界突破音效：突破时播放特殊的成就音效和角色语音
  - 奇遇触发音效：奇遇触发时播放神秘的环境音效，营造江湖奇遇氛围
  - 背景音乐：根据当前境界和福缘状态动态调整（高境界-庄严钟声、高福缘-祥和笛声）

## UI要求

- **角色面板界面**：
  - 左侧：角色3D模型预览，支持360度旋转查看
  - 中央：属性面板，显示六维核心属性、等级、境界状态
  - 右侧：EXP进度条和境界突破按钮，显示当前EXP和突破所需条件
  - 底部：天赋网格面板，4x4网格显示已点亮和未点亮的天赋节点

- **属性分配界面**：
  - 主区域：六维属性滑块，支持拖拽分配属性点
  - 左侧：可用属性点数显示，实时更新剩余点数
  - 右侧：属性效果预览，显示当前分配对战斗面板的影响
  - 底部：重置按钮和确认按钮，支持一键重置或确认分配

- **奇遇事件界面**：
  - 主区域：动态事件卡片，背景根据奇遇类型动态变化
  - 左侧：奇遇描述文本，详细说明事件内容和选项
  - 右侧：选项按钮，显示可选择的操作（如"接受"、"拒绝"、"尝试"）
  - 底部：福缘状态显示，高福缘角色显示"吉星高照"图标

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 等级和境界通过颜色区分（普通-白色、突破-金色）
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的属性分配和天赋选择，帮助玩家做出明智的成长决策

## 验收标准

- **GIVEN** 玩家击败一个普通敌人，**WHEN** 战斗结束，**THEN** 获得基础EXP，并在UI上显示EXP增长动画。
- **GIVEN** 玩家达到99级并拥有足够属性点，**WHEN** 在属性分配界面分配5点到力道属性，**THEN** 力道属性增加25点（5×5），并在战斗面板中显示更新后的物理攻击力。
- **GIVEN** 玩家完成主线任务，**WHEN** 任务奖励发放，**THEN** 获得突破丹，并在境界突破界面显示突破按钮可用。
- **GIVEN** 玩家福缘属性为50，在地图探索时触发奇遇，**WHEN** 奇遇类型为基础概率3%的"高人指点"，**THEN** 触发概率为13%，成功触发后获得2点自由属性点。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 玩家触发奇遇事件，**THEN** 系统使用默认奇遇卡片模板，确保核心功能正常运行，但视觉效果降级。
- **GIVEN** 游戏运行在不同分辨率的设备上（1920x1080到3440x1440），**WHEN** 玩家查看角色面板，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
- **GIVEN** 玩家在天赋网格中点亮一个天赋节点，**WHEN** 查看战斗面板，**THEN** 显示该天赋提供的属性加成或特殊效果。
- **GIVEN** 玩家使用突破丹进行境界突破，**WHEN** 突破成功，**THEN** 所有属性增加10%，解锁新功能，并播放特殊的成就音效和角色语音。

## 开放问题

- **角色平衡性**：如何建立有效的角色成长平衡测试框架，确保不同属性分配和天赋选择之间的公平性？
- **动态难度调整**：如何根据玩家表现动态调整EXP获取率和奇遇触发概率？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的角色成长系统设计是否足够灵活？
- **本地化支持**：如何设计角色成长系统以支持多语言本地化，特别是属性名称、天赋描述和UI文本？
- **多人模式扩展**：虽然当前是单人游戏，但角色成长系统是否为未来的多人合作或对战模式预留了扩展接口？
