# 世界状态持久化系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-25
> **实现支柱**: 支柱1：深度武学系统

## 概述

世界状态持久化系统采用"增量式JSON存储 + Steam云同步"的混合架构，通过保存玩家核心状态、世界探索状态、任务与叙事进度、环境与实体状态四类关键数据，为玩家提供安全可靠的进度保存和跨设备游玩体验。系统利用2D俯视角的优势，实现高效的异步I/O操作、差分存储和数据压缩技术。

玩家通过自动保存、手动保存和关键事件强制保存三种方式确保游戏进度安全。系统采用结构化JSON格式存储本地文件，并通过Steam Cloud API实现云端同步，在屏幕右下角显示微小的"保存中..."图标，不打断游戏流程。这种设计既保证了数据安全性，又保持了游戏流畅性，让玩家能够真正感受到"江湖历历在目"的武侠世界观。

如果没有这个系统，游戏将失去进度安全感与世界一致性，玩家每次关闭游戏后一切归零，POI和任务状态重置导致刷钱漏洞和叙事逻辑崩坏，长时间探索进度因崩溃或未保存而丢失。该系统是实现"深度武学系统"游戏支柱的重要支撑，利用Steam平台的PC硬件优势提供异步I/O操作、差分存储/增量保存、数据压缩和Steam Cloud API集成等高质量体验。

## 玩家幻想

玩家应该能够体验到"江湖历历在目"、"事事有迹可循"的武侠核心幻想，通过世界状态持久化系统确保每次游戏进度都安全可靠，直接体验到作为江湖侠客的成长历程和世界变化的持久影响。

直接层面：玩家积极且频繁地与世界状态持久化系统交互。这包括手动保存游戏进度、在土地庙/驿站选择"休息并保存"、查看云存档同步状态。这是显性的进度管理过程，直接决定了玩家的游戏安全感和跨设备游玩体验。玩家应该能够清晰地看到每个存档槽位的状态、云同步状态和保存时间，从而做出明智的保存选择。

间接层面：世界状态持久化的底层逻辑（如异步I/O操作、差分存储、数据压缩）由系统自动处理。玩家在游戏过程中体验的是"无缝保存"和"安全进度"的结果，而非直接操作底层的文件读写或数据序列化。这种无缝的体验让玩家专注于江湖冒险和武侠幻想，而不是技术细节。

参考游戏实现：
- 《巫师3》的自动保存系统，通过关键事件触发确保重要进度不丢失
- 《塞尔达传说：旷野之息》的云存档功能，支持跨设备无缝继续游戏
- 《暗黑破坏神4》的增量保存机制，只保存变化的数据以提高效率

## 详细设计

### 核心规则

1. **持久化范围**（四类关键数据）：
   - **玩家核心状态**（Player Core State）：
     - 基础属性：等级(1-99)、境界(10个大境界)、生命值/内力当前值与最大值、经验值、银两
     - 六维属性：力道、身法、根骨、悟性、定力、福缘
     - 位置与朝向：当前所在地图ID、坐标(x, y)、面向角度
     - 背包与装备：所有物品列表、装备槽位状态、快捷栏配置
     - 武学与天赋：已学会的武学、当前装备的武学、天赋树加点情况、未使用的天赋点
   - **世界探索状态**（World Exploration State）：
     - 迷雾解锁：记录每个地图区块（Chunk）的探索状态（已探索/未探索），使用位掩码或布尔数组存储
     - 兴趣点状态：宝箱（已开启/未开启）、采集物（已采集/未采集）、传送点（已解锁/未解锁）
     - 奇遇触发记录：已触发的唯一性奇遇ID列表，防止重复触发
   - **任务与叙事进度**（Quest & Narrative Progress）：
     - 任务列表：当前激活的任务ID及其内部进度变量（如：kill_count: 5/10）
     - 已完成任务：已完成的任务ID列表
     - NPC状态：关键NPC的对话阶段、生死状态、是否被招募
   - **环境与实体状态**（Environment & Entities）：
     - 动态实体：世界中生成的临时敌人、掉落物、陷阱状态
     - 简化处理：仅保存Boss或剧情关键NPC的状态，普通怪物不保存具体位置
     - 时间/天气：当前游戏内时间、天气状态

2. **存储机制**（本地JSON + Steam Cloud）：
   - **本地存储**（Local Storage）：
     - 格式：结构化JSON文件
     - 路径：user://saves/slot_1/save_data.json
     - 加密：对JSON内容进行简单的Base64编码或XOR加密，防止玩家轻易修改存档作弊
   - **Steam云存档**（Steam Cloud Sync）：
     - 机制：利用Godot的Steamworks插件，在保存成功后自动将存档文件上传至Steam云服务器
     - 冲突处理：若检测到云端和本地版本不一致，提示玩家选择"覆盖本地"或"下载云端"

3. **保存频率**（混合模式）：
   - **自动保存**（Auto-Save）：
     - 触发条件：进入新区域、完成任务/奇遇、定期间隔（每游戏内30分钟或现实时间10分钟）
     - 表现：屏幕右下角显示微小的"保存中..."图标，不打断游戏流程
   - **手动保存**（Manual Save）：
     - 触发条件：玩家在菜单中点击"保存游戏"，或在土地庙/驿站交互时选择"休息并保存"
     - 多槽位支持：提供3-5个存档槽位，允许玩家保留多个进度点
   - **关键事件强制保存**（Checkpoint Save）：
     - 触发条件：进入Boss战前、主线剧情关键转折点后
     - 目的：防止因崩溃或意外导致长时间进度丢失

4. **Steam平台优化实现**：
   - **异步I/O操作**（Async I/O）：
     - 技术：使用Godot的FileAccess异步写入功能，或在后台线程进行JSON序列化和文件写入
     - 优势：避免在保存大量数据时造成主线程卡顿或帧率下降
   - **差分存储/增量保存**（Delta Saving）：
     - 技术：基础存档包含玩家属性和全局设置，增量数据仅保存自上次保存以来发生变化的数据
     - 优势：极大减小存档文件大小，加快读写速度
   - **数据压缩**（Compression）：
     - 技术：对JSON字符串进行GZIP或Zstandard压缩后再写入磁盘
     - 优势：进一步节省空间和I/O时间，PC CPU处理压缩解压非常快
   - **Steam Cloud API集成**：
     - 技术：调用Steam.remote_storage_file_write()和Steam.remote_storage_file_read()
     - 体验：在游戏主菜单显示"云存档同步状态"图标（绿色对勾/黄色警告）

### 状态和转换

- **未保存状态**：游戏正在进行中，尚未触发任何保存操作
- **保存中状态**：系统正在执行保存操作，显示"保存中..."图标
- **已保存状态**：本地存档已成功写入，等待云同步
- **云同步中状态**：本地存档正在上传至Steam云服务器
- **云同步完成状态**：本地和云端存档都已成功保存，显示绿色对勾图标
- **云冲突状态**：检测到本地和云端存档版本不一致，需要玩家手动解决

状态转换流程：
- 未保存 → 保存中：触发自动保存、手动保存或关键事件强制保存
- 保存中 → 已保存：本地存档写入成功
- 已保存 → 云同步中：开始上传至Steam云服务器
- 云同步中 → 云同步完成：云端存档上传成功
- 云同步中 → 云冲突：检测到版本不一致，暂停同步等待玩家选择

## 公式

### 存档文件大小估算公式

`存档大小 = 基础大小 + (探索区块数 × 区块大小) + (任务数量 × 任务大小)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础大小 | base_size | int | 1000-5000 | 玩家核心状态的基础字节数 |
| 探索区块数 | explored_chunks | int | 0-1000 | 已探索的地图区块数量 |
| 区块大小 | chunk_size | int | 10-50 | 每个区块的平均字节数 |
| 任务数量 | quest_count | int | 0-200 | 当前激活和已完成的任务数量 |
| 任务大小 | quest_size | int | 50-200 | 每个任务的平均字节数 |
| 存档大小 | save_size | int | 1000-100000 | 最终的存档文件大小（字节） |

**输出范围:** 1000到100000字节（1KB到100KB）
**示例:** 当基础大小为2000，探索区块数为100，区块大小为20，任务数量为50，任务大小为100时，存档大小 = 2000 + (100 × 20) + (50 × 100) = 2000 + 2000 + 5000 = 9000字节

### 自动保存间隔公式

`自动保存间隔 = min(游戏内时间间隔, 现实时间间隔)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 游戏内时间间隔 | game_time_interval | int | 10-60 | 游戏内分钟数（触发保存） |
| 现实时间间隔 | real_time_interval | int | 5-30 | 现实世界分钟数（触发保存） |
| 自动保存间隔 | auto_save_interval | int | 5-60 | 实际的自动保存间隔（分钟） |

**输出范围:** 5到60分钟
**示例:** 当游戏内时间间隔为30分钟，现实时间间隔为10分钟时，自动保存间隔 = min(30, 10) = 10分钟

### 云同步冲突检测公式

`冲突检测 = (本地版本号 ≠ 云端版本号) AND (本地修改时间 > 云端修改时间)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 本地版本号 | local_version | string | - | 本地存档的版本标识符 |
| 云端版本号 | cloud_version | string | - | 云端存档的版本标识符 |
| 本地修改时间 | local_modified | timestamp | - | 本地存档的最后修改时间戳 |
| 云端修改时间 | cloud_modified | timestamp | - | 云端存档的最后修改时间戳 |
| 冲突检测 | conflict_detected | boolean | true/false | 是否检测到版本冲突 |

**输出范围:** true或false
**示例:** 当本地版本号为"v1.2.3"，云端版本号为"v1.2.2"，本地修改时间为2026-04-25T13:30:00，云端修改时间为2026-04-25T13:25:00时，冲突检测 = (v1.2.3 ≠ v1.2.2) AND (13:30:00 > 13:25:00) = true AND true = true

## 边缘情况

- **如果Steam平台存储空间不足**：系统将显示错误提示"云存档空间不足，无法同步"，建议玩家清理其他游戏的云存档或使用本地保存。
- **如果网络连接中断**：系统将保存本地存档，等待网络恢复后自动重试云同步，最多重试3次。
- **如果存档文件损坏**：系统将检测JSON格式有效性，如果损坏则尝试从备份文件恢复（保留最近3个备份），如果仍失败则显示"存档损坏，无法加载"。
- **如果玩家在保存过程中强制关闭游戏**：系统将保留上次完整保存的状态，增量数据可能丢失但不会导致存档完全损坏。
- **如果多个设备同时修改存档**：系统将检测到云冲突，暂停自动同步并提示玩家手动选择"覆盖本地"或"下载云端"。
- **如果存档文件过大**（>10MB）：系统将实施数据压缩和差分存储优化，如果仍超过限制则显示"存档过大，已启用精简模式"并移除非关键数据。

## 验收标准

- **GIVEN** 玩家进入新区域，**WHEN** 触发自动保存，**THEN** 系统在屏幕右下角显示"保存中..."图标，本地存档成功写入，并开始云同步。
- **GIVEN** Steam平台网络连接中断，**WHEN** 玩家手动保存游戏，**THEN** 系统保存本地存档，等待网络恢复后自动重试云同步最多3次。
- **GIVEN** 游戏运行在不同分辨率的设备上（800x600到3440x1440），**WHEN** 玩家查看存档选择界面，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
- **GIVEN** 多个设备同时修改存档，**WHEN** 检测到云冲突，**THEN** 系统暂停自动同步并提示玩家手动选择"覆盖本地"或"下载云端"。
- **GIVEN** 存档文件损坏，**WHEN** 玩家尝试加载游戏，**THEN** 系统检测JSON格式有效性，尝试从最近3个备份文件恢复，如果仍失败则显示"存档损坏，无法加载"。
- **GIVEN** 玩家在土地庙选择"休息并保存"，**WHEN** 确认保存，**THEN** 系统创建新的存档槽位，显示保存时间、玩家等级和位置信息，并播放古琴音效。
- **GIVEN** 存档文件大小超过10MB，**WHEN** 系统执行保存操作，**THEN** 实施数据压缩和差分存储优化，如果仍超过限制则显示"存档过大，已启用精简模式"并移除非关键数据。
- **GIVEN** 玩家强制关闭游戏，**WHEN** 重新启动游戏，**THEN** 系统加载上次完整保存的状态，确保核心进度不丢失。
