# 奇遇系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-25
> **实现支柱**: 支柱1：深度武学系统

## 概述

奇遇系统采用"概率池 + 权重修正"的轻量级触发模型，通过标准化的5种核心模板（高人指点、天材地宝、失传秘籍、秘境挑战、江湖传闻）为玩家提供随机正向反馈。奇遇通过地图探索、战斗后、休息/移动等时机触发，受福缘属性影响，福缘越高触发概率和奖励质量越高。

玩家通过探索世界、积累福缘，直接体验到"偶遇高人"、"洞中得宝"、"绝处逢生"的武侠核心幻想。所有奇遇均为正向增益，无负面效果，并采用一次性标记避免重复刷取破坏平衡。秘境挑战的敌人等级随玩家当前等级动态调整，确保始终具有挑战性但不过分困难。

如果没有这个系统，游戏将失去江湖的"灵魂"与惊喜感，世界变成单纯的"打怪-升级-换地图"循环，福缘属性沦为鸡肋，叙事缺乏传奇色彩，重玩价值大幅降低。该系统是实现"深度武学系统"游戏支柱的重要补充，利用Steam平台的PC硬件优势提供数据驱动配置、动态UI卡片、随机数种子管理和小型场景实例化等高质量体验。

## 玩家幻想

玩家应该能够体验到"偶遇高人"、"洞中得宝"、"绝处逢生"的武侠核心幻想，通过探索世界、积累福缘，直接体验到作为主角被命运眷顾的快感。

直接层面：玩家通过阅读奇遇文本、做出选择（如是否接受高人指点、是否开启宝箱）、观看奖励动画，直接参与并感受系统的反馈。这是显性的叙事互动和资源获取过程，直接影响玩家的决策和情绪体验（惊喜感）。玩家应该能够清晰地看到每个奇遇的类型、触发条件、可能的奖励和交互选项，从而做出明智的选择。

间接层面：奇遇的底层逻辑（如基于福缘的概率加权算法、随机数种子生成、事件去重状态管理、奖励物品的实例化与发放）由系统自动处理。玩家在后台不可见这些计算过程，只体验到最终的结果（触发了什么事件、获得了什么奖励）。这种无缝的体验让玩家专注于江湖探索和武侠幻想，而不是技术细节。

参考游戏实现：
- 《暗黑破坏神4》的随机事件系统，通过丰富的事件类型提供探索乐趣
- 《最终幻想14》的危命任务系统，通过随机触发提供额外奖励和叙事
- 《原神》的世界任务系统，通过探索触发隐藏剧情和奖励

## 详细设计

### 核心规则

1. **奇遇类型和触发机制**（概率池 + 场景权重）：
   - **基础触发时机与概率**：
     - 大地图移动：每次节点间移动，基础概率5%
     - 战斗胜利后：每次战斗结束，基础概率2%
     - 休息/存档：每次操作，基础概率3%
     - 特定地点：标记为"灵气浓郁"或"古迹"的地图节点，基础概率10%-15%，且必定触发特定类型
   - **类型分布权重**：
     - 江湖传闻：权重40（最常见，低价值）
     - 天材地宝：权重30（中等价值）
     - 高人指点：权重15（高价值，成长资源）
     - 失传秘籍：权重10（高价值，武学资源）
     - 秘境挑战：权重5（最高价值，战斗+装备）
   - **去重机制**：
     - 一次性奇遇：每个具体奇遇ID在同一周目内仅触发一次
     - 通用奇遇：设有内部冷却时间（同一大地图区域内，每5次移动最多触发1次）

2. **福缘属性影响**（概率修正 + 质量偏移）：
   - **触发概率修正公式**：`最终触发概率 = 基础概率 × (1 + 福缘/100)`
     - 单次触发概率上限20%，防止过于频繁打断节奏
   - **奖励质量/类型偏移**：
     - 高福缘降低"江湖传闻"权重，增加"高人指点"和"秘境挑战"权重
     - 权重重分配公式：高阶权重 = 基础权重 × (1 + 福缘/50)，低阶权重 = 基础权重 / (1 + 福缘/50)
   - **保底机制**：连续20次未触发奇遇后，下一次强制触发并重置计数器

3. **奇遇内容和奖励**（正向增益，无负面效果）：
   - **江湖传闻**：银两(200-500)、普通材料(5-10)，纯文本无交互
   - **天材地宝**：突破丹(1)、洗点丹(1)、稀有材料(3-5)，高福缘可能触发双倍奖励
   - **高人指点**：自由属性点(2-5)、天赋点(1-2)、武学熟练度(50-100)
   - **失传秘籍**：武学残页(1)、完整武学(低阶)、经验值(500-1000)
   - **秘境挑战**：进入单次战斗（敌人等级=玩家等级+2），胜利后获得紫色装备、大量EXP(1000-2000)、传说碎片(5%概率)

4. **Steam平台优化实现**：
   - **数据驱动配置**：所有奇遇数据存储在res://data/encounters.json，启动时一次性加载到内存字典
   - **UI预加载与对象池**：奇遇弹窗在游戏启动时实例化单例，触发时只需更新内容并播放入场动画
   - **图片缓存**：所有奇遇背景图使用Texture2D预加载，避免切换时闪烁
   - **异步战斗加载**：秘境挑战触发时，后台线程预加载战斗场景，前台显示过渡动画掩盖加载过程

### 状态和转换

- **未触发状态**：奇遇尚未被触发，处于概率池中等待判定
- **触发判定状态**：系统根据触发时机和福缘属性进行概率判定
- **奇遇显示状态**：奇遇事件卡片弹出，等待玩家阅读和选择
- **奇遇执行状态**：玩家做出选择后，系统执行相应的奖励发放或战斗启动
- **完成状态**：奇遇已完成，记录到已完成列表，避免重复触发

状态转换流程：
- 未触发 → 触发判定：满足触发时机（移动、战斗、休息）且达到基础概率
- 触发判定 → 奇遇显示：概率判定成功，随机选择奇遇类型并显示事件卡片
- 奇遇显示 → 奇遇执行：玩家做出选择或自动执行（如江湖传闻）
- 奇遇执行 → 完成：奖励发放完毕或战斗结束，标记为已完成
- 任意状态 → 保底触发：连续20次未触发后强制进入触发判定状态

### 与其他系统的交互

- **角色成长系统**：
  - 属性检查：EncounterManager读取玩家LUK计算触发概率
  - 奖励发放：直接调用CharacterStats.add_stat_points()或LevelingSystem.add_exp()
  - 境界限制：高阶奇遇设置min_realm条件，未达标者替换为低阶版本
- **战斗系统**：
  - 秘境入口：触发秘境时，EncounterManager调用BattleManager.start_quick_battle(enemy_template_id)
  - 结果回调：战斗结束后，BattleManager返回状态，胜利则发放奖励，失败则结束奇遇
- **武学系统**：
  - 秘籍处理：奖励武学时，调用MartialArtsManager.learn_art(art_id)
  - 冲突处理：已学会武学自动转化为熟练度或银两，避免奖励浪费
- **存档系统**：
  - 状态持久化：存档记录completed_encounter_ids和consecutive_failures
  - 加载恢复：读档时恢复状态，确保奇遇不会重复触发或保底计数丢失
- **UI系统**：提供奇遇事件卡片、动态背景、交互按钮等UI元素

## 公式

### 奇遇触发概率公式

`最终触发概率 = 基础概率 × (1 + 福缘/100)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础概率 | base_chance | float | 0.02-0.15 | 不同触发时机的基础概率（2%-15%） |
| 福缘 | luck | int | 0-100 | 玩家的福缘属性值 |
| 最终触发概率 | final_trigger_chance | float | 0.02-0.20 | 最终的奇遇触发概率（上限20%） |

**输出范围:** 0.02到0.20
**示例:** 当基础概率为0.05（5%），福缘为50时，最终触发概率 = 0.05 × (1 + 50/100) = 0.05 × 1.5 = 0.075（7.5%）

### 权重重分配公式

`高阶权重 = 基础权重 × (1 + 福缘/50)`
`低阶权重 = 基础权重 / (1 + 福缘/50)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础权重 | base_weight | int | 5-40 | 奇遇类型的原始权重 |
| 福缘 | luck | int | 0-100 | 玩家的福缘属性值 |
| 高阶权重 | high_tier_weight | float | 5-60 | 高价值奇遇的调整后权重 |
| 低阶权重 | low_tier_weight | float | 13-40 | 低价值奇遇的调整后权重 |

**输出范围:** 高阶权重5-60，低阶权重13-40
**示例:** 当基础权重为5（秘境挑战），福缘为100时，高阶权重 = 5 × (1 + 100/50) = 5 × 3 = 15；当基础权重为40（江湖传闻），福缘为100时，低阶权重 = 40 / (1 + 100/50) = 40 / 3 ≈ 13.33

## 边缘情况

- **如果奇遇触发时玩家背包已满**：系统将自动将可堆叠物品（如银两、材料）直接加入背包，不可堆叠物品（如装备、武学）转换为等值的银两或EXP。
- **如果Steam平台内存不足无法加载奇遇背景图**：系统将使用默认的水墨风格背景模板，确保核心功能正常运行，但视觉效果降级。
- **如果福缘属性超出范围**：系统将限制福缘属性在0-100范围内，超出部分不计入概率计算。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前奇遇状态和奖励，等待网络恢复后同步数据。
- **如果奇遇JSON配置文件损坏**：系统将跳过损坏的奇遇条目，记录错误日志，并继续使用其他有效奇遇。
- **如果秘境挑战战斗场景加载失败**：系统将取消秘境挑战，转换为等值的天材地宝奖励，避免玩家卡在无法完成的奇遇中。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **角色成长系统**：需要角色成长系统提供福缘属性、等级、境界等数据用于触发判定和奖励计算
  - **战斗系统**：需要战斗系统提供战斗结束事件和敌人模板用于秘境挑战
  - **武学系统**：需要武学系统提供武学数据用于失传秘籍奖励
  - **物品数据库**：需要物品数据库提供银两、材料、丹药等物品数据

- **下游依赖**（依赖此系统的系统）：
  - **角色成长系统**：依赖奇遇系统提供额外的属性点、天赋点、EXP等成长资源
  - **武学系统**：依赖奇遇系统提供武学残页和完整武学作为奖励
  - **装备系统**：依赖奇遇系统提供稀有装备和材料作为奖励
  - **UI系统**：依赖奇遇系统提供奇遇事件卡片、动态背景、交互按钮等UI数据
  - **存档系统**：依赖奇遇系统提供已完成奇遇ID列表和连续失败计数器

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的数据序列化、UI系统和场景管理功能
  - **Steam平台API**：使用Steam的云存档功能保存奇遇状态和进度

## 调整参数

- **基础触发概率**：大地图移动5%、战斗胜利后2%、休息/存档3%、特定地点10%-15%（可调整范围：各概率±50%）
- **类型分布权重**：江湖传闻40、天材地宝30、高人指点15、失传秘籍10、秘境挑战5（可调整范围：总权重和保持100，各类型权重可重新分配）
- **福缘影响系数**：概率修正系数1.0、权重重分配系数0.5（可调整范围：0.1-2.0）
- **触发概率上限**：20%（可调整范围：10%-50%）
- **保底触发次数**：20次（可调整范围：10-50次）
- **秘境挑战敌人等级偏移**：+2级（可调整范围：0-5级）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于平衡奇遇系统和适应不同难度级别。

## 视觉/音频要求

- **视觉风格一致性**：所有奇遇界面必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **奇遇事件卡片**：使用Godot的UI系统实时显示奇遇类型、描述文本、选项按钮，支持动态背景切换和入场动画。
- **类型差异化表现**：
  - 江湖传闻：淡雅水墨风格，轻柔淡入动画
  - 天材地宝：金色光效边框，宝箱开启音效配合
  - 高人指点：古朴卷轴样式，毛笔书写动画
  - 失传秘籍：残破古籍效果，纸张翻页动画
  - 秘境挑战：红色警示边框，火焰粒子特效
- **音频要求**：
  - 奇遇触发音效：根据奇遇类型播放不同的环境音效（江湖传闻-市井嘈杂、天材地宝-宝物光芒、高人指点-古琴悠扬、失传秘籍-风声呼啸、秘境挑战-战鼓雷鸣）
  - 背景音乐：奇遇触发时暂停当前BGM，播放短暂的奇遇专属音乐片段（2-3秒），然后淡入回原BGM
  - 语音提示：高价值奇遇（高人指点、秘境挑战）触发时播放角色惊叹语音

## UI要求

- **奇遇事件卡片界面**：
  - 主区域：动态背景图，根据奇遇类型显示不同风格（水墨、金色、古朴、残破、红色）
  - 左侧：奇遇标题和描述文本，使用传统书法字体
  - 右侧：交互选项按钮，显示可选择的操作（如"接受"、"拒绝"、"开启"、"阅读"）
  - 底部：福缘状态显示，高福缘角色显示"吉星高照"图标

- **奖励预览界面**：
  - 主区域：奖励物品图标网格，显示所有将获得的奖励
  - 左侧：奖励数量显示，支持动态数字滚动效果
  - 右侧：奖励类型标签，使用不同颜色区分（银两-黄色、材料-绿色、装备-紫色、武学-橙色）
  - 底部：确认按钮，点击后发放奖励并关闭界面

- **秘境挑战界面**：
  - 主区域：敌人预览模型，显示即将面对的敌人3D模型
  - 左侧：敌人等级和属性面板，显示敌人的详细信息
  - 右侧：战斗准备按钮，显示"进入战斗"和"放弃挑战"选项
  - 底部：玩家状态显示，显示当前角色的等级和主要属性

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - 奇遇类型通过颜色和特效区分（江湖传闻-淡雅、天材地宝-金色、高人指点-古朴、失传秘籍-残破、秘境挑战-红色）
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的奖励预览和交互选项，帮助玩家做出明智的选择

## 验收标准

- **GIVEN** 玩家福缘属性为50，在大地图移动时触发奇遇，**WHEN** 基础触发概率为5%，**THEN** 最终触发概率为7.5%，成功触发后根据权重分配显示相应类型的奇遇事件卡片。
- **GIVEN** 玩家连续20次未触发奇遇，**WHEN** 进行第21次大地图移动，**THEN** 系统强制触发奇遇，重置连续失败计数器，并显示奇遇事件卡片。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 玩家触发奇遇事件，**THEN** 系统使用默认水墨风格背景模板，确保核心功能正常运行，但视觉效果降级。
- **GIVEN** 游戏运行在不同分辨率的设备上（1920x1080到3440x1440），**WHEN** 玩家查看奇遇事件卡片，**THEN** UI元素正确适配屏幕尺寸，保持清晰可读。
- **GIVEN** 玩家触发秘境挑战奇遇，**WHEN** 敌人等级设置为玩家等级+2，**THEN** 战斗场景正确加载，敌人属性面板显示正确的等级和属性信息。
- **GIVEN** 玩家背包已满时触发天材地宝奇遇，**WHEN** 奖励包含不可堆叠物品（如装备），**THEN** 系统将不可堆叠物品转换为等值的银两或EXP，可堆叠物品直接加入背包。
- **GIVEN** 玩家高福缘（LUK=100）触发奇遇，**WHEN** 权重重分配计算完成，**THEN** "秘境挑战"权重从5提升至15，"江湖传闻"权重从40降至13，玩家更容易遇到高回报事件。
- **GIVEN** 奇遇JSON配置文件损坏，**WHEN** 游戏启动加载奇遇数据，**THEN** 系统跳过损坏条目，记录错误日志，并继续使用其他有效奇遇，不影响游戏正常运行。

## 开放问题

- **奇遇平衡性**：如何建立有效的奇遇平衡测试框架，确保不同福缘属性和触发时机下的奇遇体验公平性？
- **动态难度调整**：如何根据玩家表现动态调整奇遇触发概率和奖励质量？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的奇遇系统设计是否足够灵活？
- **本地化支持**：如何设计奇遇系统以支持多语言本地化，特别是奇遇文本、描述和UI文本？
- **多人模式扩展**：虽然当前是单人游戏，但奇遇系统是否为未来的多人合作或对战模式预留了扩展接口？
