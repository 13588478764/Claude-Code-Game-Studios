# 敌人AI系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-25
> **实现支柱**: 支柱1：深度武学系统

## 概述

敌人AI系统采用"优先级评分表(Priority Scoring/Utility AI Lite)"机制，通过战术意识行为（基础攻击、弱点利用、状态管理、生存本能、连携配合）为玩家提供智能且具有挑战性的对手。系统利用2D俯视角的优势，实现清晰的AI决策逻辑和直观的战斗反馈，既保证了策略深度，又避免了过于复杂的交互门槛。

敌人通过"评估战场->选择最优策略->执行战术动作"的决策循环体验武侠高手对决的核心乐趣。系统支持简单（随机选择）、普通（基本策略）、困难（高级策略、预测玩家行为）三种难度等级，确保不同水平的玩家都能获得合适的挑战。所有AI决策通过动态UI展示，普通攻击使用固定侧视角，强力技能触发特写镜头，特殊战术动作呈现特殊特效。

如果没有这个系统，游戏将失去战斗挑战与沉浸感，变成单纯的数值比拼，缺乏策略互动，严重破坏世界观沉浸感，使玩家精心搭配的Build毫无意义，导致重复枯燥的战斗体验。该系统是实现"深度武学系统"游戏支柱的重要支撑，利用Steam平台的PC硬件优势提供高效的AI决策计算、动态UI展示和实时战斗反馈。

## 玩家幻想

玩家应该能够体验到"见招拆招"、"以智取胜"、"高手对决"的武侠核心幻想，通过观察敌人AI的行为模式和战术选择直接体验到作为武林高手的快感与成就感。

直接层面：玩家在战斗中积极应对敌人AI的各种战术行为，包括弱点利用、状态管理、连携配合等。这是显性的策略决策过程，直接决定了战斗的胜负和效率。玩家应该能够清晰地看到每个敌人的战术意图、技能选择和行为模式，从而做出明智的反制策略。

间接层面：敌人AI的底层逻辑（如优先级评分、难度调整、决策机制）由系统自动处理。玩家在后台不可见这些计算过程，只体验到最终的结果（敌人选择的技能、目标、战术行为）。这种无缝的体验让玩家专注于策略思考和武侠对决，而不是复杂的AI算法。

参考游戏实现：
- 《最终幻想7重制版》的AI系统，通过智能的敌人行为和战术选择提供深度战斗体验
- 《女神异闻录5》的敌人AI，通过弱点利用和状态管理提供策略挑战
- 《暗黑破坏神4》的敌人AI系统，通过不同难度等级和行为模式提供适应性挑战

## 详细设计

### 核心规则

1. **AI行为类型**（战术意识行为）：
   - **基础攻击**（Basic Attack）：
     - 当无特殊策略可用时，选择伤害期望值最高的单体目标进行普通攻击或低耗技能攻击
   - **弱点利用**（Weakness Exploitation）：
     - 破防优先：若玩家处于Break(破防)状态，AI优先使用高伤害技能进行终结
     - 属性克制：AI倾向于使用克制玩家当前抗性最低属性的武学（如：对低火抗玩家使用火焰掌）
   - **状态管理**（Status Management）：
     - 施加Debuff：若玩家血量健康，AI优先施加Poison、Burn或Weaken，为后续爆发做铺垫
     - 解除Buff：若玩家拥有强力Shield或Regen，AI优先使用驱散技能或高爆发技能打破护盾
     - 控制链：若队友已施加Stun，AI跟进高伤技能；若玩家即将行动，AI尝试施加Stun或Silence打断节奏
   - **生存本能**（Survival Instinct）：
     - 撤退/防御：当自身HP < 30%且无治疗手段时，选择"防御"以恢复架势并减伤，或使用轻功后撤（若地图允许）
     - 集火威胁：优先攻击对其造成最高伤害或拥有最高暴击率的玩家角色（仇恨值逻辑简化版）
   - **连携配合**（Coordination）：
     - 组合技触发：若队友已施加Wet(湿润)，AI优先使用Lightning(雷系)技能触发感电
     - 保护盟友：若盟友处于危急状态，AI可能选择嘲讽或替身技能（若具备）

2. **AI难度等级**（三种难度实现）：
   - **简单**（Easy - "莽夫"）：
     - 策略：70%概率随机选择可用技能，30%概率选择最高伤害技能
     - 缺陷：无视弱点、无视状态、不保留内力、不集火
     - 目的：让玩家体验割草快感，熟悉操作
   - **普通**（Normal - "武者"）：
     - 策略：基于优先级评分表做出合理选择
     - 行为：会利用弱点，会优先攻击残血，会合理使用防御指令恢复架势
     - 目的：标准挑战，要求玩家认真搭配武学和策略
   - **困难**（Hard - "宗师"）：
     - 策略：在普通基础上，增加预测性和资源管理
     - 行为：
       - 预判打断：若检测到玩家下回合将释放强力大招（通过UI提示或蓄力状态），优先使用控制技能打断
       - 内力保留：不会一次性耗尽内力，保留足够内力用于应对突发状况或连携
       - 完美格挡模拟：在特定高伤技能面前，有更高概率选择防御或闪避类技能
     - 目的：为硬核玩家提供高压力的博弈体验

3. **AI决策机制**（优先级评分表）：
   - **工作流程**：
     - 生成候选动作：遍历敌人所有可用技能（包括普攻、防御、道具）
     - 评分计算(Scoring)：对每个动作针对每个潜在目标计算得分
       - Score = Base_Score + Modifiers
       - Base_Score：技能的预期伤害或治疗效果
       - Modifiers：
         - Is_Weakness: +50分（克制属性）
         - Target_Is_Broken: +100分（目标破防）
         - Target_HP_Low: +30分（目标残血）
         - Self_HP_Low: 防御技能+40分
         - Combo_Potential: +20分（能触发连携）
         - Cost_Efficiency: 扣分项（内力消耗过高且非关键时刻）
     - 选择最佳：选择总分最高的(Skill, Target)组合
     - 执行：调用战斗系统执行该指令
   - **优势**：
     - 易配置：策划只需调整JSON中的权重系数即可改变AI风格
     - 可预测：开发者可以打印出每个动作的得分，轻松调试AI为何做出"愚蠢"决定
     - 高性能：计算量极小，适合移动端或低配PC

4. **Steam平台优化实现**：
   - **高效AI计算**：使用预计算缓存避免重复评分计算，多线程后台处理复杂决策
   - **动态UI展示**：实时显示AI决策过程和战术意图，不同颜色代表不同行为类型
   - **实时战斗反馈**：当AI做出特殊战术决策时，播放对应的粒子特效和音效
   - **音频沉浸感**：不同AI行为播放不同的音效（攻击-战斗声、防御-格挡声、连携-配合声）

### 状态和转换

- **无决策状态**（No Decision）：战斗尚未开始，AI未激活
- **战场评估状态**（Battlefield Assessment）：AI获取当前战场快照（所有单位HP、状态、位置）
- **动作生成状态**（Action Generation）：遍历所有可用技能，生成候选动作列表
- **评分计算状态**（Scoring Calculation）：对每个候选动作计算优先级分数
- **难度调整状态**（Difficulty Adjustment）：根据当前难度等级调整最终决策（随机性、预测性等）
- **决策执行状态**（Decision Execution）：选择最佳动作并调用战斗系统执行
- **等待状态**（Waiting）：AI完成决策，等待下一轮行动时机

状态转换流程：
- 无决策 → 战场评估：战斗开始，AI激活
- 战场评估 → 动作生成：获取完整战场信息后，生成候选动作
- 动作生成 → 评分计算：生成所有候选动作后，开始评分计算
- 评分计算 → 难度调整：完成评分后，根据难度等级调整决策
- 难度调整 → 决策执行：确定最终决策后，执行选定动作
- 决策执行 → 等待：执行完成后，等待下一轮行动时机
- 等待 → 战场评估：轮到AI行动时，重新评估战场状态

### 与其他系统的交互

- **战斗系统**（CombatSystem）：
  - 数据输入：接收AI决策结果（技能、目标、战术意图）
  - 功能输出：提供战场快照数据（所有单位状态、HP、位置等）
- **状态效果系统**（StatusEffectSystem）：
  - 数据输入：查询目标状态效果（Buff/Debuff、控制状态等）
  - 功能输出：提供状态感知数据用于AI评分（如：目标有Shield则降低普通攻击得分）
- **命中检测系统**（HitDetectionSystem）：
  - 数据输入：查询技能命中率预测数据
  - 功能输出：提供命中预判数据用于AI决策（如：命中率低于50%则大幅降低评分）
- **武学系统**（MartialArtsSystem）：
  - 数据输入：查询可用武学技能数据（伤害、消耗、标签、属性等）
  - 功能输出：提供技能数据库用于AI动作生成
- **UI系统**（UISystem）：
  - 数据输入：接收AI决策数据（选择的技能、目标、得分理由）
  - 功能输出：渲染AI决策UI、战术意图提示、开发者调试信息

## 公式

### AI决策评分公式

`最终评分 = 基础评分 + 弱点修正 + 破防修正 + 残血修正 + 自身状态修正 + 连携修正 - 消耗效率修正`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础评分 | base_score | int | 0-1000 | 技能的预期伤害或治疗效果基础分 |
| 弱点修正 | weakness_bonus | int | 0-50 | 克制属性修正（克制=+50，无关系=0） |
| 破防修正 | broken_bonus | int | 0-100 | 目标破防修正（破防=+100，正常=0） |
| 残血修正 | low_hp_bonus | int | 0-30 | 目标残血修正（HP<30%=+30，否则=0） |
| 自身状态修正 | self_state_bonus | int | -40-40 | 自身状态修正（HP<30%且防御技能=+40，其他情况=0） |
| 连携修正 | combo_bonus | int | 0-20 | 连携潜力修正（能触发连携=+20，否则=0） |
| 消耗效率修正 | cost_penalty | int | 0-50 | 内力消耗过高修正（非关键时刻高消耗=-50，否则=0） |
| 最终评分 | final_score | int | -50-1200 | 最终的动作评分 |

**输出范围:** -50到1200
**示例:** 当基础评分为200，弱点修正为50，破防修正为100，残血修正为30，自身状态修正为0，连携修正为20，消耗效率修正为0时，最终评分 = 200 + 50 + 100 + 30 + 0 + 20 - 0 = 400

### 难度调整公式

`调整后评分 = 最终评分 × 难度系数 + 随机扰动`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 最终评分 | final_score | int | -50-1200 | 原始动作评分 |
| 难度系数 | difficulty_factor | float | 0.5-1.2 | 难度调整系数（简单=0.5，普通=1.0，困难=1.2） |
| 随机扰动 | random_noise | int | -100-100 | 随机扰动值（简单=±100，普通=±20，困难=±5） |
| 调整后评分 | adjusted_score | float | -155-1540 | 调整后的最终评分 |

**输出范围:** -155到1540
**示例:** 当最终评分为400，难度系数为1.0（普通），随机扰动为15时，调整后评分 = 400 × 1.0 + 15 = 415

### 预测性打断公式（困难难度）

`打断优先级 = 控制技能基础分 + 大招威胁度 × 威胁系数`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 控制技能基础分 | control_base | int | 100-300 | 控制技能的基础评分 |
| 大招威胁度 | ult_threat | int | 0-500 | 玩家大招的威胁程度（基于伤害、范围、效果） |
| 威胁系数 | threat_factor | float | 0.1-0.3 | 威胁转换系数 |
| 打断优先级 | interrupt_priority | int | 100-450 | 打断动作的最终优先级 |

**输出范围:** 100到450
**示例:** 当控制技能基础分为200，大招威胁度为300，威胁系数为0.2时，打断优先级 = 200 + 300 × 0.2 = 260

## 边缘情况

- **如果Steam平台内存不足无法加载AI系统数据**：系统将使用默认的通用AI配置，确保核心战斗功能正常运行。
- **如果网络连接中断**（单机模式不影响）：在未来的多人模式中，系统将保存当前战斗状态，等待网络恢复后同步数据。
- **如果AI评分计算结果溢出**：系统将自动限制最终评分在-50到1200范围内，防止数值溢出导致游戏崩溃。
- **如果难度调整参数异常**：系统将自动限制难度系数在0.5-1.2范围内，防止异常数据影响平衡。
- **如果预测性打断逻辑失效**：系统将回退到普通难度的AI决策机制，确保敌人仍能正常行动。
- **如果连携配合条件冲突**：系统将根据预定义的优先级处理（如：保护盟友 > 组合技触发），确保AI逻辑一致性。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **战斗系统**：需要战斗系统提供战场快照数据（所有单位状态、HP、位置等）
  - **状态效果系统**：需要状态效果系统提供目标状态效果数据（Buff/Debuff、控制状态等）
  - **命中检测系统**：需要命中检测系统提供技能命中率预测数据
  - **武学系统**：需要武学系统提供可用武学技能数据（伤害、消耗、标签、属性等）

- **下游依赖**（依赖此系统的系统）：
  - **战斗系统**：依赖敌人AI系统提供AI决策结果（技能、目标、战术意图）
  - **UI系统**：依赖敌人AI系统提供AI决策数据（选择的技能、目标、得分理由）

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的状态机、评分系统、AI控制器和UI系统功能
  - **Steam平台API**：使用Steam的性能监控功能优化AI决策计算效率

## 调整参数

- **基础评分范围**：0-1000（可调整范围：0-2000）
- **弱点修正范围**：0-50（可调整范围：0-100）
- **破防修正范围**：0-100（可调整范围：0-200）
- **残血修正范围**：0-30（可调整范围：0-50）
- **自身状态修正范围**：-40-40（可调整范围：-100-100）
- **连携修正范围**：0-20（可调整范围：0-50）
- **消耗效率修正范围**：0-50（可调整范围：0-100）
- **难度系数范围**：0.5-1.2（可调整范围：0.1-2.0）
- **随机扰动范围**：简单=±100，普通=±20，困难=±5（可调整范围：±5-±200）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于平衡敌人AI系统和适应不同难度级别。

## 视觉/音频要求

- **视觉风格一致性**：所有AI相关UI元素必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **AI决策显示**：不同颜色代表不同行为类型（红色=攻击、蓝色=防御、黄色=连携、紫色=状态管理）
- **特效表现**：
  - 攻击意图：敌人头顶显示红色剑形图标，表示即将发动攻击
  - 防御意图：敌人头顶显示蓝色盾形图标，表示即将使用防御
  - 连携意图：敌人头顶显示黄色连线图标，表示即将与队友配合
  - 状态意图：敌人头顶显示紫色药瓶图标，表示即将施加状态效果
- **UI动效**：
  - AI决策预览：在敌人行动前1秒显示其选择的技能和目标
  - 得分理由显示：开发者模式下显示每个动作的得分计算过程
  - 难度指示器：显示当前AI难度等级（简单/普通/困难）
- **音频要求**：
  - 攻击音效：敌人准备攻击时播放低沉的战斗声
  - 防御音效：敌人准备防御时播放格挡声
  - 连携音效：敌人准备连携时播放配合声
  - 状态音效：敌人准备施加状态时播放特殊音效

## UI要求

- **AI决策预览界面**：
  - 位置：敌人头顶上方，行动前1秒显示
  - 样式：半透明提示条，显示即将使用的技能和目标
  - 内容：包含技能图标、目标指示、行为类型（攻击/防御/连携/状态）
  - 交互：鼠标悬停显示详细得分计算过程，帮助玩家理解AI决策

- **开发者调试界面**：
  - 位置：按F1打开开发者控制台，输入show_ai_debug命令
  - 样式：表格形式显示完整的AI决策数据
  - 内容：显示所有候选动作的评分、最终选择的动作、难度调整参数等
  - 交互：支持复制AI决策日志，便于平衡测试和调试

- **难度指示器**：
  - 位置：战斗界面右上角
  - 样式：显示当前AI难度等级（简单/普通/困难），使用不同颜色标识
  - 动画：难度切换时有淡入淡出效果
  - 交互：点击可查看当前难度的具体行为特征

- **战术意图图标**：
  - 位置：敌人模型周围
  - 样式：根据行为类型显示不同图标（红色剑形=攻击、蓝色盾形=防御、黄色连线=连携、紫色药瓶=状态）
  - 动画：图标旋转入场，持续1秒后淡出
  - 音频：不同图标显示时播放对应的音效（攻击-战斗声、防御-格挡声、连携-配合声、状态-特殊音效）

- **UI交互原则**：
  - 所有UI元素应使用水墨风格图标和传统纹样边框
  - AI决策通过颜色和图标直观传达意图（红色=攻击、蓝色=防御、黄色=连携、紫色=状态）
  - 确保UI在不同分辨率下清晰可读，适配16:9、16:10、21:9等常见比例
  - 提供直观的AI预览和详细调试信息，帮助玩家理解战斗机制和做出明智决策

## 验收标准

- **GIVEN** 玩家处于Break状态，**WHEN** 敌人AI系统执行决策，**THEN** AI优先使用高伤害技能进行终结，评分增加100分。
- **GIVEN** 玩家拥有强力Shield，**WHEN** 敌人AI系统处理状态管理，**THEN** AI优先使用驱散技能或高爆发技能打破护盾，普通攻击得分降低。
- **GIVEN** Steam平台内存有限（<2GB），**WHEN** 进入战斗场景，**THEN** 系统使用默认的通用AI配置，确保核心战斗功能正常运行。
- **GIVEN** 游戏运行在不同难度等级（简单/普通/困难），**WHEN** 查看AI行为，**THEN** AI表现出对应的行为特征（简单：随机选择，普通：基本策略，困难：预测性打断和资源管理）。
- **GIVEN** 敌人HP < 30%且无治疗手段，**WHEN** 敌人AI系统处理生存本能，**THEN** AI选择"防御"以恢复架势并减伤，或使用轻功后撤。
- **GIVEN** 队友已施加Wet状态，**WHEN** 敌人AI系统处理连携配合，**THEN** AI优先使用Lightning技能触发感电组合技。
- **GIVEN** AI评分计算结果溢出，**WHEN** 系统处理最终评分，**THEN** 自动限制最终评分在-50到1200范围内，防止数值溢出导致游戏崩溃。
- **GIVEN** 玩家下回合将释放强力大招，**WHEN** 困难难度下敌人AI系统执行预测性打断，**THEN** AI优先使用控制技能打断玩家大招释放。

## 开放问题

- **AI平衡性**：如何建立有效的AI平衡测试框架，确保不同难度等级和敌人类型之间的公平性和挑战性？
- **动态难度调整**：如何根据玩家表现动态调整AI难度和行为模式？
- **跨平台兼容性**：虽然目标平台是Steam (PC)，但如果未来需要支持其他平台，当前的AI系统设计是否足够灵活？
- **本地化支持**：如何设计AI系统以支持多语言本地化，特别是UI文本和音频提示？
- **多人模式扩展**：虽然当前是单人游戏，但AI系统是否为未来的多人合作或对战模式预留了扩展接口？
