# LOD（细节层次）系统

> **状态**: 设计中
> **作者**: 用户 + 代理
> **最后更新**: 2026-04-24
> **实现支柱**: 支柱2：自由探索与发现

## 概述

LOD（细节层次）系统通过在玩家移动时根据距离动态调整游戏世界中物体的细节级别，在维持沉浸式无缝探索体验的同时，将内存占用和渲染压力控制在PC平台硬件极限之内。玩家与该系统完全自动互动，无需任何手动操作。如果没有这个系统，游戏将失去大规模地图的可行性，被迫退化为小场景加频繁黑屏加载（Loading Screen）的模式，或者因一次性加载所有高细节资源导致内存溢出崩溃及严重的帧率卡顿。该系统是实现"自由探索与发现"游戏支柱的技术基础，使玩家能够在广袤的江湖中自由漫游，同时确保水墨武侠风格在不同距离下都能保持视觉一致性。

## 玩家幻想

玩家应该感受到无缝、流畅的江湖探索体验，仿佛置身于一幅活生生的水墨山水画中。当他们在广袤的武侠世界中漫游时，不应该被技术限制打断沉浸感。系统应该在玩家不知不觉中处理所有技术细节，让他们专注于探索、发现和奇遇。

同时，玩家也应该能感受到世界的"呼吸"和"生命力"——远处的山脉、城镇和秘境随着他们的接近而逐渐显现更多细节，营造出一种世界无限延伸的感觉，激发他们继续探索的欲望。即使在远距离，水墨风格的青绿山水主色调和传统中式元素也应保持可辨识，确保视觉一致性。

参考游戏实现：
- 《刺客信条：英灵殿》的LOD系统实现了无缝的远景到近景过渡，保持了维京世界的沉浸感
- 《原神》的LOD系统在不同距离下保持了美术风格的一致性，同时优化了移动端性能

## 详细设计

### 核心规则

1. **LOD级别数量**：为2D游戏资产设置3个LOD级别：
   - **高细节级别**（近距离）：完整细节，包括所有纹理、动画和特效
   - **中细节级别**（中距离）：简化纹理和动画，移除次要特效
   - **低细节级别**（远距离）：极简版本，仅保留基本形状和主色调

2. **切换距离机制**：
   - 基于屏幕宽度的倍数确定切换距离
   - 高→中切换距离：1.5个屏幕宽度
   - 中→低切换距离：3.0个屏幕宽度
   - 低→卸载距离：4.5个屏幕宽度

3. **资产类型差异化策略**：
   - **地形**：3个LOD级别，主要简化纹理细节和多边形数量
   - **建筑**：3个LOD级别，远距离使用简化的轮廓版本
   - **NPC**：2个LOD级别（高/低），远距离使用静态精灵替代动画
   - **特效**：2个LOD级别（高/关闭），远距离完全关闭非关键特效

4. **PC平台特殊优化**：
   - 所有LOD资源可使用更高分辨率纹理格式（如PNG、JPEG），无需严格压缩
   - 实施对象池重用LOD资源，优化内存使用效率
   - 动态调整LOD切换距离基于硬件性能检测
   - 在低端PC上自动减少LOD级别数量（2级而非3级）

5. **视觉一致性保障**：
   - 所有LOD级别保持相同的青绿山水主色调
   - 远距离版本保留关键的水墨风格元素（如飞檐翘角、山水轮廓）
   - 使用渐进式加载确保LOD切换时的平滑过渡
   - 实施淡入淡出效果避免LOD切换时的突兀变化

### 状态和转换

- **高细节状态**：玩家距离物体0-1.5个屏幕宽度
- **中细节状态**：玩家距离物体1.5-3.0个屏幕宽度  
- **低细节状态**：玩家距离物体3.0-4.5个屏幕宽度
- **卸载状态**：玩家距离物体超过4.5个屏幕宽度

状态转换流程：
- 高 → 中：当玩家距离超过1.5个屏幕宽度
- 中 → 低：当玩家距离超过3.0个屏幕宽度
- 低 → 卸载：当玩家距离超过4.5个屏幕宽度
- 卸载 → 低：当玩家距离进入4.5个屏幕宽度
- 低 → 中：当玩家距离进入3.0个屏幕宽度
- 中 → 高：当玩家距离进入1.5个屏幕宽度

### 与其他系统的交互

- **世界流式加载系统**：协同工作，LOD系统负责已加载区块内资源的细节级别管理
- **开放世界探索系统**：提供玩家位置数据，触发LOD状态转换
- **艺术圣经**：确保所有LOD级别符合水墨武侠风格要求
- **性能监控系统**：接收性能数据，动态调整LOD策略以维持60FPS目标

## 公式

### LOD切换距离公式

`LOD切换距离 = 屏幕宽度 × 距离倍数`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 屏幕宽度 | screen_width | int | 800-1920 | 当前游戏窗口的像素宽度 |
| 距离倍数 | distance_multiplier | float | 1.5-4.5 | LOD级别对应的切换距离倍数 |
| LOD切换距离 | lod_switch_distance | int | 1200-8640 | 触发LOD切换的距离（像素） |

**输出范围:** 1200到8640像素
**示例:** 当屏幕宽度为1800像素，距离倍数为1.5时，LOD切换距离 = 1800 × 1.5 = 2700像素

### 动态LOD级别调整公式

`实际LOD级别 = min(配置LOD级别, 性能因子 × 设备等级)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 配置LOD级别 | configured_lod_levels | int | 2-3 | 游戏配置中设置的LOD级别数量 |
| 性能因子 | performance_factor | float | 0.5-1.0 | 基于当前帧率计算的性能因子 |
| 设备等级 | device_tier | int | 1-2 | 设备性能等级（1=低端，2=高端）<br>**检测标准**：<br>- **低端设备**：WebGL 1.0支持、内存<2GB、CPU核心数≤2<br>- **高端设备**：WebGL 2.0支持、内存≥2GB、CPU核心数>2 |
| 实际LOD级别 | actual_lod_levels | int | 1-3 | 实际使用的LOD级别数量 |

**输出范围:** 1到3个LOD级别
**示例:** 当配置LOD级别为3，性能因子为0.8，设备等级为1时，实际LOD级别 = min(3, 0.8 × 1) = min(3, 0.8) = 1（向下取整为1）

### 纹理压缩质量公式

`纹理质量 = 基础质量 - (LOD级别 × 质量衰减)`

**变量:**
| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 基础质量 | base_quality | int | 80-100 | 高细节级别的基础压缩质量 |
| LOD级别 | lod_level | int | 0-2 | LOD级别（0=高，1=中，2=低） |
| 质量衰减 | quality_decay | int | 5-15 | 每个LOD级别的质量衰减量 |
| 纹理质量 | texture_quality | int | 50-100 | 最终的纹理压缩质量 |

**输出范围:** 50到100%
**示例:** 当基础质量为90，LOD级别为2（低），质量衰减为10时，纹理质量 = 90 - (2 × 10) = 90 - 20 = 70%

## 边缘情况

- **如果玩家快速移动导致LOD级别频繁切换**：系统将实施防抖机制，避免在短时间内（500毫秒内）频繁切换LOD级别，确保视觉稳定性和性能。
- **如果PC平台内存不足**：系统将动态减少LOD级别数量，优先使用低细节级别资源，确保游戏流畅运行。
- **如果存储读取缓慢**：系统将优先加载低细节级别资源，确保玩家能够快速看到场景，然后在后台逐步加载高细节资源。
- **如果硬件性能检测失败**：系统将默认使用保守的2级LOD策略，确保在未知硬件上也能维持基本性能。
- **如果水墨风格资产在低LOD级别失去辨识度**：系统将保留关键的视觉元素（如主色调、基本轮廓），即使在最低LOD级别也能识别物体类型和风格。

## 依赖关系

- **上游依赖**（此系统依赖的系统）：
  - **世界流式加载系统**：LOD系统依赖流式加载系统提供已加载的区块数据
  - **开放世界探索系统**：需要玩家位置数据来确定LOD切换距离

- **下游依赖**（依赖此系统的系统）：
  - **地图/小地图系统**：可能需要根据LOD级别调整小地图显示细节
  - **性能监控系统**：使用LOD系统提供的性能数据进行动态调整

- **技术依赖**：
  - **Godot 4.6引擎**：利用Godot的内置LOD功能和渲染优化
  - **PC平台API**：利用PC硬件的性能监控API进行硬件性能检测

## 调整参数

- **LOD级别数量**：3个（可调整范围：2-4个）
- **高→中切换距离倍数**：1.5（可调整范围：1.0-2.0）
- **中→低切换距离倍数**：3.0（可调整范围：2.0-4.0）
- **低→卸载距离倍数**：4.5（可调整范围：3.0-6.0）
- **防抖时间**：500毫秒（可调整范围：200-1000毫秒）
- **纹理压缩基础质量**：90%（可调整范围：80%-100%）
- **纹理压缩质量衰减**：10%（可调整范围：5%-15%）
- **性能因子阈值**：0.7（可调整范围：0.5-0.9）
- **设备等级检测阈值**：30FPS（可调整范围：20-45FPS）

这些参数可以通过游戏配置文件进行调整，无需修改代码，便于在不同硬件平台上优化性能。

## 视觉/音频要求

- **视觉风格一致性**：所有LOD级别的资源必须符合艺术圣经中定义的水墨武侠风格，包括青绿山水主色调和传统中式元素。
- **LOD过渡效果**：LOD级别切换时应使用水墨晕染效果，模拟传统水墨画的渲染过程，增强沉浸感。
- **远距离辨识度**：即使在最低LOD级别，关键物体（如建筑、NPC）也应保持基本的形状和主色调，确保玩家能够识别。
- **性能指示器**：在开发版本中，可显示LOD级别的视觉指示器（如不同颜色边框），但在发布版本中应隐藏。
- **音频要求**：LOD系统本身不直接影响音频，但环境音效应根据玩家距离和LOD级别进行适当的淡入淡出处理，避免突兀变化。

## UI要求

- **无直接UI元素**：LOD（细节层次）系统本身不直接创建任何UI元素，所有LOD切换过程对玩家完全透明。
- **间接UI影响**：
  - **小地图系统**：可能需要根据LOD级别调整小地图显示的细节程度
  - **性能指示器**：在开发版本中，可显示LOD级别的视觉指示器，但在发布版本中应完全隐藏
- **UI交互原则**：
  - 玩家不应感知到LOD切换过程
  - 任何必要的UI反馈都应符合艺术圣经中的简约优雅原则
  - UI元素应使用水墨风格图标和传统纹样边框

## 验收标准

- **GIVEN** 玩家在2D世界中移动，**WHEN** 玩家距离物体1.5个屏幕宽度时，**THEN** 系统切换到中细节级别，且不会导致帧率下降超过10%（在测试设备：Intel i5-8250U, 8GB RAM, Chrome 120上）。
- **GIVEN** 玩家快速移动跨越多个区域，**WHEN** 玩家进入新区域，**THEN** 系统优先加载低细节级别资源，确保核心游戏体验不受影响。
- **GIVEN** PC平台内存充足（>2GB），**WHEN** 玩家探索大型地图，**THEN** 系统可维持3级LOD策略，提供更流畅的探索体验（在测试设备：Intel i5-8250U, 8GB RAM, Windows 10上）。
- **GIVEN** 设备性能检测显示低端PC（集成显卡、内存<4GB、CPU核心数≤2），**WHEN** 游戏启动，**THEN** 系统自动使用2级LOD策略而非3级，在测试场景（100x100单位开放区域，50个NPC）下维持60FPS目标。
- **GIVEN** 存储读取速度较慢（如机械硬盘），**WHEN** 资源加载超时，**THEN** 系统优先显示低细节级别资源，并在后台继续加载高细节资源。
- **GIVEN** 所有LOD级别资源，**WHEN** 在不同距离查看，**THEN** 水墨武侠风格的视觉一致性得到保持，关键元素（主色调、基本轮廓）始终可辨识。
- **GIVEN** 游戏运行在不同分辨率的设备上（800x600到1920x1080），**WHEN** 玩家探索世界，**THEN** 系统根据屏幕宽度动态调整LOD切换距离，确保一致的体验。
