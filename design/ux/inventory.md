## Purpose & Player Need

背包面板是玩家管理和查看游戏内所有物品的核心界面，承载以下目标：

1. **物品查看**：展示背包中所有物品（装备、消耗品、材料、任务道具、货币），按分类分页/筛选，支持查看详情
2. **物品管理**：装备/卸下装备、使用消耗品、出售/拆解物品、整理背包
3. **资源规划**：帮助玩家理解当前拥有的资源，做出合理的消耗、强化、升级决策
4. **快捷操作**：从背包快速装备、使用、出售、拆解物品，支持批量操作

**如果这个面板不存在或难用**：玩家无法查看和管理自己的物品、不知道该装备哪件装备、无法有效使用消耗品、不知道该出售或拆解哪些物品——经济与成长系统的核心体验将完全失效，玩家感受不到"收集"和"变强"的成就感。

**玩家来到这个面板的目的是**："我有什么？我该用什么？我该怎么处理多余物品？"

## Player Context on Arrival

### 到达时机与场景

| 触发场景 | 到达方式 | 玩家当前状态 | 情绪预期 |
|---------|---------|-------------|---------|
| HUD快捷键(I) / 点击背包按钮 | 玩家主动操作 | 游戏进行中，可能处于探索/战斗结束/休息 | 平静、管理策略 |
| 获得新物品后 | 系统提示→玩家主动打开 | 刚获得战利品/奇遇奖励 | 好奇、期待 |
| 战斗结束后 | 掉落奖励→玩家主动打开 | 查看获得的装备和材料 | 满足、规划 |
| 奇遇奖励后 | 点击"查看背包"链接 | 刚获得物品/材料/突破丹 | 期待、好奇 |
| 处理多余装备前 | 玩家主动打开 | 准备出售或拆解多余装备 | 策略思考 |

### 到达方式

背包面板是**玩家主动打开**的面板，不是系统强制推送。这意味着玩家带着明确的意图——"我想看看背包"或"我需要管理我的物品"。

### 情绪状态

- **获得新物品后**：好奇、期待——"我获得了什么？有多好？"
- **平时查看**：平静、管理策略——"我该装备哪件？该卖什么？"
- **战斗结束后**：满足、规划——"看看掉了什么，规划下一步"

### 关键交付时刻

1. **获得新物品查看详情时**：玩家看到物品属性、品阶，感受到收获的喜悦
2. **装备新装备时**：玩家感受到角色变强的即时反馈
3. **使用消耗品时**：玩家体验到资源管理的成就感
4. **批量出售/拆解时**：玩家感受到"清理背包"的满足感

## Navigation Position

背包面板是**侧边滑出面板**，属于HUD之上的二级菜单，与角色面板形态一致。

### 导航层级关系

```
Main Game (root)
├── 大地图场景 (World Map)
├── 战斗场景 (Battle)
├── 休息/存档场景 (Rest/Save)
│
├── CanvasLayer: HUD [Z-index: 基础层]
│   └── 背包按钮 / 物品快捷栏 ← 点击触发
│
└── CanvasLayer: Inventory Panel Overlay [Z-index: 200]
    ├── 半透明遮罩 (拦截游戏场景输入) ← 游戏画面渲染在背后，但不可交互
    └── 背包面板 (侧边滑出) ← 从右侧滑入，面板区域可交互
```

### 层级规则

- **Z-index**: HUD = 100, 角色面板 = 200, 背包面板 = 200, 奇遇面板 = 300, 确认对话框 = 400
- **面板形态**: 侧边滑出（从屏幕右侧），宽度约屏幕的40%（最小宽度560px，最大宽度720px）
- **半模态**: 面板存在期间，游戏场景持续渲染在遮罩后方（15%变暗），但输入被遮罩拦截，玩家无法与游戏场景交互
- **互斥性**: 与角色面板、设置面板互斥，同一时间只能打开一个
- **面板内导航**: 三个Tab页签——背包（默认）、货币、快捷操作

## Entry & Exit Points

### Entry Points

| 入口来源 | 触发器 | 玩家携带的上下文 |
|---------|--------|-----------------|
| HUD背包按钮 | 鼠标点击 / 键盘I键 | 当前游戏场景、背包快捷预览 |
| 战斗结束掉落提示 | 点击"查看"按钮 | 刚获得的物品列表 |
| 奇遇奖励后 | 点击"查看背包"链接 | 刚获得的物品/材料 |
| 物品快捷栏点击 | 右键点击快捷栏物品 | 当前快捷栏中的物品 |
| 装备面板跳转 | 点击"打开背包"按钮 | 当前装备管理上下文 |

### Exit Points

| 出口目标 | 触发器 | 不可逆状态变化 |
|---------|--------|---------------|
| 游戏场景 | 点击关闭按钮 / 按Escape | 已装备/使用/出售/拆解的物品已生效 |
| 角色面板 | 点击角色面板按钮 | 当前面板关闭，角色面板打开 |
| 装备物品 | 拖拽或点击"装备"按钮 | 物品已装备到对应槽位 |
| 使用消耗品 | 点击"使用"按钮 | 物品已从背包移除，效果已应用 |
| 出售/拆解物品 | 批量操作确认 | 物品已移除，银两/材料已增加 |

## Layout Specification

### Information Hierarchy

背包面板必须展示的所有信息，按优先级排列：

| 优先级 | 信息项 | 用途 | 是否始终可见 |
|-------|--------|------|-------------|
| 1 | 面板标题 | 身份识别 | ✅ 始终（Header） |
| 2 | 银两余额 | 当前货币资源 | ✅ 始终（Header） |
| 3 | 当前Tab内容 | 背包/货币/快捷操作详情 | 根据Tab切换 |
| 4 | 分类筛选器 | 快速定位物品类型 | ✅ 始终（背包Tab） |
| 5 | 物品列表/网格 | 背包中所有物品 | ✅ 始终（背包Tab） |
| 6 | 物品详情 | 选中物品的完整属性 | 选中物品时显示 |
| 7 | 操作按钮 | 装备/使用/出售/拆解等 | 根据选中物品类型变化 |
| 8 | 容量指示 | 当前占用/总容量 | ✅ 始终（背包Tab底部） |
| 9 | 货币明细 | 各货币类型数量 | 货币Tab |
| 10 | 批量操作 | 一键出售/拆解/整理 | 快捷操作Tab |

### Layout Zones

背包面板采用**侧边滑出**布局，从屏幕右侧滑入，宽度约为屏幕的40%（最小宽度560px，最大宽度720px）。面板分为以下区域：

#### 区域定义

| 区域 | 内容 | 样式 |
|------|------|------|
| **A. Header** | 面板标题、银两余额 | 深色背景，传统纹样边框 |
| **B. Tab导航** | 背包/货币/快捷操作三个Tab按钮 | 当前Tab高亮，水墨风格选中态 |
| **C. 内容** | 当前Tab的物品列表/网格/操作（可滚动） | 半透明背景，ScrollContainer |
| **D. 详情/操作** | 选中物品的详细信息 + 可用操作按钮 | 根据选中物品类型动态变化 |
| **E. 关闭** | 关闭按钮（右上角） | 简洁的X图标 |

## States & Variants

| 状态/变体 | 触发条件 | 什么变化 |
|-----------|---------|---------|
| **默认** | 玩家通过HUD点击背包按钮打开面板 | 背包Tab默认激活，显示所有物品网格，无物品选中 |
| **获得新物品后** | 战斗结束/奇遇奖励后打开 | 新物品位于网格最后可用位置，带有红色"NEW"角标（2秒后淡出），该物品自动选中并显示详情 |
| **背包满** | 物品数量达到当前容量上限 | 容量指示显示"容量: N/XX"（红色文字），网格无空位，增加物品操作禁用（出售/拆解/使用等非增加操作仍可用） |
| **背包空** | 无任何物品时打开 | 网格全空，显示"背包空空如也"占位文本和引导图标 |

| **分类筛选激活** | 点击分类按钮 | 网格仅显示对应类型物品，其他槽位隐藏 |
| **拖拽模式** | 鼠标按住物品拖拽 | 物品图标跟随光标移动，目标槽位高亮显示放置区域 |
| **拖拽冲突** | 拖拽物品到已有物品的槽位 | 槽位变为黄色边框，松开后按以下规则处理（见下方拖拽规则详表） |

| **任务道具拖拽** | 拖拽任务道具到任意槽位 | 允许移动位置，不可交换到其他类型物品槽位（仅同类任务道具可交换） |

| **UI缩放175%** | 玩家设置UI缩放到最大 | 面板宽度从40%扩大到70%，所有文字等比放大，网格槽位变为80×80px，内容区域使用ScrollContainer处理溢出，半透明遮罩保持全屏覆盖 |

## 低端设备降级策略（PC配置补充说明）

> **注**：PC平台的可用内存检测和GPU性能检测：
> - `OS.get_static_memory_usage()` 在桌面平台返回较准确值
> - `RenderingServer.get_video_adapter_name()` 可检测GPU型号
>
> **替代降级方案**：
> - **方案A**：基于帧率的动态降级 — 面板打开后监测3秒内平均帧率，若<30FPS则禁用批量动画。通过 `Engine.get_frames_per_second()` 实现。
> - **方案B**：基于预设质量的降级 — 在设置中读取 `GraphicsSettings.quality_preset`，若为"低"则直接禁用批量动画。
> - **方案C**：系统内存检测 — 使用 `OS.get_static_memory_usage()` 获取系统可用内存，若低于4GB则降级。
>
> **推荐**：V1.0采用方案B（基于预设），后续版本叠加方案A（基于帧率）。降级阈值配置保留为待实现状态。

### 分析关键事件

以下事件用于玩家行为分析：

| 事件 | 用途 |
|------|------|
| `inventory_panel_opened` | 追踪背包使用频率和来源分布 |
| `inventory_item_selected` | 追踪玩家关注哪些物品，识别高关注物品 |
| `inventory_item_equipped` | 追踪装备搭配偏好，识别OP装备 |
| `inventory_bulk_sold` | 追踪玩家清理背包频率，验证背包容量设计 |
| `quick_sell_all` | 追踪批量操作使用率 |
| `quick_dismantle_all` | 追踪拆解偏好，对比出售/拆解比例 |

**设计要点**：
- 所有修改背包状态的事件（装备/使用/出售/拆解）都是**状态变更事件**，需要持久化
- 面板打开/关闭、物品选中是**分析事件**，用于理解玩家行为
- 拖拽移动不触发持久化，仅记录分析数据
- **未来多人模式扩展**：所有事件数据结构预留`timestamp`（UNIX毫秒）和`sequence_id`（自增整数）字段。当前单机阶段由InventorySystem自动填充（timestamp=当前时间，sequence_id=操作计数）。多人模式下这两个字段将由服务器生成，客户端保持数据结构兼容。

| 物品选中 | 边框高亮 | 150ms | 槽位边框发光，品阶颜色脉冲 |
| 获得新物品 | 脉冲光效 | 500ms | 槽位品阶边框闪烁+缩放(1.1x→1.0x) |
| 装备物品 | 装备动画 | 300ms | 物品飞入装备槽位轨迹动画 |
| 卸下装备 | 卸下动画 | 250ms | 物品从装备槽位飞回背包网格 |
| 使用消耗品 | 使用动画 | 400ms | 物品图标淡出，数量角标-1，粒子效果 |
| 出售物品 | 金币动画 | 500ms | 物品消失，银两数字从0滚动到增加后的值 |
| 拆解物品 | 碎裂动画 | 400ms | 物品图标碎裂+材料图标出现 |
| 拖拽物品 | 跟随动画 | 即时 | 物品图标跟随光标，目标槽位放大1.1x |
| 放置物品 | 落入动画 | 200ms | 物品落入目标槽位，轻微弹跳 |
| 整理背包 | 重新排列 | 600ms | 所有物品按序飞入新位置，级联延迟 |
| NEW角标 | 淡出 | 2000ms后200ms淡出 | "NEW"文字从红色渐变到透明 |
| 批量操作 | 级联动画 | 800ms | 每个物品依次执行出售/拆解动画，间隔50ms |
| 银两余额变化 | 数字滚动 | 500ms | 从旧值滚动到新值，增加时金色闪烁 |

### Reduce Motion 支持

当玩家启用"减少动画"选项时：

| 原动画 | 降级行为 |
|--------|---------|
| 面板滑入/滑出 | 直接显示/隐藏（无动画） |
| Tab切换 | 直接切换内容（无淡入淡出） |
| 物品装备/卸下 | 直接更新显示状态 |
| 出售/拆解动画 | 直接更新数值和物品列表 |
| NEW角标 | 直接显示，2秒后直接消失 |
| 整理背包 | 直接重新排列，无飞行轨迹 |
| 数字滚动 | 直接显示新值（无滚动） |

**设计要点**：
- 面板动画时长控制在300ms以内，确保流畅不拖沓
- 所有动画使用Godot的`Tween`节点实现，性能开销低
- 批量操作动画是唯一的"重动画"（800ms），但可通过设置关闭
- Reduce Motion选项通过全局设置读取，面板内组件统一遵守

**低端设备降级策略**：
- 当检测到系统可用内存<4GB或GPU性能低于最低要求时，批量出售/拆解动画自动降级为"直接显示结果"（无级联动画）
- 降级判定在面板打开时执行一次，结果缓存至本次会话
- 玩家可在设置中手动开启"显示批量动画"覆盖自动降级
- 降级阈值可配置：`PerformanceConfig.low_memory_threshold_mb = 512`，`PerformanceConfig.low_gpu_tier = 1`

### 数据快照与并发策略

| 操作 | 持久化时机 | 失败处理 |
|------|-----------|---------|
| 装备/卸下 | 点击"装备"/"卸下"按钮后立即写入 | 槽位冲突时回滚操作 |
| 使用消耗品 | 点击"使用"按钮后立即写入 | 效果无法应用时回滚数量 |
| 出售物品 | 确认对话框确认后写入 | 显示错误提示，回滚数量 |
| 拆解物品 | 确认对话框确认后写入 | 显示错误提示，回滚物品 |
| 批量出售/拆解 | 确认对话框确认后批量写入 | 使用WorkerThreadPool后台处理，失败则整批回滚，跳过已锁定/已装备物品 |
| 锁定/解锁 | 点击锁定按钮或按L键后立即写入 | 仅更新锁定标记，不影响物品数量 |
| 整理背包 | 点击"整理"按钮后立即写入 | 重新读取当前物品列表，重新排列，锁定物品保持原位 |

**并发冲突处理**：
- 面板打开时从InventorySystem读取**快照数据**，面板内操作基于此快照
- 面板存在期间，外部系统（战斗、奇遇）对背包的修改**不会实时同步到面板**
- 面板关闭时，若外部数据已变更（如战斗中获得新物品），关闭前刷新一次显示
- 装备/使用/出售/拆解操作时，重新读取当前InventorySystem的对应物品进行校验，避免快照过期导致的错误操作
- 银两余额在出售/拆解后立即从EconomyManager重新读取

**设计要点**：
- 面板打开时从各系统读取快照数据，面板内操作不实时同步外部变化
- 所有Write操作需通过InventorySystem的公开API（如`equip_item()`, `use_item()`, `sell_item()`, `dismantle_item()`）
- 物品数据库数据为只读，由ItemDatabase统一管理
- 银两余额由EconomyManager统一管理，背包面板仅读取和显示

## Localization Considerations

### 文本扩展风险

简体中文为基准语言，翻译到其他语言时的文本扩展预估：

| 元素 | 中文长度 | 英文扩展 | 德文扩展 | 法文扩展 | 布局影响 |

| 物品名称 | 2-4字 | +30% | +50% | +40% | 低（详情区域可变宽度） |
| 品阶名称 | 2字（普通/稀有等） | +40% | +60% | +50% | 低（标签空间充足） |

**HIGH PRIORITY 标记项**：
- 装备类型名称在翻译后可能超过单行容纳长度（如"Main-Hand Weapon"），详情区域需支持换行

## Acceptance Criteria

### 性能

- [ ] 面板从点击触发到完全显示不超过400ms（含300ms滑入动画）
- [ ] Tab切换响应时间不超过50ms，内容切换动画200ms内完成
- [ ] 面板打开期间游戏场景持续渲染，帧率不下降超过5%
- [ ] 面板内存占用不超过50MB（含所有UI资源预加载）
- [ ] 批量出售/拆解操作在800ms内完成（30件物品上限）

### 功能

- [ ] HUD背包按钮(I键)可打开面板，背包Tab默认激活
- [ ] 分类筛选按钮点击后网格仅显示对应类型物品，其他槽位隐藏
- [ ] 点击物品槽位可选中物品，详情区域显示对应物品类型内容
- [ ] 双击装备/消耗品可执行装备/使用操作，播放对应动画
- [ ] 装备按钮在等级不足时灰色禁用，显示"等级不足"红色提示
- [ ] 出售/拆解操作弹出确认对话框，确认后物品移除并增加对应资源
- [ ] 一键出售/拆解显示预计收益/材料，确认后批量执行
- [ ] 整理背包后物品按类型分组排列，播放重新排列动画
- [ ] 货币Tab显示所有货币类型及数量，银两始终位于列表顶部
- [ ] 快捷操作Tab三个按钮功能完整，点击后执行对应操作
- [ ] 拖拽物品到空槽位可移动位置，拖拽到已有槽位可交换（同类物品）
- [ ] 点击关闭按钮或按Escape可关闭面板，半模态遮罩同步滑出

### 状态变体

- [ ] 首次打开面板时显示当前物品网格，无物品选中状态
- [ ] 获得新物品后打开，该物品带有红色"NEW"角标（2秒后淡出）并自动选中
- [ ] 背包满(30/30)时容量指示显示红色文字，所有增加物品操作禁用
- [ ] 背包空时网格显示"背包空空如也"占位文本和引导图标
- [ ] 装备选中时详情区域显示属性、品阶、等级需求，装备/出售/拆解按钮可用
