## 1. HUD哲学

### 1.1 设计原则

**核心原则**：

1. **意境优先，留白为美**
   - 继承水墨画的留白美学，HUD元素不应过度填充屏幕
   - 重要信息清晰可见，次要信息适时隐藏
   - 保持视觉呼吸空间，让玩家专注于游戏世界本身

2. **信息分层，按需显示**
   - 一级信息（生命、内力等核心资源）始终可见
   - 二级信息（Buff/Debuff、连击数）在战斗中显示
   - 三级信息（详细数值、统计）按需弹出
   - 避免信息过载，减少认知负担

3. **武侠美学，文化融合**
   - UI元素融入传统纹样、书法、卷轴等元素
   - 色彩遵循青绿山水主色调，点缀暖色强调
   - 动效体现武侠的飘逸感和力量感
   - 字体使用传统书法风格，保持文化韵味

4. **功能至上，形式服务**
   - 美学设计不能牺牲可读性和可用性
   - 所有UI元素必须在PC平台上清晰可辨
   - 交互反馈明确，避免玩家困惑
   - 性能优化优先，确保60FPS流畅体验

5. **一致性与可预测性**
   - 相同类型的信息使用统一的视觉语言
   - 布局位置保持稳定，避免频繁移动
   - 交互模式一致，降低学习成本
   - 颜色编码统一（如红色=危险，绿色=安全）

**优先级排序**：

1. **可读性** > 美观性
   - 在任何情况下，信息必须清晰可读
   - 对比度、字号、间距优先保证

2. **核心战斗信息** > 辅助信息
   - HP、Qi、Poise等战斗资源优先级最高
   - 行动顺序、敌人弱点等战术信息次之
   - 任务追踪、地图等探索信息可折叠

3. **性能** > 视觉效果
   - PC平台性能预算：<5000 draw calls
   - 动画和特效不能影响帧率
   - 必要时简化视觉效果以保证流畅度

4. **即时反馈** > 延迟美化
   - 数值变化、状态改变必须立即反馈
   - 动画过渡不能延误关键信息传达
   - 玩家操作响应优先于视觉润色

**设计约束**：

**技术约束**：
- 目标平台：Steam PC（Godot 4.6 Steam导出）
- 性能预算：<5000 draw calls，<8GB内存
- 帧率目标：60FPS稳定
- 分辨率适配：1280x720 至 1920x1080（主流）
- 输入方式：键盘+鼠标（主要），手柄（部分支持）

**美学约束**：
- 必须符合Art Bible定义的水墨风格
- 色彩限定：青绿(#2E8B57)、墨黑(#000000)、深红(#DC143C)、金色(#FFD700)
- 字体限定：方正清刻本悦宋（标题）、思源宋体（正文）
- 避免现代科技感元素，保持武侠古典氛围

**可访问性约束**：
- 最小字号：14px（确保可读性）
- 对比度：至少4.5:1（WCAG AA标准）
- 色盲友好：不能仅依赖颜色传达信息
- 键盘导航：所有功能必须可通过键盘访问

**游戏设计约束**：
- 不遮挡核心游戏画面（特别是战斗区域）
- 支持战斗内/战斗外两种模式切换
- 必须显示游戏三大支柱相关信息：
  - 深度武学系统（技能、连击、内力）
  - 自由探索与发现（地图、任务、奇遇）
  - 奇遇驱动的成长（等级、境界、属性）

### 1.2 玩家需求分析

**目标玩家画像**：

**主要玩家类型：探索者（Explorer）**
- 特征：喜欢发现世界、寻找秘密、探索地图
- 需求：清晰的导航信息、任务追踪、地图标记
- HUD需求：小地图/导航、任务列表、奇遇提示
- 占比：约40%

**次要玩家类型：成就者（Achiever）**
- 特征：喜欢克服挑战、收集物品、提升等级
- 需求：详细的角色数据、成长进度、收集统计
- HUD需求：经验条、等级显示、属性点提示、收集进度
- 占比：约35%

**其他玩家类型：**
- **社交者（Socializer）**：约15%，关注NPC关系、剧情对话
- **杀手（Killer）**：约10%，关注战斗数据、伤害统计

**综合画像**：
- 年龄：18-35岁
- 游戏经验：中度到硬核玩家
- 文化背景：对武侠文化有兴趣或了解
- 平台偏好：PC玩家，习惯键鼠操作
- 游戏时长：单次会话30-120分钟

**核心使用场景**：

**场景1：战斗中（高强度）**
- 频率：约30%游戏时间
- 关注点：
  - 生命值、内力、架势（实时监控）
  - 行动顺序队列（战术规划）
  - 敌人弱点和状态（战术决策）
  - 连击值、连携槽（技能释放时机）
  - Buff/Debuff（状态管理）
- 操作需求：快速扫视，即时决策
- HUD要求：信息密集但清晰，关键数据突出

**场景2：探索中（中等强度）**
- 频率：约50%游戏时间
- 关注点：
  - 当前位置和目标方向（导航）
  - 任务进度（目标追踪）
  - 生命值和资源（安全状态）
  - 奇遇触发提示（发现新内容）
- 操作需求：偶尔查看，不干扰沉浸感
- HUD要求：简洁低调，不遮挡风景

**场景3：角色成长（低强度）**
- 频率：约15%游戏时间
- 关注点：
  - 等级和经验进度（成长反馈）
  - 可用属性点、天赋点（成长机会）
  - 境界突破提示（重要里程碑）
  - 新技能解锁（能力扩展）
- 操作需求：详细查看，深度思考
- HUD要求：提供入口，详细信息在菜单中

**场景4：社交/剧情（低强度）**
- 频率：约5%游戏时间
- 关注点：
  - 对话选项和NPC信息
  - 剧情提示和选择后果
- 操作需求：专注对话内容
- HUD要求：最小化显示，避免干扰

**信息需求优先级**：

**P0级（生死攸关，必须始终可见）**：
1. 主角生命值（HP）
2. 主角内力（Qi）
3. 主角架势（Poise）
4. 队友生命值（如有队友）

**P1级（战斗关键，战斗中显示）**：
5. 行动顺序队列
6. 敌人生命值和弱点
7. 连击值（Combo）
8. 连携槽（Link Gauge）
9. Buff/Debuff状态
10. 当前选中目标

**P2级（战术辅助，按需显示）**：
11. 敌人详细信息（Down/Break状态）
12. 技能冷却时间
13. 物品快捷栏
14. 战斗统计（伤害、回合数）

**P3级（探索辅助，可折叠）**：
15. 小地图/导航
16. 任务追踪
17. 等级和经验条
18. 境界显示
19. 可用点数提示

**P4级（系统功能，菜单入口）**：
20. 主菜单按钮
21. 设置按钮
22. 帮助/教程入口
23. 系统时间/游戏时间

## 2. 信息架构

### 2.1 信息层级

**一级信息（始终可见，P0级）**：

这些信息对玩家的生存至关重要，必须在所有游戏状态下保持可见：

1. **主角生命值（HP）**
   - 当前值/最大值
   - 百分比条形图
   - 临界状态警告（<30%变红）

2. **主角内力（Qi）**
   - 当前值/最大值
   - 百分比条形图
   - 用于技能释放判断

3. **主角架势（Poise）**
   - 当前值/最大值
   - 百分比条形图
   - 破防警告（<20%闪烁）

4. **队友生命值（如有队友）**
   - 简化显示（仅血条+头像）
   - 倒地状态明显标识

**二级信息（情境显示，P1-P2级）**：

这些信息在特定游戏状态下显示，主要是战斗相关：

**战斗中显示**：
5. **行动顺序队列**
   - 显示接下来3-5个行动单位
   - 当前行动者高亮
   - 敌我双方图标区分

6. **敌人生命值和弱点**
   - 选中敌人的HP条
   - 五行弱点图标（金木水火土）
   - Down/Break状态标识

7. **连击值（Combo）**
   - 当前连击数
   - 连击倍率加成
   - 连击断裂倒计时

8. **连携槽（Link Gauge）**
   - 当前蓄力值/最大值
   - 可用连携技能提示
   - 充能动画效果

9. **Buff/Debuff状态**
   - 图标+剩余回合数
   - 正面效果（上方/绿色边框）
   - 负面效果（下方/红色边框）

10. **当前选中目标**
    - 目标名称
    - 目标血条
    - 目标弱点

**按需显示**：
11. **敌人详细信息**
    - 鼠标悬停或按键查看
    - 完整属性、抗性、技能列表

12. **技能冷却时间**
    - 技能图标上的冷却遮罩
    - 剩余回合数显示

13. **物品快捷栏**
    - 可用物品图标
    - 数量显示
    - 快捷键提示

14. **战斗统计**
    - 总伤害、回合数、评分
    - 战斗结束后显示

**三级信息（按需显示，P3-P4级）**：

这些信息通过玩家主动操作或特定触发条件显示：

**探索辅助**：
15. **小地图/导航**
    - 按键切换显示/隐藏
    - 当前位置、目标标记
    - 兴趣点图标

16. **任务追踪**
    - 当前主线/支线任务
    - 目标进度
    - 可折叠/展开

17. **等级和经验条**
    - 当前等级
    - 经验进度条
    - 升级时闪烁提示

18. **境界显示**
    - 当前境界名称
    - 突破进度（如适用）
    - 境界加成提示

19. **可用点数提示**
    - 属性点数量（红点提示）
    - 天赋点数量（红点提示）
    - 点击打开对应界面

**系统功能**：
20. **主菜单按钮**
    - ESC键或点击打开
    - 图标位置固定

21. **设置按钮**
    - 快捷访问常用设置
    - 音量、画质等

22. **帮助/教程入口**
    - 新手引导提示
    - 按需查看帮助

23. **系统时间/游戏时间**
    - 可选显示
    - 不影响沉浸感

## 3. 布局设计

### 3.1 屏幕分区

**布局网格**（基于1920x1080分辨率）：

> **重要**：以下坐标为Godot 4.6 Control节点的锚点+偏移量表示法，
> 非绝对像素坐标。所有HUD元素使用锚点锚定屏幕边缘，通过偏移量微调。
> `offset_left/offset_right/offset_top/offset_bottom` 相对于锚点位置。

```
┌─────────────────────────────────────────────────────────────┐
│ 左上区域 (240x180)    顶部区域 (1440x120)    右上区域 (240x180) │
│ [小地图/导航]         [行动顺序队列]         [菜单/设置]      │
│                                                             │
│ 左侧区域 (180x720)    中央区域 (1560x720)   右侧区域 (180x720)│
│ [任务追踪]            [游戏画面 - 留白]     [成长提示]       │
│ [可折叠]              [战斗区域]            [可折叠]         │
│                       [不遮挡]                              │
│                                                             │
│ 左下区域 (360x180)    底部区域 (1200x180)   右下区域 (360x180)│
│ [角色状态]            [快捷栏/连击显示]     [敌人信息]       │
│ [HP/Qi/Poise]         [物品/技能]           [目标血条]       │
└─────────────────────────────────────────────────────────────┘
```

**锚点系统说明**（Godot 4.6）：

所有HUD元素使用 `Control` 节点的锚点系统，锚点值范围为 0.0~1.0：
- `anchor_left = 0.0` 锚定屏幕左边缘
- `anchor_right = 1.0` 锚定屏幕右边缘
- `anchor_top = 0.0` 锚定屏幕顶部
- `anchor_bottom = 1.0` 锚定屏幕底部

偏移量（offset）从锚点位置计算：
- 左上角锚定时：`offset_left = 16, offset_top = 20` → 距离左边缘16px，距顶部20px
- 右下角锚定时：`offset_right = -16, offset_bottom = -20` → 距离右边缘16px，距底部20px

**坐标统一规范**：
- 本文档中所有坐标使用格式：`锚定方位 + offset值`
- 例如：左下角角色状态 = `anchor_right=0, anchor_bottom=1, offset_left=16, offset_top=-180, offset_right=376, offset_bottom=0`
- 不再使用绝对像素坐标 `(x, y)` 表示法（避免与Godot的锚点系统冲突）

### 3.2 安全区域

**视觉安全区域（Title Safe Area）**：

基于16:9宽高比（1920x1080），定义安全区域确保所有重要信息在各种显示设备上都可见：

- **外边距**：距离屏幕边缘至少5%（96px水平，54px垂直）
- **安全区域尺寸**：1728x972px（中心区域）
- **关键信息区域**：1536x864px（更保守，距边缘10%）

**安全区域规则**：
1. **P0级信息**（HP、Qi、Poise）必须在关键信息区域内
2. **P1级信息**（行动队列、敌人信息）必须在安全区域内
3. **P2-P4级信息**可以接近边缘，但不能贴边
4. **文本内容**必须完全在安全区域内，避免被裁切

**交互安全区域（Action Safe Area）**：

确保所有可交互元素都在易于点击/选择的区域：

- **最小点击区域**：48x48px（符合无障碍可访问性标准）
- **按钮间距**：至少8px
- **边缘交互元素**：距离屏幕边缘至少16px
- **鼠标悬停区域**：比视觉元素大10%，便于精确定位

**平台特定考虑**：

**目标平台**：Steam (PC)

**分辨率范围**：
- **最低支持**：1280x720（720p）
- **推荐**：1920x1080（1080p）
- **最高支持**：3840x2160（4K，固定尺寸模式）
- **超宽屏**：21:9宽高比部分支持（侧边留黑边）

**宽高比支持**：
- **主要支持**：16:9（1920x1080, 1280x720）
- **次要支持**：16:10（1920x1200, 1280x800）
- **有限支持**：21:9（2560x1080，侧边留黑边）
- **不支持**：4:3（过时比例）

**缩放策略**：

**1280x720（720p）**：
- 所有UI元素等比缩放至66.7%
- 最小字号：14px → 10px（仍可读）
- 图标尺寸：48x48px → 32x32px
- 布局保持不变，仅缩放

**1920x1080（1080p，基准）**：
- 100%原始尺寸
- 所有设计以此为基准

**2560x1440（1440p）**：
- UI元素等比缩放至133%
- 或保持1080p尺寸，增加留白
- 优先选择：保持1080p尺寸（避免UI过大）

**响应式布局调整**：

**低分辨率（<1280x720）**：
- 自动隐藏P3-P4级信息
- 任务追踪默认折叠
- 小地图缩小或隐藏
- 保留P0-P1级核心信息

**高分辨率（>1920x1080）**：
- 增加中央留白区域
- UI元素位置不变（锚定边缘）
- 可选：显示更多任务/Buff图标

**超宽屏（21:9）**：
- 中央16:9区域正常显示
- 两侧留黑边或显示装饰性水墨元素
- 不拉伸UI，保持比例

### 5.2 UI元素样式

#### 5.2.1 血条/资源条
- **形状**：长方形，圆角2-4px（HP=2px，Qi/Poise=2px，经验条=2px）
- **填充样式**：从左到右填充，渐变填充，带光点流动特效（Qi专属）
- **边框样式**：墨黑色2px，带水墨笔触效果（使用shader实现）
- **动画效果**：减少立即收缩(200px/s)，损失层延迟0.3s；增加平滑扩展(150px/s)

#### 5.2.2 图标设计
- **尺寸规范**：
  - 角色头像：80x80px（主角），60x60px（队友）
  - Buff/Debuff：32x32px
  - 五行弱点：32x32px
  - 境界标识：24x24px
  - 系统按钮：48x48px
  - 快捷栏槽位：64x64px
  - 红点标记：12x12px
- **风格统一**：水墨风格，线条简洁流畅，避免锐利几何形状
- **状态变化**：正常=无特效，不可用=灰度滤镜+50%透明，选中=金色边框3px+脉动

#### 5.2.3 文本显示
- **数值显示**：米白色(#F5F5DC)带黑色1px描边，增加/减少时用绿/红色闪烁
- **标签显示**：小字12-14px，半透明米白色，紧跟数值后方
- **描述文本**：14px Regular，行高1.5，最大宽度300px（Tooltip），超出换行

#### 5.2.4 背景与容器
- **透明度**：面板背景rgba(0,0,0,0.6-0.7)，容器边框rgba(0,0,0,0.8)
- **边框装饰**：墨黑色2px边框，圆角4px，四角可加传统纹样装饰（可选）
- **水墨元素**：边框使用自定义shader模拟水墨笔触，面板背景可加纸张纹理（subtle，10%opacity）

### 5.3 视觉层级

**Z-index分层**：

> **设计原则**：Z-index值按视觉层级排列，数值越大越靠前。
> 空间上不重叠的层级可以共用或接近同一层级，减少层级碎片。

| CanvasLayer Z-index | 层级名称 | 包含内容 | 空间位置 |
|---------------------|---------|----------|---------|
| 100 | HUD Base | HP/Qi/Poise条、经验条、等级显示（P0核心信息） | 左下角 |
| 110 | HUD Team | 队友状态面板（简化HP） | 左下角（Base下方） |
| 120 | HUD Combat | 行动队列（顶部）、连击显示（中上）、连携槽（中上）、敌人信息（右下） | 多区域 |
| 130 | HUD Hotbar | 快捷栏、物品/技能图标（底部中央） | 底部中央 |
| 140 | HUD Navigation | 小地图（左上）、任务追踪（左侧） | 左侧区域 |
| 150 | HUD System | 菜单按钮、设置按钮、帮助按钮、红点提示（右上） | 右上角 |
| 160 | HUD Notifications | 升级提示、境界突破、成就通知（右侧通知区） | 右侧区域 |
| 200 | HUD Tooltip | 所有悬停提示、物品详情、Buff详情 | 跟随光标/焦点 |
| 250 | Settings Panel | 设置面板 | 中央模态 |
| 300 | Encounter Overlay | 奇遇面板（模态覆盖） | 全屏覆盖 |
| 400 | Encounter Sub-dialog | 奇遇内的确认对话框 | 中央模态 |
| 500 | Dialog Overlay | 剧情对话框（底部1/3） | 底部覆盖 |

**层级说明**：
- 快捷栏(130)在敌人信息(120)之上 — 因为两者空间不重叠（底部中央 vs 右下角），Z值接近不会冲突
- Tooltip(200)独立层级 — 确保悬停信息始终在所有HUD元素之上
- Dialog Overlay(500)最高 — 剧情对话时必须遮挡所有HUD

**视觉权重**：

| 权重级别 | 信息类型 | 视觉强调方式 |
|---------|---------|-------------|
| 极高（P0） | HP危急、队友倒地 | 红色闪烁、屏幕晕影、循环音效 |
| 高（P1） | 当前行动者、连击即将断裂 | 金色/红色边框脉动、音调递增音效 |
| 中（P2） | 新Buff、技能冷却完成 | 图标滑入/闪光、单次提示音 |
| 低（P3） | 任务更新、经验增长 | 淡入通知、轻微音效 |
| 极低（P4） | 菜单入口、设置按钮 | 静态显示，仅悬停时高亮 |

- **左摇杆**：同上，方向映射到最近的焦点元素
- **A键**：确认/激活当前焦点元素
- **X键**：查看当前焦点元素的详细信息（替代鼠标悬停）
- **Y键**：打开当前焦点元素的上下文菜单（替代右键点击）
- **LB/RB**：在快捷栏槽位间快速切换（不进入完整导航路径）
- **Tab键**：在手柄模式下映射为"快速循环"——一键跳到下一个主要区域（跳过子元素）
- **焦点高亮**：当前焦点元素显示2px金色边框 + 105%缩放
- **焦点循环**：最后一个元素按下后回到第一个（可选，设置中可关闭）

**Tab键在手柄模式下的映射**：

| 键鼠操作 | 手柄等效操作 | 说明 |
|---------|------------|------|
| Tab（下一个焦点） | LB + 十字键右 | 跳到下一个主要区域 |
| Shift+Tab（上一个焦点） | LB + 十字键左 | 跳到上一个主要区域 |
| 鼠标悬停 | 选中后按X键 | 显示详细信息 |
| 右键点击 | 选中后按Y键 | 打开上下文菜单 |
| 拖拽调整槽位 | 选中槽位 → 移动到目标 → A确认 | 选择模式替代拖拽 |
| 小地图点击标记 | 十字键在兴趣点间导航 → A确认 | 预设标记点替代自由点击 |

**手柄不支持的功能**：

根据 `technical-preferences.md` 中定义的"手柄部分支持"，以下HUD功能在手柄上**不支持**或有限制：

1. **快捷栏拖拽**
   - 不支持：使用手柄拖拽调整槽位顺序
   - 替代方案：使用选择模式（选中槽位 → 移动到目标位置 → 确认）

2. **小地图精确点击标记**
   - 不支持：使用右摇杆精确点击地图上的任意位置设置标记
   - 替代方案：使用方向键在预定义的兴趣点间导航，A键确认选择

3. **悬停显示详情**
   - 不支持：鼠标悬停自动显示工具提示
   - 替代方案：使用焦点选中元素后，按特定按钮（如X键）查看详情

4. **右键上下文菜单**
   - 不支持：右键点击打开上下文菜单
   - 替代方案：选中元素后按Y键打开选项菜单

5. **自由光标移动**
   - 限制：右摇杆模拟鼠标光标，但精度和速度不如真实鼠标
   - 建议：优先使用焦点导航（D-Pad/左摇杆）而非光标模式

**手柄操作优化建议**：
- 所有关键功能都提供了手柄友好的替代方案
- 手柄玩家应优先使用焦点导航而非光标模式
- 快捷栏操作建议使用肩键（LB/RB）快速切换，而非拖拽
- 地图导航建议使用预设标记点，而非自由点击

#### 6.3.4 性能考虑

**动画性能预算**：
- **同时动画数量**：最多20个
- **粒子效果**：最多100个粒子
- **帧率目标**：60FPS稳定
- **CPU占用**：动画系统<5% CPU

**优化策略**：
- **动画合批**：
  - 相同类型动画合并处理
  - 使用Tween池复用
  - 批量更新Transform
- **LOD系统**：
  - 低性能设备简化动画
  - 减少粒子数量
  - 降低动画帧率（30FPS）
- **视口剔除**：
  - 屏幕外元素停止动画
  - 折叠元素停止动画
  - 最小化元素简化动画
- **缓存优化**：
  - 预计算动画曲线
  - 缓存Tween对象
  - 复用粒子系统

**动画复杂度分级**：
- **简单**（<1ms）：
  - 位置/缩放/旋转
  - 透明度变化
  - 颜色过渡
- **中等**（1-3ms）：
  - 多属性组合动画
  - 简单粒子效果
  - 序列动画
- **复杂**（3-5ms）：
  - 复杂粒子效果
  - 着色器动画
  - 骨骼动画

**降级方案**：
- **性能不足时**：
  - 禁用装饰性动画
  - 简化过渡效果
  - 使用即时切换
  - 减少粒子数量
- **极低性能**：
  - 仅保留关键动画
  - 禁用所有特效
  - 使用静态UI

### 6.4 HUD 状态定义

每个 HUD 元素在其生命周期内需经历以下状态。确保在任何异常情况下玩家都能看到明确的反馈，而非空白或错误。

#### 6.4.1 Error State（错误状态）

当数据源不可用、加载失败或数据损坏时进入错误状态。

**触发条件**：
- `PlayerData` 加载失败（存档损坏、文件缺失）
- 数据绑定超时（信号连接后3秒内无数据返回）
- 网络同步失败（如有在线功能）

**通用降级规则**：

| 元素类型 | 正常显示 | Error State 显示 | 视觉指示 |
|---------|---------|-----------------|---------|
| HP/Qi/Poise条 | 当前值/最大值条形图 + 数值 | `--/--` + 灰色遮罩 | 条形图填充 50% 灰度斜纹 (#808080)，数值区域显示 `--/--` |
| 经验条 | 经验进度 + 等级 | `--/--` + 等级 `?` | 条形图填充 50% 灰度，等级显示 `?` |
| 头像 | 角色头像纹理 | 占位符图标 | 显示默认灰色人形图标 (#CCCCCC) |
| Buff/Debuff图标 | 效果图标 + 持续时间 | 不显示 | 容器隐藏，不占用空间 |
| 任务列表 | 任务名称 + 目标 + 进度 | `"任务数据不可用"` | 显示单行灰色提示文本，无交互 |
| 小地图 | 区域地图 + 标记 | `"地图加载中..."` | 显示旋转加载动画 + 提示文本 |
| 快捷栏槽位 | 物品图标 + 数量 | 空槽 | 显示空槽背景 + `---` |
| 敌人信息 | 敌人名称 + HP + 弱点 | `"目标信息未知"` | 显示灰色提示文本，隐藏 HP 条和弱点图标 |
| 行动队列 | 行动单位图标序列 | `"战斗中"` | 显示单行灰色提示文本，不显示具体图标 |

**Error State 退出**：
- 数据恢复后自动退出错误状态（0.3秒淡入正常状态）
- 退出时播放轻微"恢复"音效（可选）

**注意**：
- Error State **不应触发** 屏幕晕影、心跳、闪烁等警告特效（避免与濒死状态混淆）
- Error State 仅在 HP/Qi/Poise 的核心资源条上持久显示，其他元素可在数据恢复前保持隐藏

#### 6.4.2 Loading State（加载状态）

当 HUD 初始化或数据正在从持久化存储加载时进入加载状态。

**触发条件**：
- 游戏启动后首次进入场景
- 从存档加载后
- 场景切换期间

**加载状态显示**：

| 阶段 | 持续时间 | 显示内容 | 视觉表现 |
|------|---------|---------|---------|
| 初始化 | 0-0.5秒 | 全屏半透明遮罩 | 黑色 40% opacity，中央旋转水墨图标 |
| 核心资源加载 | 0.5-1.5秒 | HP/Qi/Poise 条（灰色占位） | 条形图背景可见，填充区域显示流动斜纹动画 |
| 次要资源加载 | 1.5-3秒 | 逐步显示各区域（从 P0 到 P4） | 每个区域淡入显示（0.2秒/区域） |
| 加载完成 | ~3秒 | 所有 HUD 元素正常显示 | 遮罩淡出（0.3秒） |

**加载超时处理**：
- 若核心资源（HP/Qi/Poise）在 3 秒内未加载完成 → 进入 Error State（见 6.4.1）
- 若次要资源超时 → 跳过该区域，不进入 Error State（按需加载时再尝试）
- 超时后玩家仍可正常游戏（HUD 降级不影响核心玩法）

**加载状态退出**：
- 所有核心资源加载完成后自动退出
- 退出时遮罩淡出 + HUD 元素从 P0 到 P4 依次淡入

#### 6.4.3 Empty State（空状态）

当数据源正常但内容为空时进入空状态。

**触发条件**：
- 玩家尚未获得任何 Buff/Debuff
- 任务列表无活跃任务
- 快捷栏槽位无物品
- 队伍中无队友

**空状态显示**：

| 元素 | 空状态行为 | 视觉表现 |
|------|-----------|---------|
| Buff/Debuff 容器 | 隐藏容器 | 不占用空间，不显示边框或背景 |
| 任务列表 | 显示空提示 | `"暂无追踪任务"`（14px，灰色 #808080，居中） |
| 快捷栏空槽 | 显示空槽背景 | 半透明黑色背景 + `---` 符号（12px） |
| 队友状态面板 | 隐藏面板 | 不占用空间，主角面板不受影响 |
| 敌人信息面板 | 隐藏面板（探索模式） | 战斗中若无选中目标则隐藏 |
| 连携槽 | 显示空槽 | 条形图 0% 填充 + 灰色填充 (#808080) |
| 连击值 | 隐藏显示 | 完全不显示，无占位符 |
| 行动队列 | 仅显示当前行动者 | 其他位置显示 `...` |
| 可用点数提示 | 隐藏红点 | 不占用空间，不显示脉动动画 |

**空状态退出**：
- 数据变为非空时自动退出（0.2秒淡入）
- 无需音效反馈（避免频繁打扰）

#### 6.4.4 状态优先级

当多个状态同时触发时，按以下优先级显示：

```
Error State > Loading State > Empty State > Normal State
```

**示例场景**：
- 加载中 + 数据为空 → 显示 Loading State（等待加载完成后再判断是否为空）
- 加载完成 + 无数据 → 显示 Empty State
- 加载超时 → 显示 Error State
- 正常运行 → 显示 Normal State

#### 6.4.5 状态转换图

```
[Loading] ──(加载成功)──→ [Normal] ──(数据清空)──→ [Empty]
    │                        │                       │
    │(超时)                   │(数据错误)             │(数据恢复)
    ↓                        ↓                       ↓
[Error  ] ──(恢复)─────────→ [Normal] ←──────────────┘
```

## 7. 响应式设计

### 7.1 分辨率适配

**支持的分辨率**：

| 分辨率 | 宽高比 | 支持级别 | UI缩放比例 | 说明 |
|--------|--------|---------|-----------|------|
| 1280x720 | 16:9 | 完全支持 | 66.7% | 最低配置，所有元素等比缩小 |
| 1366x768 | 16:9 | 完全支持 | 71.2% | 常见笔记本分辨率 |
| 1920x1080 | 16:9 | 基准分辨率 | 100% | 设计基准 |
| 2560x1440 | 16:9 | 完全支持 | 100%（不变） | 保持1080p尺寸，增加留白 |
| 2560x1080 | 21:9 | 有限支持 | 100% | 两侧留黑边，不拉伸UI |
| 1920x1200 | 16:10 | 部分支持 | 100% | 上下留白，UI位置不变 |

**缩放策略**：

**等比缩放模式**（1280x720及以下）：
- 所有HUD元素使用 `Control` 节点的锚点布局，相对于屏幕边缘
- CanvasLayer使用 `scale = Vector2(viewport_width / 1920.0, viewport_height / 1080.0)` 进行整体缩放
- 或使用Godot 4.6的 `CanvasLayer` + `Control` 锚点系统，每个子元素独立锚定
- 字体使用 `Theme.default_font_size` 或自定义 Theme 的 `font_size` 属性等比缩放
- 最小字号：14px → 10px（720p），仍保持可读
- 图标尺寸等比缩小（48px → 32px）
- **Godot 4.6锚点API示例**：
  ```gdscript
  # 左下角锚定（角色状态面板）
  func setup_player_status():
      var panel = preload("res://scenes/hud/player_status.tscn").instantiate()
      panel.anchor_left = 0.0    # 锚定左边缘
      panel.anchor_top = 1.0     # 锚定底部
      panel.anchor_right = 0.0   # 锚定左边缘（宽度由offset_right决定）
      panel.anchor_bottom = 1.0  # 锚定底部
      panel.offset_left = 16     # 距离左边缘16px
      panel.offset_top = -180    # 距离底部180px（负值向上）
      panel.offset_right = 376   # 宽度 = 376 - 16 = 360px
      panel.offset_bottom = 0    # 贴底
      add_child(panel)
  
  # 顶部居中锚定（行动顺序队列）
  func setup_turn_queue():
      var panel = preload("res://scenes/hud/turn_queue.tscn").instantiate()
      panel.anchor_left = 0.1    # 左10%处开始
      panel.anchor_top = 0.0     # 锚定顶部
      panel.anchor_right = 0.9   # 右10%处结束
      panel.anchor_bottom = 0.0  # 锚定顶部
      panel.offset_left = 0
      panel.offset_top = 20
      panel.offset_right = 0
      panel.offset_bottom = 120  # 高度120px
      add_child(panel)
  ```

**固定尺寸模式**（2560x1440及以上）：
- HUD元素保持1080p设计尺寸不变
- 增加中央留白区域，UI锚定四角
- 可选：增加额外信息（更多Buff显示、更详细数值）

**超宽屏处理**（21:9）：
- 中间16:9区域正常显示所有UI
- 两侧留黑边，可显示装饰性水墨元素（静态，不影响性能）
- 不拉伸、不重新排列UI元素

**布局调整规则**：

| 规则 | 条件 | 调整方式 |
|------|------|----------|
| 低分辨率自适应 | 宽度<1920px | 等比缩放，布局不变 |
| 高分辨率自适应 | 宽度>1920px | 保持元素尺寸，增加留白 |
| 安全区域约束 | 所有分辨率 | P0/P1元素必须在Title Safe Area内 |
| 自动折叠 | 高度<768px | 任务追踪默认折叠，小地图缩小 |
| 底部元素保护 | 高度<720px | 快捷栏上移，避免被底部遮挡 |

## 8. 可访问性

### 8.1 视觉可访问性

**色盲模式**：

| 模式 | 影响范围 | 替代方案 |
|------|---------|----------|
| 无（默认） | 正常颜色 | — |
| 红绿色盲 | HP条红色/绿色 | HP健康=蓝色(#4682B4)，警告=橙色(#FFA500)，危险=深灰(#666666)+闪烁 |
| 红绿色盲 | 敌方边框红色 | 敌方边框=紫色(#8B008B)+三角形标识 |
| 蓝黄色盲 | Qi条青色/经验条金色 | Qi条=紫色(#9370DB)，经验条=橙色(#FF8C00) |
| 全色盲 | 所有颜色 | 全部使用灰度+图案区分（条纹/点阵/斜线） |

**对比度要求**：

| 文本类型 | 前景色 | 背景色 | 对比度 | 标准 |
|---------|--------|--------|--------|------|
| 标题/按钮 | #F5F5DC | rgba(0,0,0,0.7) | 15.4:1 | ✅ WCAG AAA |
| HP数值 | #F5F5DC | 渐变条 | ≥7:1 | ✅ WCAG AAA |
| 快捷键提示 | #F5F5DC | rgba(0,0,0,0.6) | 12:1 | ✅ WCAG AAA |
| Buff持续时间 | #F5F5DC | rgba(0,0,0,0.8) | 15.4:1 | ✅ WCAG AAA |
| Tooltip描述 | #CCCCCC | rgba(0,0,0,0.9) | 10.6:1 | ✅ WCAG AAA |
| 次级文字（经验数值） | #AAAAAA | rgba(0,0,0,0.6) | 6.2:1 | ✅ WCAG AA |

**文本可读性**：
- **最小字号**：14px（基于1920x1080），缩放后不低于10px（720p）
- **最大行宽**：300px（Tooltip），超出自动换行
- **描边/阴影**：所有HUD文字使用1px黑色描边，确保在任意背景上可读
- **字间距**：正常间距，不额外增加或缩减
- **行间距**：多行文本行高1.5倍

**减少运动模式**：
- 禁用所有缩放动画（入场/退场替换为淡入淡出）
- 禁用粒子特效（光点流动、火焰粒子等）
- 禁用呼吸/脉动动画（替换为静态颜色变化）
- 禁用屏幕震动
- 禁用伤害飘字的摆动动画（改为垂直上浮）
- 保留：HP/Qi/Poise条填充动画（功能性，不可禁用）

**焦点导航规则**：

- 当前焦点元素显示2px金色边框高亮

- 菜单打开时禁用战斗操作快捷键
- 系统提供快捷键冲突检测和警告
- 不能重新绑定的键：ESC（主菜单）

**可配置性**：

**可重新绑定的操作**：
- 快捷栏1-8绑定
- 技能快捷键Q/E/R/F
- 界面打开快捷键C/K/I/M/N/T
- 切换目标快捷键

**不可重新绑定的操作**：
- ESC：主菜单（系统级）
- Enter/Space：确认（系统级）
- Backspace：取消（系统级）

**手柄支持（部分功能受限）**：
- 所有关键HUD功能可通过手柄访问（使用替代方案）
- D-Pad/摇杆导航焦点
- A确认，B取消
- 肩键快速切换槽位
- 振动反馈可调整强度或关闭
- **注意**：部分功能在手柄上体验受限（如拖拽、精确点击、悬停），但都提供了替代操作方式

**屏幕阅读器支持（基础）**：

由于 Godot 4.6 在 PC 平台对屏幕阅读器的原生支持有限，当前实现提供基础级别的支持：

**支持的功能**：
- **焦点元素朗读**：当前焦点的 UI 元素名称和类型
- **数值变化通知**：HP/Qi/Poise 变化时的语音提示（可选）
- **重要事件通知**：升级、境界突破、战斗开始/结束等关键事件

**实现方式**：

1. **Godot 原生支持**：
   - 使用 `Control.set_accessible_name()` 为所有关键 UI 元素设置可访问名称
   - 使用 `Control.set_accessible_description()` 提供详细描述
   - 为按钮、滑块等交互元素设置正确的 `accessible_role`
   - 示例代码：
     ```gdscript
     # PlayerStatusPanel.gd
     func _ready():
         hp_bar.set_accessible_name("生命值")
         hp_bar.set_accessible_description("当前生命值 850 / 最大生命值 1200")
         hp_bar.accessible_role = Control.ACCESSIBLE_ROLE_PROGRESS_BAR
     ```

2. **状态变化通知**：
   - 使用 `AccessibilityNode` 的 `notification` 系统发送状态变化事件
   - 在数值变化时更新 `accessible_description`
   - 示例代码：
     ```gdscript
     func update_hp(current: int, max_value: int):
         hp_bar.value = current
         hp_bar.set_accessible_description("当前生命值 %d / 最大生命值 %d" % [current, max_value])
     ```

### 9.2 性能优化

#### 9.2.1 性能预算

**HUD特定性能目标**：

**渲染性能**：
- **Draw Calls**：< 100（HUD部分）
- **Batching**：尽可能合批UI元素
- **Overdraw**：避免不必要的重叠绘制
- **Shader复杂度**：简单着色器，避免复杂计算

**更新性能**：
- **每帧更新**：仅P0级信息（HP、Qi、Poise）
- **每0.1秒更新**：P1级信息（行动队列、连击）
- **按需更新**：P2-P4级信息（任务、地图）
- **避免**：每帧遍历所有UI元素

**内存占用**：
- **纹理内存**：< 50MB（所有HUD纹理）
- **节点数量**：< 500个（整个HUD场景）
- **脚本实例**：< 50个（活跃脚本对象）

**具体指标**：
- 战斗中HUD更新：< 1ms/帧
- 探索中HUD更新：< 0.5ms/帧
- 模式切换延迟：< 50ms
- 通知显示延迟：< 16ms（1帧）

### 10.2 可用性测试

**测试目标**：
- 验证玩家能在战斗中快速理解当前状态（HP、Qi、Poise）
- 验证玩家能识别行动顺序和当前行动者
- 验证玩家能找到并使用快捷栏物品
- 验证导航系统（小地图+任务追踪）易于使用
- 验证菜单入口易于发现和访问

**测试方法**：
- **观察法**：让5-10名测试者完成指定任务，观察其是否能正确找到HUD信息
- **问卷法**：测试后填写SUS（System Usability Scale）问卷
- **计时法**：记录玩家找到特定信息所需时间

**测试任务**：
1. "查看你当前还剩多少HP" — 预期时间 < 1秒
2. "找出下一个行动的是谁" — 预期时间 < 2秒
3. "查看选中敌人的弱点" — 预期时间 < 3秒
4. "使用快捷栏中的HP药水" — 预期时间 < 3秒
5. "打开设置面板" — 预期时间 < 2秒
6. "查看当前追踪的任务" — 预期时间 < 2秒

**成功指标**：
- 任务完成率 ≥ 90%
- 平均任务时间不超过上述预期
- SUS评分 ≥ 75分
- 无严重可用性问题（S级问题 = 0）

**实现建议**：
- **优先级排序**：中优先级功能 > 低优先级功能
- **工时预算**：总计约20-35天，建议分批实现
- **实现顺序**：
  1. 第一批（中优先级）：高级统计、伤害统计面板、快捷栏预设、任务导航箭头（约8-10天）
  2. 第二批（低优先级）：战斗回放、多套UI主题、动态难度提示、成就通知（约10-13天）
  3. 第三批（低优先级）：自定义HUD布局、小地图标记系统（约6-8天）
- **取舍原则**：如果时间紧张，优先保证核心HUD功能的完善和优化，可选功能可以在后续版本中添加

#### 11.5.2 字体与本地化

- **中文**：方正清刻本悦宋（标题）、思源宋体（正文）— 已获取授权
- **英文/拉丁字母**：Noto Serif（标题）、Noto Sans（正文）— Google Fonts 免费授权
- **其他语言**：Noto Sans 系列覆盖 99% Unicode 字符，缺失字符回退到系统默认字体

**字号缩放**：
- 中文字号以 16px 为基准
- 英文/西文字号等效视觉大小，使用 **14px Noto Sans ≈ 16px 思源宋体**
- 日文字号同中文，但行高增加 10%

#### 11.5.3 布局适配

| 语言 | 阅读方向 | 布局调整 | 特殊需求 |
|------|---------|---------|---------|
| 中文 | 从左到右 | 无调整 | 字间距正常 |
| 英文 | 从左到右 | 无调整 | 行高增加 5% |
| 阿拉伯语 | 从右到左 | 镜像布局（设置中启用） | 文字右对齐 |
| 日语 | 从左到右 | 无调整 | 部分文本需垂直书写（竖排） |
| 韩语 | 从左到右 | 无调整 | 文本通常比中文短 |

**镜像布局规则**：
- 左下角角色状态 → 右下角
- 右下角敌人信息 → 左下角
- 右上角菜单 → 左上角
- 左上角小地图 → 右上角
- 任务追踪左/右侧可切换
- 底部中央快捷栏位置不变

#### 11.5.4 数字与格式

| 内容 | 格式 | 示例（中文） | 示例（英文） |
|------|------|------------|------------|
| 数值 | 本地化数字分隔符 | 12,500 | 12,500 |
| 日期 | YYYY-MM-DD | 2026-05-08 | 2026-05-08 |
| 时间 | 24小时制 | 14:30 | 14:30 / 2:30 PM |
| 百分比 | XX% | 75% | 75% |
| 等级 | Lv.XX | Lv.25 | Lv.25 |
| 经验进度 | 当前/总计 | 12,500/16,000 | 12,500/16,000 |
