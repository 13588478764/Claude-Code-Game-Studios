## 议程

### 第一部分：平台定义决策 (20分钟)

#### 问题背景
- **game-concept.md** 明确定义目标平台为 **Steam (PC)**
- **martial-arts-database.md** 和 **item-database.md** 却设计为 **Web平台**
- 内存预算冲突：Web (<100MB) vs PC (>2GB)

#### 需要决策的问题

**Q1.1: 最终目标平台是什么？**
- [ ] **选项A**: Steam (PC) - 保持game-concept.md的定义
- [ ] **选项B**: Web浏览器 - 修改game-concept.md
- [ ] **选项C**: 双平台 - 需要两套优化策略

**推荐**: 选项A (Steam PC)，理由：
- 游戏概念已明确定义为Steam平台
- PC平台更适合大型开放世界武侠RPG
- 可以利用更强的硬件性能提供更好的体验

**Q1.2: 如果选择Steam PC，内存预算应该是多少？**
- [ ] **选项A**: <500MB (保守估计，适配低端PC)
- [ ] **选项B**: <1GB (中等配置)
- [ ] **选项C**: <2GB (主流配置)

**推荐**: 选项B (<1GB)，理由：
- 符合"主流PC配置"的定义
- 为其他系统预留足够内存空间
- 避免过度优化的复杂性

**Q1.3: 需要修改的GDD**
如果确认为Steam PC平台，需要更新：
- martial-arts-database.md: "Web平台优化" → "PC平台优化"
- item-database.md: "Web平台优化" → "PC平台优化"
- 所有验收标准中的"Web平台内存<100MB" → "PC平台内存<1GB"

### 第二部分：等级上限决策 (25分钟)

#### 问题背景
- **character-progression-system.md**: 等级上限 **99级**
- **experience-system.md**: 玩家等级范围 **1-99**
- **level-up-mechanism.md**: 最高境界化神期 **Lv 41-50**，硬上限 **50级**

#### 需要决策的问题

**Q2.1: 最终等级上限是多少？**
- [ ] **选项A**: 50级 - 符合武侠"化神期"为最高境界的设定
- [ ] **选项B**: 99级 - 提供更长的成长曲线
- [ ] **选项C**: 其他 (请说明): _______

**推荐**: 选项A (50级)，理由：
- 符合传统武侠"化神期"为最高境界的设定
- 5个境界 × 10级/境界 = 50级，结构清晰
- 避免后期数值膨胀和平衡性问题
- MVP阶段更容易实现和测试

**Q2.2: 每级获得多少属性点？**
- [ ] **选项A**: 1点/级 (总计50点，稀缺资源，策略性强)
- [ ] **选项B**: 5点/级 (总计250点，自由度高，角色强大)
- [ ] **选项C**: 其他 (请说明): _______

**推荐**: 选项A (1点/级)，理由：
- 符合传统RPG设计
- 每个属性点的价值更高，选择更有意义
- 避免属性点过剩导致的选择无意义化
- 更容易平衡战斗系统

**Q2.3: 境界数量是多少？**
- [ ] **选项A**: 5个境界 (炼气、筑基、金丹、元婴、化神)
- [ ] **选项B**: 4个境界 (需要重新定义)
- [ ] **选项C**: 其他 (请说明): _______

**推荐**: 选项A (5个境界)，理由：
- level-up-mechanism.md已详细定义
- 符合传统武侠修炼体系
- 每10级一个境界，节奏合理

**Q2.4: 总属性点数计算**
基于上述决策：
- 如果50级 × 1点/级 = **50点总属性点**
- 如果50级 × 5点/级 = **250点总属性点**

**需要更新的公式和数值**:
- character-progression-system.md: 总属性点495 → 50或250
- experience-system.md: 等级范围1-99 → 1-50
- 所有相关的升级公式和经验值曲线

### 第三部分：属性维度决策 (20分钟)

#### 问题背景
- **character-progression-system.md**: **六维** (力道、身法、根骨、悟性、**定力**、福缘)
- **level-up-mechanism.md**: **五维** (力道、身法、根骨、悟性、福缘)
- **damage-calculation-system.md**: **五维** (STR、WIS、AGI、CON、LUK)
- **combat-system.md**: 无定力相关描述

#### 需要决策的问题

**Q3.1: 是否保留"定力"属性？**
- [ ] **选项A**: 保留定力 (六维体系)
- [ ] **选项B**: 移除定力 (五维体系)
- [ ] **选项C**: 将定力整合到其他属性 (例如：根骨或悟性)

**推荐**: 选项B (移除定力，五维体系)，理由：
- 所有其他系统都使用五维
- 定力的功能可以整合到现有属性：
  - 架势条上限 → 根骨 (CON)
  - 格挡成功率 → 身法 (AGI)
  - 免受控制概率 → 悟性 (WIS)
- 简化属性系统，降低玩家认知负荷

**Q3.2: 如果保留定力，需要在哪些系统中添加定力的影响？**
如果选择保留定力，必须在以下系统中添加定力的影响：
- [ ] combat-system.md: 定力影响架势条上限
- [ ] health-defense-system.md: 定力影响格挡成功率
- [ ] status-effect-system.md: 定力影响控制抵抗
- [ ] damage-calculation-system.md: 定力参与伤害计算公式

**Q3.3: 最终属性体系**
基于上述决策，确认最终属性体系：

**五维体系** (推荐):
- **力道 (STR)**: 影响物理伤害、负重
- **身法 (AGI)**: 影响命中率、闪避率、行动速度、格挡成功率
- **根骨 (CON)**: 影响生命值上限、架势条上限、防御力
- **悟性 (WIS)**: 影响内力上限、内功伤害、控制抵抗
- **福缘 (LUK)**: 影响暴击率、奇遇触发概率、掉落品质

**需要更新的GDD**:
- character-progression-system.md: 移除定力属性
- health-defense-system.md: 架势值关联属性从"定力"改为"根骨"

### 第四部分：伤害计算公式统一 (15分钟)

#### 问题背景
- **martial-arts-database.md** 包含"元素克制倍率"
- **combat-system.md** 缺少"元素克制倍率"

#### 需要决策的问题

**Q4.1: 伤害计算公式是否包含元素克制倍率？**
- [ ] **选项A**: 包含元素克制倍率 (支持五行相克系统)
- [ ] **选项B**: 不包含元素克制倍率 (简化战斗系统)

**推荐**: 选项A (包含元素克制倍率)，理由：
- 武侠题材天然适合五行相克系统
- 增加战斗策略深度
- martial-arts-database.md已定义金木水火土五行

**Q4.2: 最终伤害计算公式**
基于上述决策，确认最终公式：

```
最终伤害 = 基础伤害 × 暴击系数 × 连击系数 × 弱点系数 × 破防系数 × 状态系数 × 随机浮动 × 元素克制倍率
```

**变量定义**:
- 基础伤害: 10-1000
- 暴击系数: 1.0-2.5
- 连击系数: 1.0-1.3
- 弱点系数: 1.0-1.5
- 破防系数: 1.0-1.5
- 状态系数: 0.5-2.0
- 随机浮动: 0.95-1.05
- **元素克制倍率: 1.0-1.5** (新增)

**需要更新的GDD**:
- combat-system.md: 添加元素克制倍率到伤害公式
- control-manifest.md: 记录最终权威公式

### 第五部分：其他警告级问题快速决策 (10分钟)

#### 需要快速决策的问题

**Q5.1: 境界突破加成方式**
- [ ] **选项A**: 百分比加成 (全属性+10%)
- [ ] **选项B**: 固定值加成 (HP+200, 内力+100)

**推荐**: 选项A (百分比加成)，理由：符合武侠"境界突破"的概念

**Q5.2: 卸载距离统一**
- [ ] **选项A**: 3.0倍屏宽 (world-streaming)
- [ ] **选项B**: 4.5倍屏宽 (lod-system)

**推荐**: 选项B (4.5倍屏宽)，理由：确保LOD完全卸载后才卸载区块

**Q5.3: 内力回复率**
- [ ] **选项A**: 固定10%/回合
- [ ] **选项B**: 范围5%-10%，默认5%

**推荐**: 选项B (5%-10%，默认5%)，理由：提供调整空间
