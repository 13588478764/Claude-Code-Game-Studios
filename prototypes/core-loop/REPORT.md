# Prototype Report: Core Loop

> **Prototype**: `prototypes/core-loop/index.html`
> **Date**: 2026-05-16 → 2026-05-18
> **Status**: Concluded — PROCEED to production

## Hypothesis

二选一事件卡 + 资源管理的核心循环是否有趣？3 分钟内能否产生紧张感和笑点？

## Approach

单文件 HTML 原型（CSS + JS + 硬编码数据），三轮迭代：

1. **v1** — Vue 3 CDN + 基础 UI
   - 国内 CDN 不可达 → 切纯原生 JS
   - 嵌套引号破坏 JS 字符串字面量 → 修复
2. **v2** — 视觉升级
   - 启动标题画面 + 渐变金色 logo + CTA 开工按钮
   - 64px 角色头像随状态变 7 种表情
   - 渐变立体按钮 + 资源条发光描边
   - 舞台幕布日期切换 + 心情危机时屏幕脉冲红光
3. **v3** — 加深机制（4 个新系统）
   - 🔗 后果链 followUp：选 A 触发紫色"后续"卡片，单点选择变成短叙事链
   - ⚡ 状态系统 Buff/Debuff：☕亢奋（精力消耗 ×0.5）、💔emo（心情损失 ×1.5）等带天数倒数
   - 🎲 风险博弈：按钮显示概率，全屏骰子动画 + 大字成功/翻车结果
   - 🛒 小卖部：每张卡间隙能花钱买咖啡/奶茶/按摩，金钱变成战略资源

最终：21 个程序员主题事件，每天 2-4 个事件，5 天工作周。

## Result

- **核心循环验证通过**：用户反馈"总体还行"
- **视觉品质显著影响玩法评价** — 素界面会被误判为"机制简单"，加视觉后用户重新定位问题为"机制深度"，加机制后再定位到"内容广度"
- **4 个深度机制全部 work**：
  - 后果链产生叙事连贯感
  - Buff/Debuff 让数值变化变成策略选择（保留 buff 还是用爆发）
  - 风险骰子加紧张感（70% 装病请假动画拉满）
  - 小卖部把金钱从"记分板"变成"资源"
- **主要瓶颈在内容广度，不是核心机制** — 21 个事件 5 天能玩完，重复感强；但这是内容生产的范畴，不是原型该解决的

## Metrics

| 指标 | 实测 |
|------|------|
| 单局时长 | 约 2-4 分钟（达成"3 分钟产生紧张感"目标） |
| 选择次数 | 每局约 16-20 次 |
| 死亡条件触发率 | 双线（精力/心情）压力清晰，玩家两次死亡都因"心情归零暴走离职" |
| 视觉响应 | 60fps（DOM 渲染无压力） |
| 用户感受迭代曲线 | "界面太简单" → "玩法过于简单" → "总体还行" |

## Recommendation: **PROCEED**

机制层验证完毕，可进入正式开发。原型证明了：

1. 二选一 + 资源管理在 3 分钟体验中能产生张力
2. 后果链 / Buff / 风险 / 消费 四个机制都为玩法增加了有效深度
3. 视觉品质是核心循环可玩性的一部分，不是事后包装

## If Proceeding

### 架构需求（已在 9 个 GDD + 3 个 ADR 中定义）

- 按职业分包（ADR-002）支撑 50-100+ 事件/职业

### 性能目标
- 60fps、首屏 < 3s
- 主包 < 2MB、分包总计 < 20MB
- 内存 < 128MB（低端安卓兼容）

### 生产改动

2. **事件文案由 systems-designer 批量产出**：

4. **Buff/状态系统是新增需求**，需要追加 GDD（原 status-system 未在 9 个 MVP GDD 中）

- MVP 约 6-8 周（参考 `design/gdd/systems-index.md` MVP 范围）
- 内容生产是与开发并行的独立轨道（systems-designer 批量产出 JSON 配置）

## Lessons Learned

1. **CDN 依赖在国内极不可靠** — 原型层禁用外部 CDN，关键依赖必须本地化或纯原生
2. **引号字符的隐性陷阱** — JS 字符串里嵌套普通双引号会静默 parse 失败，中文内容应统一用『』或单引号转义
3. **视觉与机制的判断耦合** — 用户对"是否有趣"的判断，约 30% 来自视觉品质。素界面会让好机制被误判，这点要在生产里贯彻
4. **原型范围管理** — 加深机制是合理的（验证机制深度本身是核心问题），但加内容是错的（内容广度是生产任务）。本次在加内容前及时刹车，避免了范围蔓延
5. **状态化角色头像是高 ROI 反馈** — 一张 64px 头像随精力/心情变 7 种表情，成本几乎为零，但显著强化了"代入感"。生产里要保留这个设计语言
6. **机制深度需要被即时反馈** — Buff 改了数值要带 `*` 标记，风险骰子要全屏动画，否则玩家感受不到机制在工作

## Open Questions for Production

- **Buff/Debuff 系统应该独立成一个 GDD** — 当前 9 个 MVP GDD 没有覆盖，需要在 sprint plan 之前补一份
- **风险事件的概率展示**是否会让玩家"算计"过度（破坏沉浸）？需要在生产期 playtest 验证
- **小卖部是否应该按职业差异化**（程序员喝咖啡、销售喝白酒）？涉及职业身份感
