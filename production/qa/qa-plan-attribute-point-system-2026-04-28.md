## 自动化测试要求

### Story 001: 属性点机制 — Logic

**测试文件路径**: `tests/unit/character/attribute_point_mechanics_test.gd`

**测试内容**:

#### AC-1: 属性点获取机制正常
- **公式**: 每升 1 级获得 5 点自由属性点
- **验证**:
  - 玩家升级到第 2 级时，获得 5 点属性点
  - 玩家升级到第 3 级时，总共获得 10 点属性点
  - 玩家升级到第 99 级时，总共获得 495 点属性点
  - 不同等级的升级都正确获得 5 点属性点

**边缘情况**:
- 等级 1 时没有属性点（升级前）
- 等级 2 时有 5 点属性点（首次升级）
- 等级 99 时有 495 点属性点（最高等级）
- 批量升级（从等级 1 升到等级 10）正确获得 45 点属性点

#### AC-2: 属性点分配规则正确
- **公式**: 分配 1 点到属性时，该属性值增加 1，可用点数减少 1
- **验证**:
  - 拥有 5 点可用属性点时，分配 1 点到力道，力道增加 1，可用点数变为 4
  - 分配 5 点到身法，身法增加 5，可用点数变为 0
  - 无法分配超过可用点数的属性点
  - 无法分配负数属性点
  - 分配 0 点时，属性值和可用点数不变

**边缘情况**:
- 可用点数为 0 时，无法分配任何属性点
- 分配到属性上限（99 点）时，无法继续分配
- 分配负数时，系统拒绝并返回错误
- 分配非整数时，系统拒绝并返回错误

#### AC-3: 属性体系实现
- **六维属性**: 力道、身法、根骨、悟性、定力、福缘
- **验证**:
  - 查询力道属性值，返回正确的数值
  - 查询身法属性值，返回正确的数值
  - 查询根骨属性值，返回正确的数值
  - 查询悟性属性值，返回正确的数值
  - 查询定力属性值，返回正确的数值
  - 查询福缘属性值，返回正确的数值
  - 所有属性初始值为 0

**边缘情况**:
- 属性值为 0 时，查询返回 0
- 属性值达到上限（99 点）时，查询返回 99
- 查询不存在的属性时，系统返回错误或 0
- 属性值为负数时（不应该发生），系统处理正确

#### AC-4: 属性点数据结构正确
- **数据结构**:
  ```yaml
  AttributeAllocation:
    totalPoints: Integer  # 总获得属性点数
    allocatedPoints: Integer  # 已分配属性点数
    attributes:
      strength: Integer  # 力道
      agility: Integer   # 身法
      constitution: Integer  # 根骨
      intelligence: Integer  # 悟性
      willpower: Integer  # 定力
      luck: Integer  # 福缘
    resetCount: Integer  # 免费重置次数
  ```
- **验证**:
  - 保存属性点数据后，加载时数据完全恢复
  - 所有六维属性值正确保存和加载
  - 总属性点数正确保存和加载
  - 已分配属性点数正确保存和加载
  - 免费重置次数正确保存和加载

**边缘情况**:
- 数据损坏时，系统能够检测并报告错误
- 版本迁移时，旧版本数据能够正确转换
- 存档格式变更时，能够向后兼容
- 多次保存和加载循环后，数据保持一致

**预计测试数量**: ~25 个单元测试
