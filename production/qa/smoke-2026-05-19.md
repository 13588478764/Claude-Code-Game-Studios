## 3. Architectural Coherence Verified

The integration tests in `tests/integration/` exercise cross-system flows that
mirror the production wiring:

### 3.1 Choice Resolution Pipeline (S2-3)

Verified ordering invariant via spy: `applyToEffect → applyEffects → addStatus`
- Status modifier applied to effects BEFORE ResourceManager applies them
- Buff added AFTER effects applied (so this choice's effects are NOT modified
  by the buff this choice itself adds)
- Subsequent choice DOES see the buff active

### 3.2 RunManager State Machine (S2-4)

Full 6-phase lifecycle verified:
- Death path: JOB_SELECT → INITIALIZING → PLAYING → DYING → SETTLING → ENDED → JOB_SELECT
- Win path: JOB_SELECT → INITIALIZING → PLAYING → SETTLING → ENDED → JOB_SELECT
- ENDED phase triggers statusSystem.clearAll via onPhaseChanged subscription
- DYING/SETTLING phases preserve statuses (revive flow integrity)
- Single-revive policy enforced (revivedThisRun flag blocks 2nd ad)
- Same-frame death + week-completed → DYING wins (resource depletion priority)

### 3.3 Day-end Ordering Contract (S2-5 useGameSession)

Listener registration order ensures the day-cycle.md contract:
1. **First** listener applies salary (resourceManager.applyEffects)
2. **Second** listener ticks statuses (statusSystem.subscribeToDayEnded)

TypedEventEmitter Set iteration preserves insertion order, so subscribers fire
in registration sequence.

### 3.4 Event Card Two-phase Resolve (S2-2)

`selectChoice → isResolving=true → resolveHandler → commitResolve → advance`
- Re-entrant selectChoice during RESOLVING is ignored (debounce property)
- followUp loading respects MAX_FOLLOWUP_DEPTH=3
- Empty text fallback "今天平平无奇地过去了…" applied at card display time
